# 学生登录页面设计

## 目标

系统面向学生用户提供统一登录入口。学生使用姓名、学号和密码完成身份验证，并支持密码重置与密码修改。设计目标是保证登录流程简洁、字段可审计、密码不明文存储，并为后续接入短信、邮箱或管理员重置预留扩展空间。

## 页面结构

登录页面包含三个主要区域：

1. 登录表单：输入姓名、学号、密码。
2. 辅助操作：提供“忘记密码”和“修改密码”入口。
3. 状态提示：展示登录失败、密码错误、账号不存在、重置成功等反馈信息。

## 登录流程

1. 学生输入姓名、学号和密码。
2. 前端校验必填项：姓名不能为空，学号不能为空，密码不能为空。
3. 后端根据学号查询学生账号。
4. 后端校验姓名是否与账号记录一致。
5. 后端使用密码哈希算法校验密码。
6. 校验成功后创建登录会话或签发访问令牌。
7. 校验失败时返回明确但不过度暴露信息的错误提示，例如“姓名、学号或密码不正确”。

## 密码重置流程

密码重置用于学生忘记原密码的场景。

1. 学生点击“忘记密码”。
2. 输入姓名、学号，并完成身份校验。
3. 系统生成一次性重置凭证，设置有效期。
4. 学生输入新密码并确认新密码。
5. 后端校验重置凭证是否有效、未过期、未使用。
6. 后端更新密码哈希，并将重置凭证标记为已使用。
7. 重置成功后要求学生重新登录。

初期实现可采用管理员审核重置或预置校验信息；后续可扩展为短信验证码、邮箱验证码或校园统一身份认证。

## 密码修改流程

密码修改用于学生已登录且知道原密码的场景。

1. 学生进入“修改密码”页面。
2. 输入原密码、新密码和确认新密码。
3. 后端校验当前登录状态。
4. 后端验证原密码是否正确。
5. 后端校验新密码复杂度与两次输入一致性。
6. 校验通过后更新密码哈希。
7. 修改成功后可选择使当前会话继续有效，或强制重新登录。

## 密码规则

建议采用以下基础规则：

1. 密码长度不少于 8 位。
2. 至少包含字母和数字。
3. 不允许与学号完全相同。
4. 不允许与最近一次密码相同。
5. 数据库仅保存密码哈希，不保存明文密码。

## 数据库字段设计

### 学生账号表：`student_accounts`

| 字段名 | 类型 | 约束 | 说明 |
|---|---:|---|---|
| `id` | `BIGINT` | 主键，自增 | 学生账号内部 ID |
| `student_no` | `VARCHAR(32)` | 唯一，非空 | 学号 |
| `name` | `VARCHAR(64)` | 非空 | 学生姓名 |
| `password_hash` | `VARCHAR(255)` | 非空 | 密码哈希值 |
| `password_updated_at` | `DATETIME` | 非空 | 最近一次密码更新时间 |
| `status` | `VARCHAR(20)` | 非空，默认 `active` | 账号状态，如 `active`、`disabled` |
| `last_login_at` | `DATETIME` | 可空 | 最近一次登录时间 |
| `created_at` | `DATETIME` | 非空 | 创建时间 |
| `updated_at` | `DATETIME` | 非空 | 更新时间 |

### 密码重置表：`password_reset_tokens`

| 字段名 | 类型 | 约束 | 说明 |
|---|---:|---|---|
| `id` | `BIGINT` | 主键，自增 | 重置记录 ID |
| `student_account_id` | `BIGINT` | 外键，非空 | 关联 `student_accounts.id` |
| `token_hash` | `VARCHAR(255)` | 非空 | 一次性重置凭证哈希 |
| `expires_at` | `DATETIME` | 非空 | 凭证过期时间 |
| `used_at` | `DATETIME` | 可空 | 凭证使用时间 |
| `created_at` | `DATETIME` | 非空 | 创建时间 |

### 登录日志表：`login_logs`

| 字段名 | 类型 | 约束 | 说明 |
|---|---:|---|---|
| `id` | `BIGINT` | 主键，自增 | 日志 ID |
| `student_account_id` | `BIGINT` | 可空 | 登录成功时关联学生账号 |
| `student_no` | `VARCHAR(32)` | 非空 | 本次登录输入的学号 |
| `success` | `BOOLEAN` | 非空 | 是否登录成功 |
| `failure_reason` | `VARCHAR(100)` | 可空 | 失败原因 |
| `ip_address` | `VARCHAR(64)` | 可空 | 登录 IP |
| `user_agent` | `VARCHAR(255)` | 可空 | 浏览器或客户端信息 |
| `created_at` | `DATETIME` | 非空 | 登录发生时间 |

## 接口概要

| 接口 | 方法 | 功能 |
|---|---|---|
| `/api/auth/login` | `POST` | 学生登录 |
| `/api/auth/password/reset/request` | `POST` | 发起密码重置 |
| `/api/auth/password/reset/confirm` | `POST` | 确认密码重置 |
| `/api/auth/password/change` | `POST` | 已登录学生修改密码 |
| `/api/auth/logout` | `POST` | 退出登录 |

## 安全要求

1. 密码必须使用安全哈希算法存储，例如 Argon2、bcrypt 或 PBKDF2。
2. 登录失败次数应进行限流，避免暴力破解。
3. 密码重置凭证只保存哈希值，且设置较短有效期。
4. 所有登录、重置和修改密码操作应写入审计日志。
5. 前后端通信必须使用 HTTPS。
