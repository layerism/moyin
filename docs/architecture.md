# 架构草案

## 目标

系统面向教师与学生两类用户。教师上传 Word 模板，系统提取模板中的空缺项和选项；学生登录后填写对应表单；系统根据填写结果生成可下载的 Word 文档。

## 核心模块

| 模块 | 职责 | 当前状态 |
| --- | --- | --- |
| 认证与权限 | 学生、教师登录与角色区分 | 占位 |
| 模板管理 | 教师上传 Word 模板，维护模板版本 | 占位 |
| 字段抽取 | 从 Word 模板中识别空缺项、选项和约束 | 占位 |
| 表单填写 | 学生按模板填写字段 | 占位 |
| 文档生成 | 将学生填写内容回填为 Word 文档 | 占位 |
| AI 辅助 | 字段解释、填写建议、内容润色、模板识别辅助 | 占位 |

## 推荐数据流

1. 教师上传 `.docx` 模板。
2. 后端解析模板结构，提取字段定义。
3. 前端按字段定义渲染学生填写表单。
4. 学生提交填写内容。
5. 后端生成对应 Word 文档。
6. 学生下载生成结果。

## 部署形态

生产环境建议采用：

- Nginx 提供前端静态资源与 `/api` 反向代理。
- FastAPI 提供业务 API。
- 数据库、对象存储、AI 服务在后续阶段接入。
