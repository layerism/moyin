# DOCX 预览整理计划

日期：2026-10-13。状态：用户已确认，第一轮预览链路优化已实施；Windows Word 几何验收未完成。

基线检查点：`ae35163`，包含当前已提交预览实现；不包含用户已有的审核脚本配置修改。

## 目标与约束

- 以现有 docx-preview 0.4.1 为解析与 HTML 渲染基础，按 OOXML 与 Windows Word 实现说明补齐缺失能力，不另造完整排版引擎。
- 同时改善效率、跨文档通用性和排版几何；不按文件名、标题文字、固定页号或截图坐标添加特殊分支。
- 保持现有模块组织和共享预览入口。模板、参考材料和人工审核使用同一条处理链。
- 字体仍来自项目 docx-fonts，按 XML 选择并按需加载；保留已批准的项目内缺字补齐及明确提示，不隐式依赖 Linux 字体。
- 规则缺失时先解析继承与规范定义的缺省值。不得自行增加统一字号、1.2 倍行高、固定 1em 制表位、页面缩放系数等业务默认值。
- 未支持的规则记录为能力差异，不通过裁切、隐藏或缩小正文伪装为正确排版。文档明确要求的裁切须在坐标和文字行框正确的前提下实现，不能一律替换为 overflow:hidden。
- Windows Word 版本、兼容模式、字体文件版本会参与验收基线；未对照实际 Word 输出前不宣称像素一致。

## 当前证据与问题

1. DocxPreview 调用 parseAsync 后，docxLayout 与 docxFontConfig 分别使用 unzipSync 再次解压、解析相关 XML。
2. 库已处理样式继承、基础段落属性、页面尺寸和边距、表格列与合并、边框、内边距等。项目又在解析模型和渲染 DOM 两个阶段写入部分相同属性。
3. 新增固定行高容器使用 maxHeight 和 overflow:hidden；用户截图已出现标题字形被裁切，应优先撤除该近似实现。
4. 网格处理采用计算行高向上取整，normal 行高用字号乘 1.2；没有完整解释字体度量、段落标记、混合字号与兼容设置。
5. w:tab 被统一替换为 1em 占位；库已有实验性制表位计算，但需要审计其范围与执行时机。
6. 表格和段落部分通过扁平序列数量匹配 XML；文本框通过 style 字符串匹配。数量相等不能证明对象对应正确。
7. 分页器多次深克隆表格并同步读写布局，没有完整使用 keepNext、keepLines、widowControl、cantSplit；不可拆分媒体还有自动 zoom 兜底。
8. 排版补充主要覆盖 document.xml，字体处理已遍历多个 part，两者对页眉、页脚、脚注和文本框的覆盖范围不一致。

## 规则依据及所有权

为每个需要补充的属性记录：XML 路径、单位、继承来源、规范缺省、兼容设置、库中处理位置、项目补充位置、已知限制。一个属性只能有一个最终计算职责；分页只能消费布局结果和分页约束。

依据按用途区分：

- OOXML：属性、单位、继承和缺省语义。
- Microsoft MS-OI29500：Office 对标准的实现差异及适用版本，不把标准描述直接视为所有 Word 版本的实际行为。
- 字体文件与 OpenType 文档：字形、字重、上升部、下降部和行间距等度量；不能认定一个 OS/2 字段公式适用于所有字体和 Word 模式。
- 固定版本 docx-preview 源码：确认已经支持、解析但未消费、部分支持和确实缺失四种状态。
- 同版本 Windows Word 导出的 PDF：用于几何对照；LibreOffice 输出不能替代 Word 真值。

## 实施顺序

### 前置：建立文档全局布局上下文

2026-10-13 用户追加表格错位、行距差异和异常跳页观察。三项纳入同一布局链路审计，不视为三个独立 CSS 问题。

| XML 来源 | 需要解析或确认库已消费的信息 | 影响 |
| --- | --- | --- |
| settings.xml | compat/compatibilityMode、相关排版兼容项、defaultTabStop、奇偶页眉页脚与镜像边距设置 | 规则版本、制表位与页布局 |
| styles.xml | docDefaults、默认样式、basedOn、段落/字符/表格条件样式及对应优先级 | 行距、字体、表格内文字及边框 |
| theme/theme*.xml、fontTable.xml 及关系文件 | 实际引用主题、语言对应字体、字体定义与嵌入关系；项目字体映射仍按既定策略执行 | 字形选择与文字度量 |
| document.xml 中 sectPr | 节所属内容范围、纸张/方向、边距、装订线、分栏、网格、节起始类型、页码起始与页眉页脚引用 | 可用区域、换页和几何 |
| numbering.xml | 编号层级、缩进、编号字体、制表位与样式关联 | 段落起点、换行和分页 |
| header/footer/footnotes/endnotes 等 part | 所属节、关系映射、继承/引用及实际占用 | 正文空间、节首页与奇偶页 |

全局信息须带作用范围，不能把某一节的网格、宽度或页边距推广到整份文档。未显式设置的属性按各属性的规范继承链处理，不能用一条简单全局优先级替代全部规则。全局上下文每个文件版本只解析一次。

### 三项追加问题的定位要求

1. **表格布局**：计算起点是所属节/分栏或父单元格的可用宽度。补查 tblStyle/tblLook/cnfStyle、gridBefore/gridAfter、表格结束后的段落、重复标题、合并组与跨页约束。区分列网格、首选宽度与最终分配宽度，不能只看单元格局部 tcW。
2. **文字行距**：追踪文档默认→适用样式→直接格式及兼容项的有效结果；区分基线间距、可见字形高度、段间距与表格行高。记录字体和字号、段落标记、行距规则及网格是否参与，不能从截图字块高度直接推断行距。
3. **异常跳页**：统一记录每个分页边界的来源与关联节点，类别包括显式 br、pageBreakBefore、nextPage/evenPage/oddPage 分节、保存时 lastRenderedPageBreak、段落保持/孤行规则、表格约束及内容溢出。物理空白页、正文留白和页码字段跳号分开诊断。

当前已确认的源码风险：DocxPreview 同时启用保存时分页标记、为部分分节插入普通分页符，之后再执行 paginateDocx；nextPage/evenPage/oddPage 被同一补丁处理，尚未完整表达奇偶页语义。需要按语义合并同一边界，不能按位置盲删重复分页，也不能将所有空白页一律删除。库生成的空段落、表格后的段落、字体就绪前后高度、页眉页脚空间重复扣除、页面舍入误差也纳入排查。

本地 assets 的只读 XML 清单：论文模板有 5 个表格、6 个 sectPr、13 个 lastRenderedPageBreak，没有显式 w:br type=page；实习周记有 18 个表格、3 个节且没有保存分页标记。二者适合覆盖不同分页输入。此统计来自仓库样例，不能视为当前浏览器上传文件相同，也不能据此断言异常跳页根因。

增加开发用分页诊断信息：节与源节点、分页原因、内容高度、可用高度、是否命中旧分页标记及奇偶页规则。信息按预览会话汇总且默认关闭，不输出正文，不在产品流程中堆放技术字段。

### 1. 撤除有损补丁，建立明确边界

- 移除现有固定行裁切容器及依赖其标记的分页特殊处理；保留 XML 原始行高信息。
- 移除分页中的强制缩放兜底，区分可分页内容、不可拆分对象和本来就超页的对象；暂不能精确布局时保持内容可见并提示差异。
- 对齐原始纸张与 A4/A3 重排模式的边界：只有原始版式与 Word 原始输出比较；用户选择重排不应改变文件原始配置。
- 保留有依据的 AlternateContent 分支处理、项目字体与页码能力；逐项审计，不整体回滚已有正确能力。

### 2. 统一 XML 上下文，复用库模型

- 核对库的 part 原始 XML 保留能力（本地源码包含 keepOrigin），优先复用已解析 part；若采用内部接口，封装在窄适配边界并固定版本。
- 无法直接复用时，最多建立一次共享 XML 读取上下文，取消两个模块各自解压同一 DOCX。
- 统一处理 AlternateContent、命名空间与 part 关系，以 part 路径和结构路径/对象标识对应节点；不再只依赖计数或 style 字符串。
- 提供只读源信息与渲染会话状态分离；库渲染会修改解析对象，禁止把渲染过的可变对象直接作为跨会话缓存反复使用。
- 充分复用库的样式树和继承过程。只补漏掉的属性与已定位的缺陷，不建立另一套与库竞争的全量样式引擎。

### 3. 先校正文字与段落几何

- 核对默认样式、basedOn、段落/字符/表格条件样式及直接格式的优先级，保留“省略”和“显式零值”的区别。
- 分别处理 auto、exact、atLeast；核对段落标记字号、混合字体/字号、上下标及空段落如何影响行框。
- 段前段后、自动间距、上下文间距与相邻段落间距组合按规则计算，避免以 CSS margin 折叠作为 Word 规则的替代品。
- 网格按节属性、snapToGrid 与兼容设置决定是否生效；不对所有段落执行通用取整公式。
- 优先复用库的制表位算法，审计左/右/居中/小数点对齐、前导符和默认制表间隔。字体加载及 DOM 挂载完成后才测量；单纯打开 experimental 开关不视为完成。

### 4. 在文字几何稳定后校正表格与浮动对象

- 表格：分别核对 auto/fixed、tblW/tcW/tblGrid、百分比与绝对宽度、缩进、单元格间距、边框模型和内边距；不能一律把列宽求和作为最终宽度。
- 行高：区分 auto/atLeast/exact，结合单元格文字高度、垂直对齐和合并组求解；不按独立行裁切跨行合并单元格。
- 文本框/图片：根据实际选择的 DrawingML 或 VML 表示读取锚点、定位参照、偏移、绕排、尺寸、内边距、形状类型和边框；禁止把所有 text-relative 对象都当成单元格左上角定位。
- 保留字体和字形原始比例，区分 Word 明确指定的缩放与为塞入页面而添加的项目缩放。

### 5. 约束驱动的分页和页码

- 区分显式分页、分节与 lastRenderedPageBreak（保存时的排版痕迹）；不得把后者无条件当作当前字体和版式下的可靠几何结论。
- 使用库已解析的段落属性，补齐 keepNext、keepLines、widowControl、表格 cantSplit/重复标题行等约束。
- 按合法行/段落边界切分；处理长表格时保持列宽、合并关系和边框，不以任意 UTF-16 偏移作为最终排版语义。
- 页眉页脚、脚注及浮动对象参与可用区域与分页决策；新增页不能盲目复制所有节级内容。
- 保持行框与样式计算结果不被分页器重新定义；分页完成后更新 PAGE/NUMPAGES/SECTIONPAGES 和节起始编号。

### 6. 与上述改动同步控制成本

- 记录文件读取、解析、字体、渲染、布局测量、分页阶段的耗时和计数；先建立基线，再决定是否需要 Worker 或虚拟化，不先加复杂架构。
- 字体按需并行加载，缓存字体数据、字形覆盖和样式解析结果；仅等待当前文档依赖的字体。
- 解析属性、字体选择与规则计算按稳定对象/属性组合缓存，减少逐字符 JSON 解析和重复 getComputedStyle。
- 批量写入样式后统一测量；分页复用块边界和测量结果，避免逐候选整表克隆。不假定浮动内容与任意表格布局天然满足二分查找的单调性。
- 长布局阶段分批执行并支持取消，关闭/切换预览后不继续无效计算。
- 缩放只改变展示比例；纸张切换复用文件与只读解析信息，重算相关几何；跨打开缓存必须有文档版本标识、失效策略及大小限制。
- 本轮暂不预设“快几倍”或毫秒目标，性能结论必须区分冷字体缓存和热缓存。

## 验收计划与当前限制

- 结构覆盖：普通正文、中英混排和混合字号、空段落、三种行距、段间距、网格、制表位、固定/自动表格、嵌套表格、横纵合并、超长单元格、浮动图文、横竖混排节、页眉页脚和脚注。
- 从 assets 现有多份 DOCX 建立只读结构清单，不能只验证当前论文封面；必要的缺失结构样例另行列出。
- 几何验收：同一文件、同版本字体、同一 Windows Word 版本及兼容模式、相同纸张；对照页数、换行位置、基线、表格列边界和锚点坐标。屏幕缩放先归一化，不能用不同缩放的截图直接比较。
- 必须区分类型/静态检查、浏览器布局观察、Word 对照和性能测量。任何一类结果不能替代其他类。
- 当前 AGENTS.md 禁止运行测试与浏览器插件：实施阶段按现有约束只做源码、XML 和类型审计；视觉及几何结果由用户在 Windows Word 与页面对照反馈。未取得允许或实际对照结果，不宣称几何验收完成。
- 保留逐项支持状态：已由库支持、项目补齐、尚未支持；剩余差异如实记录。
- 三项追加验收：相同表格在不同节宽和嵌套容器中不会沿用错误宽度；相同最终段落属性不会因补丁路径不同而产生不同间距；每一次换页可追溯到规则或溢出，合法奇偶页空白保留，无解释的重复换页不得作为完成状态。
