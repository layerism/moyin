# 答题卡节点设计方案

> 状态：2026-10-15 同步答案存储和实时判分实现；依据项目规范进行静态检查，未执行测试、前端构建或浏览器验收。
> 适用范围：Moyin OA DAG 流程中的教师设计端、学生运行端、自动判分与教师结果导出。

## 1. 实际使用场景

教师在流程中增加一个“答题卡”节点，用于课前测验、章节练习、实验准入测试或材料学习检查。例如：

1. 教师添加 3 道题：单选题、多选题和含两个空的填空题。
2. 教师用 Markdown 编写题干，使用数学公式和代码块。
3. 教师配置标准答案、作答次数和反馈策略。
4. 发布流程时，系统冻结题目结构和评分规则；标准答案保存在当前节点配置中。
5. 学生进入节点，看到经过安全渲染的题目，暂存答案后提交。
6. 后端保存学生提交；每次查看或导出时，读取当前标准答案实时计算成绩。
7. 完成合法提交后节点变为 `approved` 并按流程开放下游；成绩变化不重置进度。

核心调用链如下：

```text
教师编辑题目
  -> 保存公开题目配置 + 私有答案配置
  -> 保存到 flows.draft_config 节点，发布时冻结公开配置

学生读取节点
  -> 只取得公开题目配置
  -> 暂存 answers
  -> 提交 answers + idempotencyKey
  -> 写入 node_submissions 并推进节点状态

查看成绩 / 教师导出
  -> 后端读取当前标准答案 + 当前正式提交
  -> 确定性判分，按反馈策略返回结果
  -> 不写成绩表，不修改提交或进度
```

## 2. 设计目标与边界

### 2.1 目标

- 支持单项选择题、多项选择题和填空题。
- 题干和选项只提供普通文本、一级/二级标题、数学公式及代码高亮。
- 自动判分必须由后端执行，不能信任客户端提交的分数或判题结论。
- 学生流程配置不得包含标准答案；成绩接口仅在反馈策略明确允许时返回标准答案。
- 复用现有发布快照、学生实例、节点状态、暂存、幂等提交和 DAG 推进机制。
- 教师预览与正式学生端复用同一套可见渲染组件和交互规则。
- 题目、标准答案和学生作答都相同时，判分结果一致；不保存或恢复历史成绩。

### 2.2 V1 不处理的能力

- 主观题、证明题、编程题和人工阅卷。
- AI 语义判分、正则表达式判分和数学表达式等价性证明。
- 随机抽题、随机选项顺序和题库组卷。
- 按班级排名、考试监考、倒计时强制交卷和防作弊。
- 学生在题目中上传附件。

这些能力不应混入 V1 的确定性答题卡模型；后续可通过新的题型或考试模式扩展。

## 3. 节点类型与现有系统关系

新增节点类型：

```ts
type AcademicFlowNodeKind =
  | "announcement"
  | "confirmation"
  | "file"
  | "form"
  | "answer_sheet";
```

答题卡不应作为现有 `form` 节点的特殊配置实现。两者虽然都包含输入控件，但业务语义不同：

| 维度 | 表单节点 | 答题卡节点 |
| --- | --- | --- |
| 目的 | 采集信息 | 测量作答结果 |
| 选项 | 无正确或错误之分 | 具有标准答案和分值 |
| 提交结果 | 保存字段值 | 保存答案并生成评分结果 |
| 状态推进 | 通常提交即通过 | 由及格策略决定是否通过 |
| 数据安全 | 字段配置可公开 | 标准答案必须私有 |

答题卡采用后端同步判分，不进入现有异步 AI 审核脚本队列。其判分是纯业务规则，不应伪装成审核脚本，否则会增加不必要的任务状态、重试和运行时依赖。

## 4. 教师端配置设计

### 4.1 节点入口

节点面板新增：

```text
┌──────────────────────┐
│ 答题卡               │
│ 选择题、填空题与自动判分 │
└──────────────────────┘
```

节点仍使用现有标题、说明、开放时间和截止时间。双击节点后，在设置窗口中显示答题卡编辑区。

### 4.2 编辑器布局

```text
┌──────────────────────────────────────────────────────────────┐
│ 答题卡设置                                      总分：10 分 │
│ 及格分 [6]  作答次数 [截止前不限▼]  反馈 [逐题对错▼]        │
│                         [+单选] [+多选] [+填空]              │
├──────────────────────────────────────────────────────────────┤
│ ⠿ 第 1 题  设函数 f(x)=x²，求……  单选·1分·2项  [⌃] [⋯]  │
├──────────────────────────────────────────────────────────────┤
│ 题型 [单项选择▼]     分值 [1]                    [✓ 必答]   │
│ 设函数 $$f(x)=x^2$$，代码为 `return x`                     │
│ ○ [选项 A：聚焦源码 / 失焦渲染]                         [⋯] │
│ ● [选项 B：聚焦源码 / 失焦渲染]                         [⋯] │
│ [+ 添加选项]                                               │
├──────────────────────────────────────────────────────────────┤
│ ⠿ 第 2 题  若……，则____。       填空·3分·1空  [⌄] [⋯]  │
└──────────────────────────────────────────────────────────────┘
```

具体交互规则：

- 题目和选项使用稳定 ID；排序、改文案时不改变 ID。
- 题目默认折叠，同一时间只展开一道题；新增题目后自动展开新题。
- 题目可通过左侧拖拽柄排序，也可在三点菜单中上移、下移或删除；键盘可使用 `Alt + ↑/↓` 排序。
- 折叠摘要以题干首行作为主要识别信息，过长时省略；空题干显示“未填写题干”。
- 折叠摘要显示题号、题型、分值、选项或填空数量与校验状态；题型、分值和必答等编辑控件集中在展开区。
- 填空题的总分由各填空分值汇总，不显示题目级分值输入框。
- 单选题必须且只能设置一个正确选项。
- 多选题至少设置一个正确选项，V1 采用“集合完全一致”计分。
- 填空题通过“添加填空”操作产生 `[[blank:<blankId>]]` 标记；配置中每个标记必须恰好存在一次。
- 选项和填空的低频操作收纳到三点菜单，避免横向堆叠操作按钮。
- Markdown 编辑框聚焦时始终显示完整源码，不提供公式、格式或图片按钮。
- 编辑框失去焦点后，在同一位置渲染结果；点击渲染结果重新进入源码编辑。
- 题目和选项不设置独立预览列，降低卡片高度与横向占用。
- 编辑器始终显示总分、及格分和发布校验错误。

### 4.3 发布前校验

发布时至少校验：

1. 节点至少有一道题。
2. 题目 ID、选项 ID、填空 ID 在各自作用域内唯一且非空。
3. 每道题题干非空，分值为正数。
4. 单选题至少两个选项，且恰有一个正确答案。
5. 多选题至少两个选项，且至少一个正确答案。
6. 填空题至少有一个空；题干标记与填空配置一一对应。
7. 每个空至少配置一个非空标准答案和一个正分值。
8. 及格分位于 \(0\) 到总分之间。
9. 若反馈策略要求“截止后展示答案”，节点必须配置截止时间。

## 5. Markdown、数学公式与代码

### 5.1 数学公式语法与失焦渲染

按照教师输入习惯，答题卡使用以下语法：

```markdown
圆的面积为 $S=\pi r^2$，其中 $r$ 为半径。

$$
\int_0^1 x^2\,dx=\frac{1}{3}
$$
```

- `$...$`：行内数学公式。
- `$$...$$`：行间数学公式。公式独占一行时可把内容与定界符写在同一行；多行公式的开始、结束标记各自独占一行。
- 代码块和行内代码中的美元符号不参与公式解析。

编辑器采用“聚焦编辑源码、失焦原位渲染”的方式：

1. 教师点击题干或选项后，编辑框只显示原始 Markdown。
2. 编辑过程中不把公式替换成可视节点，也不显示任何格式工具栏。
3. 编辑框失去焦点后，使用与学生端相同的只读渲染组件展示公式和代码。
4. 点击渲染结果或使用键盘聚焦后，可重新编辑完整源码。
5. 数据库存储的始终是 Markdown 源码，不保存渲染生成的 HTML。

例如，教师编辑 `圆的面积为 $S=\pi r^2$` 时看到完整源码；点击编辑框外部后，该区域显示排版后的 \(S=\pi r^2\)。

### 5.2 支持范围

只保留以下 Markdown 能力：

- 普通文本和段落；
- 一级标题 `#` 与二级标题 `##`；
- 粗体 `**文字**` 与斜体 `*文字*`；
- 有序列表、无序列表与引用；
- GFM 表格，允许在单元格中使用受支持的行内格式；
- 行内代码和围栏代码块；围栏注明语言时进行语法高亮；
- `$...$` 行内数学和 `$$...$$` 行间数学。

三级及以上标题降为普通段落；删除线、链接和任务列表只保留可见文字，不产生对应交互或特殊格式；图片仅保留替代文本。原始 HTML、脚注和水平分隔线不渲染。本轮不提供图片按钮、粘贴上传或拖拽上传。

### 5.3 安全渲染

教师预览、真实学生预览和正式学生端统一复用 `AnswerSheetMarkdown`：

```text
Markdown AST
  -> 基础 Markdown 白名单
  -> `remark-math` 标准数学语法
  -> 数学节点交给 KaTeX
  -> 代码节点交给 rehype-highlight
  -> 拒绝 Markdown 原始 HTML
  -> React 渲染
```

安全要求：

- 不启用 Markdown 原始 HTML。
- KaTeX 使用不信任模式，不允许危险协议和任意 HTML 扩展。
- 教师题干预览、学生题干和选项使用相同的渲染规则。

### 5.4 组件库选型

答题卡不使用同一个组件同时承担编辑和只读展示，而是按照职责组合：

| 场景 | 采用组件 | 职责 |
| --- | --- | --- |
| 教师 Markdown 编辑 | 原生受控 `textarea` | 聚焦显示源码，失焦切换为只读渲染，不提供工具栏 |
| 数学公式排版 | `katex` | 将 LaTeX 数学节点渲染为可视公式 |
| 教师预览、学生端及结果展示 | `react-markdown` | 按基础能力白名单渲染题干和选项 |
| GFM 表格解析 | `remark-gfm` | 只启用表格语法；删除线、任务列表和自动链接仍由白名单降级处理 |
| 数学节点转为 KaTeX | `rehype-katex` | 将 Markdown AST 中的数学节点交给 KaTeX |
| 代码高亮 | `rehype-highlight` | 对注明语言的围栏代码块做静态语法高亮 |
| 数学公式语法 | `remark-math` | 按标准 `$...$` 行内公式和 `$$...$$` 行间公式解析；整行单行公式先规范化为 flow math |

实现中封装共享的 `answerSheetMarkdown` 语法层：

```text
教师聚焦：textarea 原始 Markdown
教师失焦：AnswerSheetMarkdown

学生展示：react-markdown
  -> remark-math 标准数学语法
  -> 基础能力白名单
  -> rehype-katex / rehype-highlight
  -> React 只读内容
```

教师失焦预览和学生展示必须使用同一组件，避免两侧对标题、数学或代码的解释不一致。

依赖版本在实施时依据项目固定的 Node.js 24.18.0、React 18 和现有 Vite 构建环境完成兼容性核对后锁定。本设计阶段不预先写死未经构建验证的版本号。

## 6. 公开题目与私有答案分离

### 6.1 不能把答案放进节点 JSON

当前学生运行接口会返回发布版本中的节点配置。若在 `config_snapshot` 中保存 `correctOptionId` 或标准填空答案，即使界面不展示，学生仍可通过网络响应或前端状态读取。因此必须从数据层分离，而不是仅依赖前端隐藏字段。

### 6.2 公开节点快照

```json
{
  "id": "answer-sheet-01",
  "kind": "answer_sheet",
  "title": "函数基础测试",
  "requirement": "总分 10 分，达到 6 分后进入下一节点。",
  "answerSheet": {
    "schemaVersion": "1.0",
    "questions": [
      {
        "id": "q1",
        "type": "single_choice",
        "content": "若 $$f(x)=x^2$$，则 $$f(2)$$ 等于：",
        "points": 2,
        "required": true,
        "options": [
          { "id": "o1", "content": "2" },
          { "id": "o2", "content": "4" }
        ]
      },
      {
        "id": "q2",
        "type": "multiple_choice",
        "content": "下列属于偶函数的是：",
        "points": 3,
        "required": true,
        "options": [
          { "id": "o1", "content": "$$x^2$$" },
          { "id": "o2", "content": "$$x^3$$" },
          { "id": "o3", "content": "$$|x|$$" }
        ]
      },
      {
        "id": "q3",
        "type": "fill_blank",
        "content": "$$2+2=[[blank:b1]]$$；英文 four 写作 [[blank:b2]]。",
        "required": true,
        "blanks": [
          { "id": "b1", "points": 2 },
          { "id": "b2", "points": 3 }
        ]
      }
    ],
    "gradingPolicy": {
      "maxAttempts": null,
      "feedback": "question_result"
    }
  }
}
```

学生可以看到题目和分值，流程配置不包含标准答案。

### 6.3 节点中的私有答案配置

以下对象保存在 `flows.draft_config.nodes[].answerSheetKey`；题目与规则保存在同一节点的 `answerSheet`。

```json
{
  "schemaVersion": "1.0",
  "graderVersion": "answer-sheet-v1",
  "answers": {
    "q1": {
      "type": "single_choice",
      "correctOptionId": "o2"
    },
    "q2": {
      "type": "multiple_choice",
      "correctOptionIds": ["o1", "o3"],
      "mode": "exact_set"
    },
    "q3": {
      "type": "fill_blank",
      "blanks": {
        "b1": {
          "acceptedAnswers": ["4", "四"],
          "caseSensitive": false
        },
        "b2": {
          "acceptedAnswers": ["four"],
          "caseSensitive": false
        }
      }
    }
  }
}
```

当前复用的存储如下：

| 存储位置 | 作用 |
| --- | --- |
| `flows.draft_config.nodes[].answerSheetKey` | 当前标准答案；固定模板也使用这个位置 |
| `flows.draft_config.nodes[]._configMeta.answerKey` | 答案修改次数、修改人和时间，不保存旧答案 |
| `flow_versions.config_snapshot` | 发布题目结构；只有预览快照包含自己的标准答案 |
| `node_drafts` / `node_submissions` | 学生暂存 / 正式作答 |
| `flow_assets` / `flow_version_assets` | 教师题图及版本引用 |

成绩由后端读取时计算，不设答案表、成绩表或成绩历史表。教师编辑 API 仍传递独立的 `answerSheetKeys` 映射；后端在同一事务中合入配置，学生 API 则剔除私有答案字段。

## 7. 学生作答与提交数据

### 7.1 学生提交载荷

```json
{
  "answers": {
    "q1": { "selectedOptionId": "o2" },
    "q2": { "selectedOptionIds": ["o1", "o3"] },
    "q3": {
      "blankValues": {
        "b1": "4",
        "b2": "Four"
      }
    }
  }
}
```

提交接口沿用现有节点提交接口和 `idempotencyKey`。服务端只接受发布快照中存在的题目、选项和填空 ID；未知字段应拒绝，不能静默写入。

暂存允许未答完，但仍需执行结构校验；正式提交时，所有 `required=true` 的题目或填空必须完成。

### 7.2 学生端布局

- 节点标题和说明下方以紧凑标签显示总分与作答次数，不使用独立的横向元信息栏。
- 总分标签显示“总分 N 分”；不限次数时显示“截止前不限次”，有限次数时显示“剩余 N 次”。
- 截止时间继续使用独立提示栏，因为它属于需要学生注意的操作约束。
- 标题区与答题区之间只保留一条分隔线，避免形成内容稀疏的空白条带。
- 每道题使用独立题卡，显示序号、题型和分值。
- 单选使用 radio，多选使用 checkbox，填空标记原位渲染为文本输入框。
- 暂存不判分；正式提交时前后端均校验必答项。
- 提交后按照反馈策略展示结果，不在不允许的时间泄露标准答案。
- 已通过答题卡默认只读；是否允许修改应单独定义，不能直接继承现有表单节点的“通过后修改”规则。

## 8. 自动判分规则

### 8.1 通用规则

- 判分函数必须是无网络、无随机数、无当前时间依赖的纯函数。
- 判分输入为：版本题目结构、当前私有标准答案和当前正式提交。预览使用自己的答案快照。
- 分数只由服务端计算；客户端传入的 `score`、`passed` 等字段一律拒绝。
- 所有选项比较都基于稳定 ID，不基于显示文本或排列位置。
- V1 分值使用正整数，避免浮点舍入和 Excel 汇总歧义。

### 8.2 单选题

学生选择的选项 ID 与 `correctOptionId` 相同，获得该题全部分值；否则为 0 分。

### 8.3 多选题

V1 使用集合完全一致规则：

$$
score(q)=
\begin{cases}
p_q, & A_q=C_q \\
0, & A_q\ne C_q
\end{cases}
$$

其中 \(A_q\) 为学生所选选项集合，\(C_q\) 为标准答案集合，\(p_q\) 为该题分值。选项提交顺序不影响结果，重复选项 ID 应判为非法载荷。

V1 不做部分得分，避免“漏选、错选、倒扣分”组合产生不透明规则。若后续需要，应增加新的显式评分模式，而不是改变 `exact_set` 的语义。

### 8.4 填空题

每个空独立计分。比较前只执行：

1. Unicode NFC 规范化；
2. 将 `CRLF` 统一为 `LF`；
3. 去除首尾空白；
4. 当 `caseSensitive=false` 时执行 Unicode 大小写折叠。

规范化结果与任一 `acceptedAnswers` 完全相同即得该空全部分值，否则为 0 分。V1 不压缩中间空格、不执行正则、不计算数学表达式等价性，防止教师难以预测实际判分结果。

### 8.5 总分与节点状态

$$
S=\sum_{q=1}^{n} score(q)
$$

所有题目完整作答并成功提交后，提交与节点状态记为 `approved`，按现有流程规则推进下游。成绩不决定是否通过节点；修改标准答案、查看成绩或导出都不重置进度、不新增提交。旧提交保留，但当前成绩只依据当前尝试对应的正式提交计算。

## 9. 作答次数与反馈策略

### 9.1 作答次数

`maxAttempts`：

- `null`：截止时间前不限次数，建议作为练习默认值。
- 正整数：最多提交指定次数，适合测验。

已使用次数以后端成功创建的提交数量为准，暂存和重复幂等请求不计次数。达到次数上限后，学生仍可查看已允许展示的结果，但不能再次提交。

### 9.2 反馈策略

建议提供三个明确选项：

| 配置值 | 学生提交后可见内容 |
| --- | --- |
| `score_only` | 总分、满分和是否通过 |
| `question_result` | 总分、是否通过、每题得分或对错；不显示标准答案 |
| `full_after_deadline` | 截止前同 `question_result`，截止后增加标准答案 |

默认使用 `question_result`。只要仍允许再次提交，就不应立即展示标准答案，否则重答机制失去意义。

学生端响应应由后端按照反馈策略裁剪；不能先把完整评分结果下发，再由前端隐藏。

## 10. 提交与实时判分

提交事务校验学生身份、有效名单、实例归属、节点状态、时间、作答次数和幂等键，再校验并规范化学生答案，写入 `node_submissions`、更新节点状态和下游进度。不写成绩表。

学生进入流程或点击“查看节点分数”时，重新请求实例接口；后端读取当前正式提交与最新标准答案，计算总分及逐题结果，并按反馈策略裁剪。教师查看和导出复用同一计算函数。判分不新增提交、不消耗次数，也不修改节点进度。

返回的成绩示例：



```json
{
  "schemaVersion": "1.0",
  "graderVersion": "answer-sheet-v1",
  "score": 8,
  "maxScore": 10,
  "passed": true,
  "questionResults": [
    {
      "questionId": "q1",
      "awardedPoints": 2,
      "maxPoints": 2,
      "correct": true
    }
  ]
}
```

成绩仅存在于本次响应或导出文件中。标准答案内容哈希仅用于教师答案设置与变更审计，不用于恢复历史成绩。

## 11. API 边界建议

### 11.1 教师端

- `POST /api/workflows/{flowId}/nodes/{nodeKey}/answer-sheet-assets`：上传题图。
- `DELETE /api/workflows/{flowId}/answer-sheet-assets/{assetId}`：仅删除尚未被发布版本引用的题图。
- 草稿保存接口：在一个服务端事务中保存公开答题卡配置和私有答案草稿。
- 发布接口：联合校验题目和答案，冻结公开配置及题图引用；当前答案保存到流程配置中。
- `GET /api/workflow-admin/node-instances/{nodeInstanceId}/submission-detail`：扩展返回答题卡成绩明细。
- 现有节点 Excel 导出接口：扩展为答题卡成绩导出。

### 11.2 学生端

- 现有流程实例读取接口：只返回公开答题卡配置。
- 现有节点暂存接口：接受 `answers`，不判分。
- 现有节点提交接口：接受 `answers` 并同步返回学生可见评分结果。
- `GET /api/student/flow-instances/{instanceId}/content-assets/{assetId}`：鉴权后返回题图短期访问地址。

所有学生接口继续从登录会话取得学生身份，并持续校验当前流程的有效名单授权。

## 12. 发布、修订与数据保留

- 发布版本固定题目、选项、顺序、分值、反馈策略及版本资产引用。
- 已发布答题卡的题目结构不可直接改动；新增节点仍需发布并执行实例迁移。
- 标准答案通过教师答案设置立即更新到 `draft_config`，用修改次数防止旧页面覆盖新答案。
- 标题、说明和时间继续按已有实时参数规则处理。
- 原始学生提交与进度保留；旧答案修订和成绩历史不保存。正式查看及导出采用最新答案。
- 预览创建时将答案保存进自己的 `config_snapshot`，不随正式流程答案更新。

## 13. 教师查看与 Excel 导出

教师进度页在答题卡节点中增加：

- 学生姓名、学号、提交状态、提交时间；
- 当前得分、满分、是否通过、已提交次数；
- 当前提交次数、逐题得分和判定结果；
- 学生答案和最新标准答案可通过教师 Excel 导出查看；导出时重新计算成绩，原始提交继续保留。

节点 Excel 导出继续以有效名单为基准，每名学生一行；未提交学生的答案、成绩和提交时间使用空单元格，不使用“未提交”占位答案。建议工作簿包含：

1. `学生成绩`：一人一行，含总分、是否通过、次数和各题得分。
2. `学生答案`：一人一行，按题目或填空展开列。
3. `题目说明`：题号、题型、题干 Markdown、分值和选项；仅教师权限下可包含标准答案。

导出字符串仍需防止 Excel 公式注入。

## 14. 错误与异常语义

- 配置不完整：阻止发布，并定位到具体题目或填空。
- 图片上传失败：保留编辑内容，图片引用不写入题干。
- 资产不存在或不属于当前流程：阻止保存或发布。
- 提交结构非法：返回字段级错误，不创建提交、不消耗次数。
- 标准答案缺失或配置不合法：阻止保存或发布；读取时遇到异常则返回错误，不伪造零分或改变节点状态。
- 判分异常：本次成绩读取失败，可重试；既有提交不回滚，节点不进入 `audit_error`。
- 重复幂等请求：复用已有提交并返回当前实例，不重复扣减次数；返回的成绩按当前答案计算。

## 15. 实施模块划分

建议按以下边界实施，避免把全部逻辑堆入现有大型页面：

### 前端

- `AnswerSheetEditor`：教师题目、答案、分值和策略编辑。
- `MarkdownBlurEditor`：聚焦时显示原始 Markdown，失焦后切换为同位置只读渲染。
- `answerSheetMarkdown`：提供自定义公式定界符转换和序列化规则。
- `basicAnswerSheetMarkdown`：将渲染能力限制为标题、数学和代码。
- `AnswerSheetMarkdown`：组合 `react-markdown`、KaTeX 与代码高亮，供教师预览和学生端共用。
- `RuntimeAnswerSheet`：学生作答与校验。
- `RuntimeAnswerSheet` 的只读模式：已提交答案；`AnswerSheetGradeResult`：允许展示的评分反馈。
- `answerSheet.ts`：前端类型、纯校验、草稿规范化和编辑器辅助函数。

### 后端

- `domain/answer_sheet.py`：配置校验、答案规范化和纯判分函数。
- `repositories/answer_sheet_keys.py`：当前配置中的私有答案与预览答案读取。
- `repositories/flow_content_assets.py`：教师题图生命周期。
- `repositories/answer_sheet_grades.py`：统一实时判分及学生结果裁剪，不持久化成绩。
- 现有 `flow_instances` 提交事务：增加 `answer_sheet` 分支并复用状态推进。
- 现有发布服务：联合校验题目和答案，分开处理正式发布与预览。

## 16. 验收标准

1. 学生流程配置不包含标准答案；成绩结果严格按反馈策略裁剪。
2. 教师聚焦编辑框时始终看到原始 Markdown；失焦后才渲染，且不显示任何格式或图片按钮。
3. 只渲染一级/二级标题、粗体、斜体、列表、引用、GFM 表格、数学和代码高亮，未列出的 Markdown 格式不生效。
4. 单选、多选和填空题均由后端依据版本题目和当前标准答案实时判分。
5. 多选答案顺序不影响结果，漏选或多选均不得分。
6. 填空答案按文档规定的规范化规则稳定比较。
7. 同一幂等键不会产生两次提交；查看成绩不增加提交次数。
8. 完整合法提交后按现有流程开放下游；分数变化不重置进度。
9. 反馈策略由后端裁剪，重答期间不会意外泄露标准答案。
10. 教师预览和正式学生端的题目、公式、代码和作答控件一致。
11. 修改标准答案后，正式查看与导出采用新答案；已有预览仍采用自己的答案快照。
12. Excel 以有效名单为基准，一名学生一行，未提交字段保持为空。

## 17. V1 已采用的产品规则

1. 多选题采用完全匹配：漏选或多选均为 0 分，不设置部分分或倒扣。
2. 当前编辑器不提供独立的通过分数配置，完成合法提交即通过节点。
3. 默认在截止前不限次数；教师可配置 1、2、3、5 或 10 次。
4. 填空题支持多个等价文本答案、NFC、换行与首尾空白规范化及可选大小写敏感；V1 不做数值误差或数学表达式等价判定。
5. 默认反馈逐题得分但不泄露标准答案；教师可选择仅总分，或在设置截止时间后允许截止后展示标准答案。
6. 已发布题目结构固定；标准答案可独立更新，正式成绩按最新答案计算，预览答案固定。
