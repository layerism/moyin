# 答题卡节点设计方案

> 状态：已按本文完成代码实现；依据项目规范仅完成静态业务逻辑审计，未执行测试、前端构建或浏览器验收。
> 适用范围：Moyin OA DAG 流程中的教师设计端、学生运行端、自动判分与教师结果导出。

## 1. 实际使用场景

教师在流程中增加一个“答题卡”节点，用于课前测验、章节练习、实验准入测试或材料学习检查。例如：

1. 教师添加 3 道题：单选题、多选题和含两个空的填空题。
2. 教师用 Markdown 编写题干，在题干中插入公式和图片。
3. 教师配置各题分值、标准答案、及格分、作答次数和反馈策略。
4. 发布流程时，系统冻结题目、图片、评分规则和标准答案。
5. 学生进入节点，看到经过安全渲染的题目，暂存答案后提交。
6. 后端依据发布版本中的私有答案快照同步判分，保存不可变提交和评分结果。
7. 达到及格分时节点变为 `approved` 并开放 DAG 下游；未达到时变为 `rejected`，是否允许重答由教师配置决定。

核心调用链如下：

```text
教师编辑题目
  -> 上传题图并获得 assetId
  -> 保存公开题目配置 + 私有答案配置
  -> 发布时分别冻结公开快照和私有评分快照

学生读取节点
  -> 只取得公开题目配置
  -> 暂存 answers
  -> 提交 answers + idempotencyKey
  -> 后端读取私有评分快照
  -> 确定性判分
  -> 写入 Submission + Grade
  -> approved/rejected
  -> 必要时开放下游节点
```

## 2. 设计目标与边界

### 2.1 目标

- 支持单项选择题、多项选择题和填空题。
- 题干支持 Markdown、数学公式及教师上传的图片；选项支持 Markdown 与数学公式。
- 自动判分必须由后端执行，不能信任客户端提交的分数或判题结论。
- 标准答案不得出现在学生可读取的流程配置、接口响应或前端状态中。
- 复用现有发布快照、学生实例、节点状态、暂存、幂等提交和 DAG 推进机制。
- 教师预览与正式学生端复用同一套可见渲染组件和交互规则。
- 判分应可复现、可审计，同一发布版本和同一答案必须得到相同结果。

### 2.2 V1 不处理的能力

- 主观题、证明题、编程题和人工阅卷。
- AI 语义判分、正则表达式判分和数学表达式等价性证明。
- 随机抽题、随机选项顺序和题库组卷。
- 按班级排名、考试监考、倒计时强制交卷和防作弊。
- 学生在题目中上传附件。

这些能力不应混入 V1 的确定性答题卡模型；后续可通过新的题型或考试模式扩展。

## 3. 节点类型与现有系统关系

新增节点类型：

```ts
type AcademicFlowNodeKind =
  | "announcement"
  | "confirmation"
  | "file"
  | "form"
  | "answer_sheet";
```

答题卡不应作为现有 `form` 节点的特殊配置实现。两者虽然都包含输入控件，但业务语义不同：

| 维度 | 表单节点 | 答题卡节点 |
| --- | --- | --- |
| 目的 | 采集信息 | 测量作答结果 |
| 选项 | 无正确或错误之分 | 具有标准答案和分值 |
| 提交结果 | 保存字段值 | 保存答案并生成评分结果 |
| 状态推进 | 通常提交即通过 | 由及格策略决定是否通过 |
| 数据安全 | 字段配置可公开 | 标准答案必须私有 |

答题卡采用后端同步判分，不进入现有异步 AI 审核脚本队列。其判分是纯业务规则，不应伪装成审核脚本，否则会增加不必要的任务状态、重试和运行时依赖。

## 4. 教师端配置设计

### 4.1 节点入口

节点面板新增：

```text
┌──────────────────────┐
│ 答题卡               │
│ 选择题、填空题与自动判分 │
└──────────────────────┘
```

节点仍使用现有标题、说明、开放时间和截止时间。双击节点后，在设置窗口中显示答题卡编辑区。

### 4.2 编辑器布局

```text
┌──────────────────────────────────────────────────────────────┐
│ 答题卡设置                                      总分：10 分 │
├──────────────────────────────────────────────────────────────┤
│ 题目 1  [单项选择 ▼]  [2 分]                    [拖动] [⋯] │
│ ┌──────────────────────────────────────────────────────────┐ │
│ │ Markdown 实时编辑区                                     │ │
│ │ 设函数 f(x)=x² ...        ← 输入完整 $$...$$ 后原位渲染 │ │
│ │ [插入行内公式] [插入行间公式] [插入图片]                │ │
│ └──────────────────────────────────────────────────────────┘ │
│ ○ A. ...                                                     │
│ ● B. ...                                      ← 教师答案区  │
│ ○ C. ...                                                     │
├──────────────────────────────────────────────────────────────┤
│ 题目 2  [填空题 ▼]                                          │
│ 若 ...，则 [[blank:b1]]。                                   │
│ 空 b1：答案 [42] [四十二]  分值 [3]  [忽略英文大小写]        │
├──────────────────────────────────────────────────────────────┤
│ [+ 单选题] [+ 多选题] [+ 填空题]                             │
├──────────────────────────────────────────────────────────────┤
│ 及格分 [6] / 10   作答次数 [截止前不限 ▼]   反馈 [逐题对错 ▼]│
└──────────────────────────────────────────────────────────────┘
```

具体交互规则：

- 题目和选项使用稳定 ID；排序、改文案时不改变 ID。
- 题目通过上移、下移按钮调整顺序。
- 单选题必须且只能设置一个正确选项。
- 多选题至少设置一个正确选项，V1 采用“集合完全一致”计分。
- 填空题通过“插入填空”按钮产生 `[[blank:<blankId>]]` 标记；配置中每个标记必须恰好存在一次。
- Markdown 编辑和渲染位于同一个编辑区域，不设置左右分栏预览。
- 输入完整的 `$$...$$` 或 `$$$$...$$$$` 后，公式立即在当前位置渲染；点击已渲染公式可重新编辑其 LaTeX 源码。
- 编辑器始终显示总分、及格分和发布校验错误。
- 图片上传成功后自动在光标处插入 Markdown 资产引用。

### 4.3 发布前校验

发布时至少校验：

1. 节点至少有一道题。
2. 题目 ID、选项 ID、填空 ID 在各自作用域内唯一且非空。
3. 每道题题干非空，分值为正数。
4. 单选题至少两个选项，且恰有一个正确答案。
5. 多选题至少两个选项，且至少一个正确答案。
6. 填空题至少有一个空；题干标记与填空配置一一对应。
7. 每个空至少配置一个非空标准答案和一个正分值。
8. 及格分位于 \(0\) 到总分之间。
9. Markdown 中所有图片都引用当前流程所属、上传成功且未删除的资产。
10. 若反馈策略要求“截止后展示答案”，节点必须配置截止时间。

## 5. Markdown、数学公式与图片

### 5.1 数学公式语法与实时原位渲染

按照教师输入习惯，答题卡使用以下语法：

```markdown
圆的面积为 $$S=\pi r^2$$，其中 $$r$$ 为半径。

$$$$
\int_0^1 x^2\,dx=\frac{1}{3}
$$$$
```

- `$$...$$`：行内数学公式。
- `$$$$`：行间公式的开始和结束标记；开始、结束标记必须各自独占一行。
- 解析时先识别较长的 `$$$$`，再识别 `$$`，避免定界符冲突。
- 代码块和行内代码中的美元符号不参与公式解析。
- 教师编辑器提供“行内公式”和“行间公式”按钮，减少手工输入错误。

编辑器采用“Markdown 源码存储、编辑区原位渲染”的方式：

1. 教师输入开始定界符、LaTeX 内容和结束定界符。
2. 结束定界符完整后，编辑器立即把这段源码转换为可视公式节点，不需要切换预览模式。
3. 定界符尚未闭合时保留 Markdown 原文，不产生半成品公式节点。
4. 单击或使用键盘聚焦已渲染公式时，显示对应 LaTeX 源码并允许修改；失去焦点后再次渲染。
5. 数据库存储的始终是 Markdown 源码，不存储 KaTeX 生成的 HTML，保证内容可迁移、可重新渲染。

例如，教师完成输入 `圆的面积为 $$S=\pi r^2$$` 后，当前编辑区中的公式部分立即显示为排版后的 \(S=\pi r^2\)，其余文字仍可继续编辑。

该语法与常规 LaTeX Markdown 的 `$...$`、`$$...$$` 不同，因此实现独立的语法转换层，并显式跳过代码围栏和行内代码，不能直接对整段文本做无边界替换。

### 5.2 图片引用

教师上传图片后，服务端返回不可变 `assetId`，编辑器插入：

```markdown
![抛物线示意图](asset://asset_01J...)
```

公开题目快照只保存 `asset://` 引用，不保存 OSS 永久地址或临时签名地址。学生查看时，通过具备流程、名单和实例权限校验的后端资源接口取得短期签名 URL。

V1 建议仅允许 PNG、JPEG 和 WebP，单张不超过 5 MB；不允许 SVG、`data:` URL、`javascript:` URL和任意外部图片 URL。图片必须填写替代文本，兼顾无障碍访问和图片加载失败时的理解。

题图属于“教师内容资产”，不能复用学生提交文件表。两者的所有者、生命周期、权限和发布语义完全不同。

### 5.3 安全渲染

教师预览、真实学生预览和正式学生端统一复用 `AnswerSheetMarkdown`：

```text
Markdown AST
  -> 自定义公式语法插件
  -> 数学节点交给 KaTeX
  -> asset:// 图片节点解析
  -> 拒绝 Markdown 原始 HTML
  -> React 渲染
```

安全要求：

- 不启用 Markdown 原始 HTML。
- KaTeX 使用不信任模式，不允许危险协议和任意 HTML 扩展。
- 链接只允许 `https:`；外部链接增加安全的 `rel` 属性。
- 图片只允许受控的 `asset://` 标识，由应用层解析。
- 教师题干预览、学生题干和选项使用相同的渲染规则。

### 5.4 组件库选型

答题卡不使用同一个组件同时承担编辑和只读展示，而是按照职责组合：

| 场景 | 采用组件 | 职责 |
| --- | --- | --- |
| 教师 Markdown 实时编辑 | `@milkdown/crepe` | 在同一编辑区域内完成 Markdown 编辑、公式原位渲染和源码回写 |
| 数学公式排版 | `katex` | 将 LaTeX 数学节点渲染为可视公式 |
| 学生端及提交结果展示 | 项目现有的 `react-markdown` | 只读渲染题干、选项和图片 |
| 数学节点转为 KaTeX | `rehype-katex` | 将 Markdown AST 中的数学节点交给 KaTeX |
| 自定义公式语法 | 项目内转换层 | 统一转换 `$$...$$` 行内公式和 `$$$$...$$$$` 行间公式，并保护代码区域 |

选择 `@milkdown/crepe` 的原因是其属于 Markdown 优先的所见即所得编辑器，底层基于 ProseMirror 和 remark，适合实现“输入闭合定界符后立即原位渲染、点击公式后重新编辑源码”。项目当前安装的 `react-markdown` 只负责从 Markdown 到 React 的渲染，不具备可编辑文档模型，因此不能单独完成该交互。

实现中封装共享的 `answerSheetMarkdown` 语法层：

```text
教师编辑：Milkdown/ProseMirror
  -> answerSheetMarkdown
  -> KaTeX 原位公式节点
  -> Markdown 序列化后保存

学生展示：react-markdown
  -> answerSheetMarkdown
  -> rehype-katex
  -> React 只读内容
```

该共享语法层必须对编辑端和展示端使用同一组解析测试，防止教师端能够显示、学生端却显示为原始符号。Milkdown 默认数学语法不能直接代替本项目规则，因为本项目明确使用 `$$...$$` 表示行内公式、使用 `$$$$...$$$$` 表示行间公式。

依赖版本在实施时依据项目固定的 Node.js 24.18.0、React 18 和现有 Vite 构建环境完成兼容性核对后锁定。本设计阶段不预先写死未经构建验证的版本号。

## 6. 公开题目与私有答案分离

### 6.1 不能把答案放进节点 JSON

当前学生运行接口会返回发布版本中的节点配置。若在 `config_snapshot` 中保存 `correctOptionId` 或标准填空答案，即使界面不展示，学生仍可通过网络响应或前端状态读取。因此必须从数据层分离，而不是仅依赖前端隐藏字段。

### 6.2 公开节点快照

```json
{
  "id": "answer-sheet-01",
  "kind": "answer_sheet",
  "title": "函数基础测试",
  "requirement": "总分 10 分，达到 6 分后进入下一节点。",
  "answerSheet": {
    "schemaVersion": "1.0",
    "questions": [
      {
        "id": "q1",
        "type": "single_choice",
        "content": "若 $$f(x)=x^2$$，则 $$f(2)$$ 等于：",
        "points": 2,
        "required": true,
        "options": [
          { "id": "o1", "content": "2" },
          { "id": "o2", "content": "4" }
        ]
      },
      {
        "id": "q2",
        "type": "multiple_choice",
        "content": "下列属于偶函数的是：",
        "points": 3,
        "required": true,
        "options": [
          { "id": "o1", "content": "$$x^2$$" },
          { "id": "o2", "content": "$$x^3$$" },
          { "id": "o3", "content": "$$|x|$$" }
        ]
      },
      {
        "id": "q3",
        "type": "fill_blank",
        "content": "$$2+2=[[blank:b1]]$$；英文 four 写作 [[blank:b2]]。",
        "required": true,
        "blanks": [
          { "id": "b1", "points": 2 },
          { "id": "b2", "points": 3 }
        ]
      }
    ],
    "gradingPolicy": {
      "passingScore": 6,
      "maxAttempts": null,
      "feedback": "question_result"
    }
  }
}
```

学生可以看到题目分值和及格要求，但看不到任何标准答案。

### 6.3 私有评分快照

```json
{
  "schemaVersion": "1.0",
  "graderVersion": "answer-sheet-v1",
  "answers": {
    "q1": {
      "type": "single_choice",
      "correctOptionId": "o2"
    },
    "q2": {
      "type": "multiple_choice",
      "correctOptionIds": ["o1", "o3"],
      "mode": "exact_set"
    },
    "q3": {
      "type": "fill_blank",
      "blanks": {
        "b1": {
          "acceptedAnswers": ["4", "四"],
          "caseSensitive": false
        },
        "b2": {
          "acceptedAnswers": ["four"],
          "caseSensitive": false
        }
      }
    }
  }
}
```

建议新增以下私有数据：

| 数据 | 作用 |
| --- | --- |
| `answer_sheet_drafts` | 保存某流程草稿中各答题卡节点的私有答案配置 |
| `flow_version_answer_keys` | 发布时冻结的私有评分快照及 `grading_hash` |
| `flow_content_assets` | 教师题图的 OSS 元数据和归属 |
| `flow_version_content_assets` | 固定发布版本所引用的题图 |
| `answer_sheet_grades` | 一次提交对应的不可变评分结果 |

发布事务应同时冻结公开配置、私有答案和引用资产；任一部分失败则整体回滚。

## 7. 学生作答与提交数据

### 7.1 学生提交载荷

```json
{
  "answers": {
    "q1": { "selectedOptionId": "o2" },
    "q2": { "selectedOptionIds": ["o1", "o3"] },
    "q3": {
      "blankValues": {
        "b1": "4",
        "b2": "Four"
      }
    }
  }
}
```

提交接口沿用现有节点提交接口和 `idempotencyKey`。服务端只接受发布快照中存在的题目、选项和填空 ID；未知字段应拒绝，不能静默写入。

暂存允许未答完，但仍需执行结构校验；正式提交时，所有 `required=true` 的题目或填空必须完成。

### 7.2 学生端布局

- 顶部显示节点标题、说明、总分、及格分、剩余作答次数和截止时间。
- 每道题使用独立题卡，显示序号、题型和分值。
- 单选使用 radio，多选使用 checkbox，填空标记原位渲染为文本输入框。
- 暂存不判分；正式提交时前后端均校验必答项。
- 提交后按照反馈策略展示结果，不在不允许的时间泄露标准答案。
- 已通过答题卡默认只读；是否允许修改应单独定义，不能直接继承现有表单节点的“通过后修改”规则。

## 8. 自动判分规则

### 8.1 通用规则

- 判分函数必须是无网络、无随机数、无当前时间依赖的纯函数。
- 判分输入固定为：公开题目快照、私有答案快照和本次规范化答案。
- 分数只由服务端计算；客户端传入的 `score`、`passed` 等字段一律拒绝。
- 所有选项比较都基于稳定 ID，不基于显示文本或排列位置。
- V1 分值使用正整数，避免浮点舍入和 Excel 汇总歧义。

### 8.2 单选题

学生选择的选项 ID 与 `correctOptionId` 相同，获得该题全部分值；否则为 0 分。

### 8.3 多选题

V1 使用集合完全一致规则：

$$
score(q)=
\begin{cases}
p_q, & A_q=C_q \\
0, & A_q\ne C_q
\end{cases}
$$

其中 \(A_q\) 为学生所选选项集合，\(C_q\) 为标准答案集合，\(p_q\) 为该题分值。选项提交顺序不影响结果，重复选项 ID 应判为非法载荷。

V1 不做部分得分，避免“漏选、错选、倒扣分”组合产生不透明规则。若后续需要，应增加新的显式评分模式，而不是改变 `exact_set` 的语义。

### 8.4 填空题

每个空独立计分。比较前只执行：

1. Unicode NFC 规范化；
2. 将 `CRLF` 统一为 `LF`；
3. 去除首尾空白；
4. 当 `caseSensitive=false` 时执行 Unicode 大小写折叠。

规范化结果与任一 `acceptedAnswers` 完全相同即得该空全部分值，否则为 0 分。V1 不压缩中间空格、不执行正则、不计算数学表达式等价性，防止教师难以预测实际判分结果。

### 8.5 总分与节点状态

$$
S=\sum_{q=1}^{n} score(q)
$$

当 \(S\ge S_{pass}\) 时：

- 提交状态写为 `approved`；
- 节点写为 `approved`；
- 在同一事务内推进下游节点。

当 \(S<S_{pass}\) 时：

- 提交状态写为 `rejected`；
- 节点写为 `rejected`；
- 若仍有作答次数且未截止，允许创建下一次作答；
- 若次数耗尽，保持未通过并提示联系教师。

若教师希望“只记录成绩，不阻塞流程”，可将及格分配置为 0，此时任何合法提交都会通过节点。

## 9. 作答次数与反馈策略

### 9.1 作答次数

`maxAttempts`：

- `null`：截止时间前不限次数，建议作为练习默认值。
- 正整数：最多提交指定次数，适合测验。

已使用次数以后端成功创建的提交数量为准，暂存和重复幂等请求不计次数。达到次数上限后，学生仍可查看已允许展示的结果，但不能再次提交。

### 9.2 反馈策略

建议提供三个明确选项：

| 配置值 | 学生提交后可见内容 |
| --- | --- |
| `score_only` | 总分、满分和是否通过 |
| `question_result` | 总分、是否通过、每题得分或对错；不显示标准答案 |
| `full_after_deadline` | 截止前同 `question_result`，截止后增加标准答案 |

默认使用 `question_result`。只要仍允许再次提交，就不应立即展示标准答案，否则重答机制失去意义。

学生端响应应由后端按照反馈策略裁剪；不能先把完整评分结果下发，再由前端隐藏。

## 10. 提交事务与评分审计

提交事务建议按以下顺序执行：

1. 校验当前学生身份、有效名单和实例归属。
2. 锁定并读取节点实例，校验前驱、状态、开放时间、截止时间和作答次数。
3. 依据 `idempotencyKey` 查询已有提交；命中时直接返回原结果。
4. 从 `flow_version_answer_keys` 读取当前发布版本的私有评分快照。
5. 严格校验并规范化学生答案。
6. 使用固定 `graderVersion` 计算分数和逐题结果。
7. 写入不可变 `submissions` 和一对一的 `answer_sheet_grades`。
8. 更新节点状态；通过时推进下游。
9. 提交事务。

评分记录建议包含：

```json
{
  "schemaVersion": "1.0",
  "graderVersion": "answer-sheet-v1",
  "gradingHash": "sha256:...",
  "score": 8,
  "maxScore": 10,
  "passingScore": 6,
  "passed": true,
  "questionResults": [
    {
      "questionId": "q1",
      "awardedPoints": 2,
      "maxPoints": 2,
      "correct": true
    }
  ]
}
```

评分记录不必复制标准答案；`gradingHash` 用于证明本次判分使用的答案快照，私有答案仍由发布版本表保存。

## 11. API 边界建议

### 11.1 教师端

- `POST /api/workflows/{flowId}/nodes/{nodeKey}/answer-sheet-assets`：上传题图。
- `DELETE /api/workflows/{flowId}/answer-sheet-assets/{assetId}`：仅删除尚未被发布版本引用的题图。
- 草稿保存接口：在一个服务端事务中保存公开答题卡配置和私有答案草稿。
- 发布接口：联合校验并冻结公开快照、私有答案快照和题图引用。
- `GET /api/workflow-admin/node-instances/{nodeInstanceId}/submission-detail`：扩展返回答题卡成绩明细。
- 现有节点 Excel 导出接口：扩展为答题卡成绩导出。

### 11.2 学生端

- 现有流程实例读取接口：只返回公开答题卡配置。
- 现有节点暂存接口：接受 `answers`，不判分。
- 现有节点提交接口：接受 `answers` 并同步返回学生可见评分结果。
- `GET /api/student/flow-instances/{instanceId}/content-assets/{assetId}`：鉴权后返回题图短期访问地址。

所有学生接口继续从登录会话取得学生身份，并持续校验当前流程的有效名单授权。

## 12. 发布、修订与历史数据

- 发布版本冻结题目、选项、顺序、分值、答案、反馈策略和引用图片。
- 发布版本固定 `graderVersion` 与 `gradingHash`，后续程序升级不能改变历史分数。
- 已发布答题卡节点不可删除；已发布题目和答案在 V1 中不可直接修改。
- 标题、节点说明和起止时间继续遵循现有发布后修订规则。
- 新增答题卡节点时，继续执行现有 DAG 影响分析和学生实例迁移。
- 历史提交、答案和评分结果不可清空；流程修订导致节点失效时，仍保留旧提交供教师审计。

如果后续确需“纠正已发布标准答案”，应单独设计带原因、影响人数、重新判分范围和审计日志的管理操作，不能直接覆盖原答案快照。

## 13. 教师查看与 Excel 导出

教师进度页在答题卡节点中增加：

- 学生姓名、学号、提交状态、提交时间；
- 当前得分、满分、是否通过、已提交次数；
- 当前提交次数、逐题得分和判定结果；
- 学生答案和标准答案通过教师 Excel 导出查看；历史提交与 `gradingHash` 在数据库中保留。

节点 Excel 导出继续以有效名单为基准，每名学生一行；未提交学生的答案、成绩和提交时间使用空单元格，不使用“未提交”占位答案。建议工作簿包含：

1. `学生成绩`：一人一行，含总分、是否通过、次数和各题得分。
2. `学生答案`：一人一行，按题目或填空展开列。
3. `题目说明`：题号、题型、题干 Markdown、分值和选项；仅教师权限下可包含标准答案。

导出字符串仍需防止 Excel 公式注入。

## 14. 错误与异常语义

- 配置不完整：阻止发布，并定位到具体题目或填空。
- 图片上传失败：保留编辑内容，图片引用不写入题干。
- 资产不存在或不属于当前流程：阻止保存或发布。
- 提交结构非法：返回字段级错误，不创建提交、不消耗次数。
- 私有评分快照缺失或哈希不一致：视为系统配置异常，不创建提交，不把节点标为未通过。
- 判分程序内部异常：事务回滚，学生可重试，不进入 `audit_error`；`audit_error` 仍保留给现有异步审核链路。
- 重复幂等请求：返回第一次提交和评分结果，不重复扣减次数。

## 15. 实施模块划分

建议按以下边界实施，避免把全部逻辑堆入现有大型页面：

### 前端

- `AnswerSheetEditor`：教师题目、答案、分值和策略编辑。
- `CrepeMarkdownEditor`：封装 `@milkdown/crepe`，保存 Markdown 源码，并在同一编辑区内原位渲染公式和图片。
- `answerSheetMarkdown`：为 Milkdown 与 `react-markdown` 提供一致的自定义公式定界符解析和序列化规则。
- `AnswerSheetMarkdown`：组合 `react-markdown`、`remark-math`、`rehype-katex` 与 KaTeX，统一安全渲染 Markdown、公式和题图。
- `RuntimeAnswerSheet`：学生作答与校验。
- `RuntimeAnswerSheet` 的只读模式：已提交答案；`AnswerSheetGradeResult`：允许展示的评分反馈。
- `answerSheet.ts`：前端类型、纯校验、草稿规范化和编辑器辅助函数。

### 后端

- `domain/answer_sheet.py`：配置校验、答案规范化和纯判分函数。
- `repositories/answer_sheet_keys.py`：私有答案草稿与发布快照。
- `repositories/flow_content_assets.py`：教师题图生命周期。
- `repositories/answer_sheet_grades.py`：不可变评分记录。
- 现有 `flow_instances` 提交事务：增加 `answer_sheet` 分支并复用状态推进。
- 现有发布服务：增加公开配置与私有答案联合冻结。

## 16. 验收标准

1. 学生接口和页面源数据中不存在标准答案。
2. 教师在同一 Markdown 编辑区输入完整的 `$$...$$` 或独占行 `$$$$...$$$$` 后，公式立即原位渲染；点击公式可以恢复源码编辑，学生端显示结果与教师端一致。
3. 题图不保存永久公开 URL，名单外学生不能访问。
4. 单选、多选和填空题均由后端依据发布版本自动判分。
5. 多选答案顺序不影响结果，漏选或多选均不得分。
6. 填空答案按文档规定的规范化规则稳定比较。
7. 同一幂等键不会产生两次提交或两条评分记录。
8. 达到及格分才按配置开放下游；及格分为 0 时合法提交即开放。
9. 反馈策略由后端裁剪，重答期间不会意外泄露标准答案。
10. 教师预览和正式学生端的题目、公式、图片和作答控件一致。
11. 发布版本固定答案、图片、评分器版本和哈希，历史结果可复现。
12. Excel 以有效名单为基准，一名学生一行，未提交字段保持为空。

## 17. V1 已采用的产品规则

1. 多选题采用完全匹配：漏选或多选均为 0 分，不设置部分分或倒扣。
2. 新建答题卡的及格分默认等于初始总分，教师可调整为 0 到总分之间的整数。
3. 默认在截止前不限次数；教师可配置 1、2、3、5 或 10 次。
4. 填空题支持多个等价文本答案、NFC、换行与首尾空白规范化及可选大小写敏感；V1 不做数值误差或数学表达式等价判定。
5. 默认反馈逐题得分但不泄露标准答案；教师可选择仅总分，或在设置截止时间后允许截止后展示标准答案。
6. 已发布答题卡的题目、选项、分值、答案和题图不可直接修改或删除；纠错通过新增替代节点处理。
