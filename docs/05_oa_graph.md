# OA 流程图设计说明

> 本文用于手写梳理 OA 流程图的业务语义、配置结构、发布逻辑与学生端运行规则。

## 1. 原理和逻辑

- 教师会通过拖拉拽方式搭建一个流程图，流程图是 DAG 图
- 每个图节点都包含需要可由教师自定义采集的信息组件，还配有自动审查
- 教师发布流程图后，会固化一个图的定义到数据库库
- 学生侧会根据该图的定义，展示出相应的图
- 学生点击图中每个节点，可以根据要求填写或上传文件，提交后等待审核
- 审核会执行一个 py 或者 js 脚本，失败会提示脚本报的错误，方便学生查错更改
- 如果审核通过，则 DAG 下游节点访问权限将会放开，学生可以如此类推完成整个流程
- 如果审核不通过，则学生需要完成才能走下一步

## 每个节点基础功能
- 根据不同组件，分表单填写文件提交，以及条件分支等，用户会随时更新组件
- 文件提交节点必须包含一个脚本审核，脚本模板自拟，并提供给用户下载
- py 脚本

## 发布后管理
- 流程图发布后可以更改或增加节点，不可以删除原先的节点，也不可以更改原先的连接关系
- 修改节点包含：修改节点要提交的内容，更换审核脚本等
- 增加节点包含：新增节点并创建连线

## 学生状态管理
- 每个流程当中有许可权限的学生，看的图的拓扑结果是完全一致的
- 每个学生都有独立的填写状态，标记了每个节点的填写进度
- 如果发布后，流程图某个节点被改变（修改，或者新增），则该节点的后续所有子节点都需要重新填写，但是之前填写的内容不会被清空
