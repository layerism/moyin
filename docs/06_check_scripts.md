# 审查脚本逻辑

> 本文用于手写审查脚本逻辑相关运行逻辑

## 审查脚本如何构建
- 需要在 backend/scripts 下构建审查脚本，提供必要的 meta 信息，支持前端修改部分 meta 信息，例如名字

### 审查脚本要求
- 必须是 python 的脚本
- 输入和输出都是 json 结构，而且需要固定一个统一的模板
- 输出必须包含 `pass` 字段，以及 `reason` 字段 表示是否审查通过，以及不通过的原因，其余字段属于定制
- 需要在 backend 提前安装好处理 docx，xlsx，pdf，pptx，jpeg，jpg，png 格式的相关 python 库
- 脚本支持从项目 .env 获取环境密钥，例如 openai 的 apikey 等

## 审查脚本如何使用
### 教师端
- 只有文件上传节点需要添加脚本审查
- 脚本审查是单项选择，根据审查脚本 meta 信息提供的名字作为选项
- 发布以后将跟随

### 学生侧
- 点击文件上传节点，选择文件上传，然后点击确认
- 确认后执行审查，不阻塞学生后续流程
- 节点审查不通过（pass=false），该节点的子节点不能放开，将会在当前节点显示一个错误的提示，点击提示，弹窗显示 reason，敦促学生重新修改上传
- 节点审查通过（pass=true），将允许 DAG 放开下游子节点的权限
