# DOCX 表格 AI 定点编辑设计

> 2026-09-20 · 讨论稿，尚未实现。

## 1. 目标

根据表名、表序号、行列和关键词定位编辑区域，按提示词生成内容，保留所需格式并替换写入。任务按文档中的表格顺序执行，结果另存为新 DOCX。

`assets/` 仅用于提炼共性和验证方案，不按文件名、业务字段或具体模板编写特殊逻辑。不追求覆盖所有 Word 结构；无法可靠处理的目标返回明确原因。

## 2. 核心流程

```text
解析文档 → 建立索引 → 定位全部任务 → 检查冲突
→ 按表格及区域顺序生成、替换 → 保存新 DOCX 和修改记录
```

只需要三个核心对象：

| 对象 | 内容 |
|---|---|
| 文档索引 | 表格顺序、名称线索、单元格位置、合并范围、文本及格式 |
| 编辑任务 | 定位条件、替换范围、提示词、参考资料、格式策略 |
| 替换操作 | 目标 ID、原内容校验值、替换范围、新内容及格式属性 |

AI 负责生成内容，也可提出定位候选；程序负责位置校验、格式应用和文件写入。AI 不输出任意代码或 XML。

## 3. 定位与替换

- **组合定位**：表名、表序号、行列、关键词按需填写，最终必须唯一定位；条件冲突或多解时返回候选，不猜测写入。
- **编号明确**：表序号与行列从 1 开始；物理表顺序不等于题注编号。合并格的多个坐标映射到同一实际单元格。
- **关键词定位**：支持空白、换行、全半角等规范化匹配；模糊匹配只用于提出候选。匹配文本须能映射回原始位置。
- **范围明确**：支持单元格正文替换，以及明确起止边界之间的替换。关键词可以是标签或边界，不一定是删除对象。
- **先定位后编辑**：提前固定所有目标，避免前面的替换破坏后续关键词；重叠区域先报告冲突。

示例仅表达任务结构，不是已实现的接口：

```yaml
定位:
  表名: 项目说明
  表序号: 2
  行: 4
  列: 2
替换:
  起点: 实施方案标题之后
  终点: 预期成果标题之前
生成:
  提示词: 根据项目资料编写实施方案，分两段，约300字
  参考资料: 项目资料
格式: 继承目标正文
```

自然语言边界须先解析为确定的段落或字符位置。字段填写与长文生成共用替换机制；已有明确字段值时可直接填入。

## 4. 内容与格式

向模型提供任务、目标原文、必要上下文和参考资料。区分模板示例与用户事实，不将示例内容直接视为真实信息。

默认继承目标正文格式；任务明确指定的字体、字号、行距等覆盖对应属性，其余保留。正文或批注中的说明只作为候选规则，作用范围明确并被任务采用后才执行。

采用局部写入，保留区域外内容、表格结构及未涉及的文档包部件。不将 DOCX 转成 Markdown 再重建，也不以整体赋值 `cell.text` 作为通用替换方法。

目标包含无法可靠处理的图片、域、修订等结构时停止该项；复杂对象位于目标之外时尽量原样保留。格式保留不保证分页不变，第一版不自动缩字号、改行高或实现精准分页。

## 5. 最小实现与系统接入

- `python-docx`：读取常规表格、段落及样式，项目已有依赖。
- `lxml`、`zipfile`：必要的 XML 定位和局部修改。
- 现有模型连接：生成受约束的正文或段落列表。

复用现有执行基础设施。当前 `audit_script_executor.py` 返回审核 JSON，并在结束后清理临时目录；需要补充受控文件输出，在清理前校验并将结果保存到 OSS，关联原文件与任务。

遵循 `MEMORY.md`：原提交与发布快照不变，下载经过服务端权限校验。编辑完成与审核通过分别记录。

结果包括新 DOCX、逐项修改记录及失败原因。默认全部成功才产出正式结果；重试从原始输入和已接受的操作重建，避免重复追加。

## 6. 第一版边界与验收

**实现**：正文顶层表格、支持范围内的合并格、组合定位、整格正文与格内区间替换、格式继承和明确属性覆盖、顺序执行。

**暂不实现**：通用复选框编辑、改表结构、修订处理、所有 Word 对象编辑及精准分页。扩展依据实际反复出现的需求，不依据单个样本增加功能。

验收重点：更换表名、字段和表格数量无需修改核心代码；歧义和冲突能被发现；替换不越界；非目标内容保持不变；不支持的区域能解释原因。`assets/` 只是验证材料之一。本轮未实施或运行测试。
