# 提交后保留学生节点弹窗

## 需求

学生在节点弹窗内提交内容后，不再因节点立即通过而自动退出弹窗。提交结果应直接在当前弹窗内呈现，学生仍可通过右上角关闭按钮或点击遮罩主动退出。

## 当前原因

`StudentRuntimePage.submit()` 在服务端返回的节点状态为 `approved` 时调用 `setActiveNodeKey(null)`，导致共享的 `RuntimeNodeDialog` 立即卸载。答题卡通常同步评分并直接通过，因此该行为最明显。

## 设计

- 提交成功后继续使用服务端返回的最新实例更新页面。
- 节点变为 `approved` 时保留 `activeNodeKey`，使当前弹窗按最新状态重渲染为只读结果。
- 清除 `amendingNodeId`，确保已通过表单修改提交后退出编辑模式，但不关闭弹窗。
- 保留审核中、答题未通过、字段错误、提交异常及手动关闭逻辑。
- 修改共享的 `StudentRuntimePage`，因此正式学生端和教师真实学生预览保持一致。

## 范围

仅修改前端提交成功后的弹窗状态，不修改 API、后端提交事务、评分、审核或节点推进规则。

## 验证边界

按照项目规则，本任务不运行自动测试、类型检查或浏览器插件；实施后通过静态调用链审计和 Git 差异检查确认范围。

## 实施结果

已移除节点立即通过分支中的自动关闭调用。`setInstance(next)` 更新运行实例后，`activeNodeKey` 保持不变，`activeRuntime` 因而从最新实例中取得同一节点并在原弹窗内展示只读结果；用户主动关闭弹窗的既有调用仍保留。
