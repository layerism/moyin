# DOCX 项目字体按缺失字符补齐

用户批准按前述补齐机制修缮预览：XML 字体优先，仅缺字使用项目字体，保持不依赖 Linux 字体库。遵循根 MEMORY.md 的当前源码优先和共享预览约束，保留文件组织、无关审核配置修改；当前分支实施前后各一次检查点，不运行测试或浏览器插件，完成后通过 `bash deploy/run_dev.sh` 重启。

实现范围：`docxFonts.ts`、共享 `DocxPreview.tsx` 和字体说明。未知字体、未配置主题/脚本槽位和字体文件失败仍明确报错，不将它们泛化为宋体。缺字由已加载原字体的 cmap 判定：仿宋_GB2312 → 仿宋，楷体_GB2312 → 楷体，之后项目宋体 → 微软雅黑，跳过原字体。所有候选都缺字时使用已验证的项目宋体方框占位，显示原字符码位。符号字体或私用区缺字直接占位，避免相同码位在不同字体中意义不一致。控制和默认可忽略字符不要求单独字形。

保留字体槽位、字号、加粗/斜体和符号编码规则。以原字体、请求字重/字形、字符码位记录补齐结果；字体下载与原始字体对象沿用缓存，仅缺字时加载必要候选。正文按字符分组补齐，编号文字与生成计数器使用同一字符选择结果；CSS 计数器无法逐字符改写，若其候选都缺字，该编号整体占位。编号字体别名按原始字体文件字形与覆盖范围复用，释放和失败清理均处理共享对象。XML 单字体的 SVG/MathML 文本仅追加明确的项目补齐字体，保留原字体优先。

共享组件显示可展开的补齐/占位提示，列出原字体、目标字体与字符编码；每组最多展示 12 种并注明总数，限制提示高度。字体处理完成后再分页，模板、参考文件与人工审核预览复用同一行为。当前采用项目固定策略，不声称与 Windows/Word 的自动选择完全相同。

静态核对 TypeScript no-emit、差异格式、字体文件 cmap（U+5570 在旧仿宋缺失、新仿宋存在，宋体提供占位 U+25A1）及所有调用方。不运行测试、构建和浏览器验证。
