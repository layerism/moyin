# 信息表单发布后配置更新

## 范围与依据

依据 `docs/published-node-editing-and-student-progress-requirements-form.md` 的信息表单规则，仅调整 `kind=form`：标题、说明、开始时间、截止时间属于可变配置；字段与选项结构仍受发布锁定约束。

项目 `MEMORY.md` 所述流程版本引用、稳定 `node_key`、学生实例及历史提交机制继续复用。无需数据库表结构变更、数据回填或手动修改现有学生记录。

## 实施

1. 修订分析保留 `changedNodeIds`，单独比较进度相关配置。表单上述四个字段不作为失效起点；其他节点变更、前驱变化及其下游影响保持原规则。
2. 发布后学生流程实例引用新版本。没有失效节点时不调用失效处理，以保留完成时间；已通过节点、提交批次、草稿和历史提交保留。
3. 对本次变更且未被其他修改失效的未完成表单，按新版本时间、学生个别截止时间及前驱条件更新操作状态。已通过、审核中等状态不参与条件重置；草稿内容保留。读取和提交继续复用现有时间校验。
4. 发布确认界面按实际失效范围显示提示，区分内容变更与需要重做。

## 边界

- 修改保存后仍需重新发布生效，不增加即时保存配置接口。
- 不改变其他节点的审核参数策略，不修改人工审核及文件历史清理逻辑。
- 同次发布若另有上游失效或前驱结构变化，表单仍可被这些变化影响；仅表单自身四项配置变化不触发重做。
- 不修复过去已发生的进度重置，也不改写旧版本快照。

## 静态审计

- 核对修订影响预览与正式发布复用同一分析函数。
- 核对字段锁定、实例版本迁移、条件检查及正式提交链路。
- 使用 Python AST 解析与 `git diff --check` 检查语法和补丁格式。
- 按项目要求不运行测试、构建或浏览器验证；完成后仅重启开发服务并检查进程与端口。
