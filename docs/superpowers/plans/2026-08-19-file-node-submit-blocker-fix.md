# 文件节点提交按钮错误禁用修复计划

## 现象

学生在带模板的普通文件节点完成模板下载并成功上传文件后，界面显示“文件已上传，可提交”，但“提交节点”按钮仍然禁用。教师预览和正式学生端复用同一运行组件，因此两侧表现一致地出错。

## 根因

`StudentRuntimePage.tsx` 使用 `Boolean(runtime.template)` 判断是否启用扫描件提交校验。普通文件节点也可以配置模板，于是它被错误要求满足确认承诺节点专属的条件：勾选确认、上传扫描件。

文件节点没有确认框和扫描件上传区，因此 `getScanSubmitBlocker()` 会持续返回阻断原因。后端 `submit_node()` 已正确区分普通文件与模板确认节点，问题仅存在于前端共享提交条件。

## 最小修改

- 修改 `frontend/src/features/academic-flow/StudentRuntimePage.tsx`。
- 扫描件提交校验仅在 `node.kind === "confirmation" && Boolean(runtime.template)` 时启用。
- 不修改文件上传、提交接口、数据库或节点状态逻辑。
- 共享组件修改同时作用于教师预览和正式学生端。

## 静态验收

1. 普通文件节点：模板已下载、文件已上传且没有正在上传时，扫描件校验不再禁用提交按钮。
2. 模板确认节点：仍要求确认、模板下载和至少一个扫描件。
3. 无数据库和后端改动。
4. `git diff --check` 无错误；前后端本地服务重启并监听 5173/8000。
