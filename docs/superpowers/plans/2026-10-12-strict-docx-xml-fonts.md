# DOCX 仅使用 XML 指定的项目字体

用户已确认移除备用字体，并要求补充微软雅黑、等线、Arial、Calibri、Consolas。遵循根 MEMORY.md 的共享预览、项目内资源、任务范围提交和本地 run_dev 启动约束。

1. 从固定版本的字体仓库取得所需原字体文件，包含真实粗体、斜体及已有轻字重；记录源 URL、Git blob、字体内部名称、版本和 SHA256。不安装系统字体，不把社区来源表述为厂商官方下载或授权。
2. 从 DOCX 的 document/styles/theme/settings/numbering 及页眉页脚、脚注尾注 XML 解析字体配置。合并文档默认、样式 basedOn、段落样式、字符样式、直接 rPr，按 ascii/hAnsi/eastAsia/cs 和主题语言分配文本字体，而非从操作系统计算出的字体名反推。
3. 只加载实际渲染文字及编号所需的项目字体和字形，私有字体族隔离系统库。取消 Fandol/Liberation、GB2312 到新版、未知到宋体、Helvetica 到 Arial、Courier New 到 Consolas 等替换。缺字体或缺字符明确报错。
4. TTC 在内存中取出指定原字体成员，保留原始文件及字形；分页在字体加载完成后进行。中文无独立粗斜体时保留现有合成支持。
5. 删除备用文件及专属授权文件，更新资源说明、来源和校验清单。仅业务逻辑/类型/资源审计，不运行测试、构建或浏览器；结果提交后重启 bash deploy/run_dev.sh，保留无关用户改动。

实施审计补充：仓库论文和开题报告的 XML 中实际存在华文中宋、Courier New 与 Cambria 引用，因此补齐原字体，包含 Cambria Math 集合成员。原字体共 40 个文件，全部字节与固定 Git blob/SHA256 一致。段落标记和空白行也使用 XML 字体，避免系统字体影响行高；PAGE 字段更新保留私有字体。编号按 unicode-range 分配各脚本的原字体，预览销毁时释放临时编号字体。

检查范围：TypeScript no-emit、差异格式、字体元数据和源文件字节审计。未进行运行测试、前端构建或浏览器视觉验证。严格模式在 XML 字体配置缺失、原字体缺字、复杂结构无法对应或未支持的编号格式上明确报错；不保证浏览器排版与 Word 完全相同。
