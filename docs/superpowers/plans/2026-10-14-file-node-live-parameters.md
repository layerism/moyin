# 文件上传节点：共享配置与两类计算

状态：用户确认最新文件格式/大小边界后要求实施。采用现有 JSON 和策略表，不新增表、字段、索引或迁移。代码已完成；Python 语法、TypeScript 类型和差异检查通过，未运行测试或浏览器验证。

## 范围与行为

仅落实需求文档“二、文件上传节点”及其引用的架构原则；共享实现需按节点类型隔离，保持确认节点、答题卡等现有行为。

1. h：标题、说明、起止时间、参考文件、上传文件大小上限在点击完成后生效，无需重新发布；审核参数和模型继续使用现有策略存储。编辑期间不改变生效配置，取消关闭放弃未保存配置。参考文件上传与节点引用保存分开，保存时检查归属；下载读取生效引用。
2. v：发布后禁止新增、替换、删除文件模板，上传文件格式固定；审核步骤数量、类型、顺序和脚本固定。前端禁用及后端上传、删除、修订接口均校验，不能仅隐藏入口。
3. 条件计算：读取共享配置检查时间、前驱、权限和上传限制，正式提交再次验证；改变 h 不使既有通过结果失效、不重置下游。
4. f：正式提交创建新轮次，自动结果和教师正式审核推进当前轮次，最后一步通过自动完成。配置修改不取消在途任务；步骤开始执行或允许重试时读取当前 h，已开始执行的步骤保留实际使用参数，不自动重算。
5. 历史：文件节点重新提交不再删除旧提交、审核、反馈或材料；当前轮次查询、教师反馈草稿代次及拒绝状态按轮次隔离，防止旧结果干扰新提交。重试保留上次执行依据和结果，复用现有 audit_logs 记录执行历史。
6. 预览与正式运行采用相同处理规则，预览配置保持隔离。学生重新打开节点时刷新服务端数据，避免仅从旧页面状态读取配置。

## 复用存储方案（无数据库结构变更）

撤回新增 node_file_parameters 表方案。复用 flows.draft_config 现有 JSON 容器，以服务端专管的 publishedNodeParameters 区段保存已发布文件节点的生效参数和修改代次；该区段与 nodes 草稿定义分离，不直接把未发布草稿当作运行配置。

普通保存草稿必须从数据库保留该区段，忽略客户端对它的覆盖；仅独立参数保存接口能修改。发布、预览和复制时显式解析并移除该内部区段，再生成有效节点配置，不把内部运行配置元数据传播为节点结构。无该区段时回退发布配置，无须批量回填。

审核参数、模型继续复用 node_audit_policies / node_review_step_policies；审计使用 audit_logs。参考文件使用现有资源表与生效参数中的引用，下载校验生效引用及归属；保存与取消编辑不能误删当前生效或历史仍引用的资源。

仅教师保存配置时写入上述现有配置、策略和日志记录；不改写历史发布快照，不批量重置学生进度，不删除学生历史。不新增表、列、索引，不运行数据迁移。历史留存复用现有提交、审核、反馈表；旧版本已经删除的历史无法恢复。

本次依据用户对上述方案再次要求实施的授权，仅接入教师正常保存和学生运行时的数据写入；开发中不批量改写现有业务数据。如果发现需要额外数据库结构变更，再单独说明并等待授权。
