# 登录身份入口回跳修复计划

## 问题

在教师登录页点击“学生入口”时，页面可能短暂显示学生登录，随后又回到教师登录。

当前认证导航同时修改浏览器 URL 和 React 的 `screen`、`authRole` 状态；`history.pushState()` 不触发 `popstate`，而异步认证守卫可能继续依据旧 `screen` 执行教师端重定向，造成 URL 与页面状态竞争。

## 失败场景

1. 页面仍持有教师受保护页面的旧 `screen` 状态。
2. 用户点击“学生入口”，URL 被写为 `/login`。
3. 旧认证守卫依据教师 `screen` 将 URL 再写为 `/teacher/login`。
4. 用户看到学生登录闪现后退回教师登录。

## 修复

- 提取统一的路由状态应用函数，将 URL 解析结果同步到全部路由相关 React 状态。
- `popstate` 与身份入口导航复用同一同步函数。
- 认证守卫以当前 URL 解析出的路由为判断依据，不根据可能过期的 `screen` 重定向。
- 保持学生、教师登录 URL、认证 API、会话和教师邀请注册规则不变。

## 范围

- 修改 `frontend/src/App.tsx`。
- 不修改登录卡片样式、后端接口或数据库。

## 验证边界

按照项目约定，不运行测试、构建或浏览器自动化。仅审计以下状态链：

- `/teacher/login` 点击学生入口后稳定为 `/login` 与学生登录状态。
- `/login` 点击教师入口后稳定为 `/teacher/login` 与教师登录状态。
- 未登录访问教师受保护页面仍重定向 `/teacher/login`。
- 未登录访问学生受保护页面仍重定向 `/login`。

完成后重启本地服务，并核对 `8000`、`5173` 监听端口和工作目录。
