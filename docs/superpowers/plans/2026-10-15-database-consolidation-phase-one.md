# 第一批数据库表精简实施计划

用户已于 2026-10-15 明确要求提交检查点并实施审计文档第一批范围。本计划包含对应代码、数据库迁移及本地开发服务重启，不涉及第二批业务重构。

## 范围与数据映射

- 三张教师资源表统一为 `flow_assets`，用 `asset_kind` 区分 `template`、`content`、`announcement`；模板与参考材料继续共用模板资源类别。保留原资源 ID、流程/节点归属、OSS 对象键、元数据和上传限制。
- 三张版本资源关系表统一为 `flow_version_assets`；资源类别与资源使用组合外键关联，主模板采用部分唯一索引保持每版本每节点最多一个，图片与附件允许多个。
- 模板下载事件重建外键指向统一资源表，保留原事件及模板类别约束。历史快照和 JSON 内资源 ID 不改写。
- `node_form_parameters` 的记录迁入 `flows.draft_config.publishedNodeParameters`，保留参数、修改代次、修改人及时间；表单 API 保留，底层共用发布后参数仓储。
- `flow_node_runtime_configs` 中与原发布快照不同的截止时间，迁入上述节点参数区的按版本覆盖，保持版本作用域及更新信息。相同值无需重复保存；按版本覆盖先应用，正式流程共享参数后应用，预览不应用共享参数。
- 完成引用迁移后删除旧表，不保留旧表或兼容视图。发布快照及 hash、学生实例、节点状态、提交、个人延期与审核结果不由本次迁移改写。

## 实施顺序

1. 将审计文档提交为实施前检查点，排除用户已有审核脚本配置改动；本计划位于默认忽略目录，在完成检查点中单独归档。
2. 停止已确认属于当前项目的开发服务，避免热重载在代码修改中触发迁移；使用 SQLite 备份接口保存迁移前数据库。
3. 更新建表及幂等迁移；统一参数和资源仓储，逐一替换发布、预览、复制、下载、进度、导出、管理员管理与账号清理依赖。
4. 静态审计代码、SQL 引用、数据映射和外键；不运行测试、构建或浏览器验证。
5. 执行获授权的本地迁移，核对表数、资源/关联/下载事件映射及受保护表数据是否保持一致；异常时事务回滚，不忽略冲突。
6. 通过 `bash deploy/run_dev.sh` 重启，检查进程归属、端口和启动日志；清理项目生成的限定中间缓存；提交任务范围结果检查点。

## 回滚与边界

- 备份保存到本地忽略的 `backend/storage/backups/`，不提交数据或凭据。
- 若需回滚，先停止服务、回到实施前代码，再恢复备份。迁移后若已产生新业务数据，不直接覆盖，应先保存新库并另行制定增量回滚方案。
- 模板库、审核策略两表、节点草稿、返工关系、分组及独立任务队列不合并。
- 验证限定为业务逻辑审计、实际迁移的数据核对及服务启动观察，不能表述为测试或浏览器回归通过。
