# 重新发布交互修复计划

## 问题

1. 已发布流程进入修订后，如果尚无改动，主按钮仍显示“重新发布”，但点击行为实际是退出修订。
2. 重新发布前发现答题卡配置错误时，页面直接切换到答题卡节点，只给出笼统提示，用户无法判断为什么发布被阻止。
3. 后端返回的修订冲突或校验错误需要保留原始业务信息，不能统一覆盖成发布基准变化。

## 修改范围

- 没有修订内容时，主按钮显示“退出编辑”；只有存在待发布修改时显示“重新发布”。
- 将答题卡发布前校验整理为纯函数，返回节点与首个具体错误。
- 校验失败时保持当前节点和检查器不变，在顶部展示具体错误，并提供“前往修正”操作。
- 仅将真正的草稿哈希冲突转换为“发布基准已变化”，其他后端错误原样展示。
- 补充发布按钮、答题卡发布前校验与冲突分类测试。

## 验证边界

遵循项目规范，不运行测试、构建或浏览器检查；仅执行 TypeScript 语法解析、差异检查和业务逻辑审计，完成后本地重启前后端服务。
