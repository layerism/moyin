# 超级管理员数据库管理设计

## 目标

将现有教师账户“卢禹锟 / 04170”提升为 `super_admin`。超级管理员继承教师权限，并可从账户菜单进入独立数据库管理页面，浏览全部业务表并修改经过白名单约束的字段。

## 权限模型

- `student`：仅访问自己的流程实例和提交。
- `teacher`：设计、发布和管理教务流程。
- `super_admin`：继承教师权限，并访问 `/api/admin/*` 与 `/admin/database`。

角色存储在 `teacher_accounts.role`。后端会话解析返回角色；前端角色只控制展示，最终授权始终由后端完成。

## 数据库管理边界

- 展示所有业务表的 schema、记录数量和分页原始记录。
- `password_hash`、`token_hash` 始终脱敏，不能通过通用接口修改。
- 表名和列名只能来自服务端静态策略，所有值使用参数化 SQL。
- `audit_logs`、版本快照、提交快照和会话表默认只读。
- 账户、流程、运行状态、截止时间等维护字段允许修改。
- 每次修改前生成 SQLite 备份，并写入包含前后值的审计日志。

## 前端

超级管理员账户菜单显示身份和“数据库管理”入口。独立页面使用左侧表目录、中部数据表格和右侧记录编辑抽屉；支持分页、刷新、原始值查看和可编辑字段修改。

## 安全规则

- 普通教师和学生访问管理 API 返回 `403`。
- 不能通过请求体修改未授权字段或构造任意表名。
- 角色提升只在一次性数据库迁移中作用于当时已存在的 `04170` 账户；之后注册同工号不会自动成为管理员。
- 第一版不提供任意 SQL 控制台、通用删除或密码哈希编辑。
