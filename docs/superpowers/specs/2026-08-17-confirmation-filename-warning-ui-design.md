# 确认承诺文件名警告 UI 设计

## 问题

确认承诺节点当前把完整文件名错误直接渲染在 `.runtime-submit-control` 内。长文件名与“暂存”“提交节点”按钮共享底部横向区域，造成按钮错位、错误文字过长和视觉边界混乱。

普通文件节点已经使用统一的 `RuntimeWarningDialog` 展示文件校验失败。确认承诺节点应复用相同交互与视觉语言。

## 交互设计

- 文件名不合规时，底部操作区只显示“暂存”和“提交节点”，不再渲染长错误文案。
- “提交节点”保持可点击，以便用户主动触发文件名校验反馈。
- 用户点击提交后，前端先检查确认勾选，再检查扫描件文件名。
- 文件名不合规时，不调用提交 API，打开现有 `RuntimeWarningDialog`：
  - 分类：`文件校验`
  - 标题：`文件提交未通过`
  - 内容：沿用现有文件名错误信息，指出首个错误文件和模板主文件名要求。
  - 操作：`我知道了`
- 关闭警告后保留节点弹窗、扫描件列表和当前填写状态，用户可直接使用扫描件行内“替换”操作。
- 模板未下载、确认未勾选、扫描件上传中或没有扫描件等既有前置条件继续沿用当前阻断方式。

## 状态与组件边界

- `getScanSubmitBlocker()` 继续负责模板下载、确认、上传中和空扫描件等流程前置条件。
- 新增独立的纯函数负责返回文件名错误，使“按钮禁用条件”和“点击后弹窗反馈”不再共用一个长文本状态。
- `RuntimeNodeDialog` 在 `handleSubmit()` 中拦截文件名错误，并设置本地文件警告状态。
- `RuntimeWarningDialog` 支持根据来源显示“文件上传未通过”或“文件提交未通过”，不复制新的弹窗组件。
- 后端提交校验保持不变，仍为不可绕过的最终约束。

## 视觉约束

- 复用现有白色警告面板、红色警告图标、浅红信息区域、蓝色确认按钮及现有圆角和间距。
- 不在底部按钮容器新增边框、红框或大段说明。
- 不增加新动画或新的颜色体系。
- 桌面和窄屏均保持操作按钮布局稳定，长文件名只在警告弹窗的信息区域自动换行。

## 验收条件

1. 存在文件名错误时，底部不再显示长错误文案，按钮布局保持整齐。
2. 点击“提交节点”后显示统一文件校验弹窗，且不调用提交 API。
3. 弹窗明确显示错误文件名和模板名称要求。
4. 关闭弹窗不会关闭底层节点弹窗，也不会清空扫描件。
5. 文件名修正后可正常提交；后端文件名校验保持不变。
