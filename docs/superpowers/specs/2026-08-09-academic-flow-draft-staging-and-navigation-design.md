# 教务流程暂存与离开确认设计

## 1. 目标

为教务流程设计器增加服务器暂存能力，使教师可以在尚未发布的草稿流程或已发布流程的修订状态中主动保存当前编辑内容，离开后重新进入仍可继续编辑。同时，所有设计器内部离开入口在存在本地未暂存修改时，都应允许教师选择“暂存并离开”。

## 2. 当前状态与问题

当前系统已经具备以下基础能力：

- 后端 `PUT /api/workflows/{flow_id}/draft` 可以写入 `flows.draft_config`；
- 设计器以 `revisionDirty` 标记当前页面是否存在本地修改；
- “返回首页”“返回教务流程”、面包屑和打开学生页面已统一经过 `requestNavigation()`；
- 页面刷新或关闭时，`beforeunload` 会提示本地修改尚未保存；
- `UnsavedChangesDialog` 目前只支持继续编辑或放弃修改离开。

但现有教师流程响应对已发布流程刻意只返回当前已发布快照，并固定返回 `hasUnpublishedChanges: false`。因此，虽然后端能够写入修订草稿，重新进入设计器时仍无法恢复该草稿。当前 `revisionDirty` 也同时承担“本地未保存”和“存在未发布修订”两种语义，无法正确表达“已经暂存、尚未发布”的状态。

## 3. 核心状态模型

明确区分三种事实：

1. `published config`：当前学生和教师进度页面实际使用的不可变已发布快照；
2. `draft config`：教师服务器端已暂存、下一次发布将使用的可编辑草稿；
3. `local dirty`：当前浏览器页面相对于服务器端 `draft config` 新产生、尚未暂存的修改。

教师流程 API 响应增加 `draftConfig`，同时保留现有 `config` 语义：

- 未发布流程：`config` 与 `draftConfig` 均为当前草稿；
- 已发布流程：`config` 继续为当前已发布快照，`draftConfig` 为服务器端暂存修订。

`hasUnpublishedChanges` 表示已发布流程的 `draftConfig` 是否不同于当前已发布配置。比较时使用带现行运行时截止时间的发布配置与规范化草稿配置，避免截止时间独立存储造成错误差异。

学生实例、分享链接、教师进度和已发布版本继续只读取 `flow_versions`，不会看到暂存草稿。

## 4. 设计器初始化与状态恢复

前端 `AcademicProcess` 增加独立的 `draftConfig`，保留 `nodes`、`edges` 作为当前已发布或当前列表展示配置。

进入设计器时：

- `workingProcess.nodes/edges` 从 `draftConfig` 初始化；
- 已发布且 `hasUnpublishedChanges` 为真时，自动进入“修订中”编辑状态；
- 本地 `revisionDirty` 初始化为假，因为当前页面内容与服务器暂存草稿一致；
- 未发布流程同样从 `draftConfig` 恢复，不需要额外分支。

教师进度、学生链接和发布影响分析继续明确使用已发布快照或当前 `workingProcess` 的既有入口，不用 `draftConfig` 替换学生运行时数据。

## 5. 主动暂存

设计器顶部操作区在“学生名单”和发布按钮之间增加“暂存”按钮。

按钮规则：

- 编辑器未解锁时禁用；
- 没有本地未暂存修改时禁用；
- 保存过程中禁用并显示“暂存中”；
- 保存成功后显示非阻塞提示“流程已暂存”；
- 保存失败时保留页面内容和本地未暂存标记，并显示现有操作提示。

暂存成功后：

- 使用服务器响应更新父级流程缓存与设计器工作副本；
- `revisionDirty` 设为假；
- 已发布流程根据服务器返回的 `hasUnpublishedChanges` 继续显示“修订中”，发布按钮保持“重新发布”；
- 未发布流程保持“草稿”，可继续提交发布。

不增加定时自动保存，不在每次节点拖动或字段输入时发送请求。

## 6. 模板资产操作

上传和删除节点模板本身已经直接写入服务器草稿。为保持状态一致：

- 上传模板前继续先暂存当前其他本地修改；
- 模板上传或删除成功后，将返回的模板资产或空值合入工作副本，再调用统一暂存同步函数，以服务器响应更新 `draftConfig` 与 `hasUnpublishedChanges`；
- 成功完成服务器写入后不再把该模板操作标记为本地未暂存修改；
- 任一步骤失败时保留当前可恢复状态及本地未暂存标记，并显示现有错误提示。

这样离开提示只针对尚未写入服务器的修改，不会对已经成功上传或删除的模板重复询问。

## 7. 离开确认

当 `revisionDirty` 为真时，以下入口继续统一经过 `requestNavigation()`：

- 顶部“返回教务流程”；
- 顶部“返回首页”；
- 面包屑“教务流程”；
- 设计器内打开学生填写页面。

`UnsavedChangesDialog` 改为三个动作：

1. “继续编辑”：关闭弹窗，不保存、不跳转；
2. “不暂存并离开”：丢弃当前页面相对服务器草稿的新修改并跳转；
3. “暂存并离开”：调用同一暂存函数，成功后跳转，失败则保留弹窗和当前页面。

“暂存并离开”期间三个按钮均不可重复触发，并显示“暂存中”。已经暂存且没有新增本地修改时，导航直接执行，不弹窗。

浏览器关闭、刷新和地址栏跳转继续使用原生 `beforeunload`。浏览器安全模型不保证关闭过程中异步请求完成，因此不在该路径自动暂存。

## 8. 发布后的同步

首次发布或重新发布成功后：

- 新发布配置同时成为新的服务器草稿基线；
- `draftConfig` 与已发布 `config` 一致；
- `hasUnpublishedChanges` 和 `revisionDirty` 均为假；
- 设计器退出修订编辑状态。

发布失败或修订影响冲突时，不清除服务器草稿或本地未暂存修改。

## 10. 验收标准

1. 未发布草稿修改后可以主动暂存，退出并重新进入仍恢复暂存内容。
2. 已发布流程解锁编辑、修改并暂存后，重新进入自动恢复修订草稿并保持“修订中”。
3. 学生实例、分享链接和教师进度在重新发布前仍使用旧的已发布版本。
4. 存在本地未暂存修改时，从顶部按钮、面包屑或学生页面入口离开均出现三选项弹窗。
5. “暂存并离开”仅在保存成功后跳转；失败时不丢失当前编辑内容。
6. 已经暂存、没有新增修改时可以直接离开。
7. 模板上传或删除成功后不会错误提示仍有本地未暂存修改。
8. 首次发布或重新发布成功后，暂存草稿与发布版本一致，所有修改标记清除。

## 11. 验证边界

实施时更新既有测试断言和最小状态测试，但依据项目约定不运行自动化测试、构建或浏览器自动化。仅进行静态业务逻辑审计：

- 教师 API 是否同时返回且正确区分 `config` 与 `draftConfig`；
- `hasUnpublishedChanges` 是否比较规范化服务器草稿与当前发布配置；
- `revisionDirty` 是否只表示本地未暂存修改；
- 所有内部导航是否共用同一暂存逻辑；
- 发布、模板资产和暂存成功后是否同步父级缓存及工作副本；
- 学生运行时接口是否完全未改动。

完成静态审计后清理缓存，并以本地方式重启 FastAPI 与 Vite 服务，由用户手动验收。
