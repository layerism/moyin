# OA 流程永久删除设计

## 目标

将现有“从列表隐藏”的软删除改为不可逆的永久删除，同时通过强确认降低误操作风险。

## 交互

- 删除弹窗使用明确的危险操作视觉层级，并标注“永久删除，无法恢复”。
- 弹窗列出删除范围：流程配置、发布版本、分享链接、学生流程实例、节点草稿、提交记录和截止时间特例。
- 用户必须输入完整流程名称；输入不匹配时，“永久删除”按钮保持禁用。
- 提交期间锁定输入和按钮，失败时保留弹窗并显示错误信息。

## 数据处理

- `DELETE /api/workflows/{flow_id}` 在一个 SQLite 事务中执行。
- 按外键依赖顺序清理流程版本、运行配置、分享令牌、学生实例、节点实例、草稿、提交记录和截止时间特例，最后删除 `flows` 主记录。显式清理可兼容现有 SQLite 数据库中尚未配置级联删除的旧表。
- 在删除主记录前写入一条最小审计记录，只包含教师 ID、流程 ID、流程名称、原状态和删除时间；不保留学生填写内容。
- 不删除教师账户、学生账户及其登录会话。
- 对不存在或已删除的流程返回 `404`，避免把重复删除误报为成功。

## 验证

- 后端测试验证所有流程关联表清空、账户保留、审计记录保留和不存在流程返回 `404`。
- 前端构建检查验证类型和组件编译。
- 浏览器验证名称不匹配时按钮不可用，匹配后可删除且列表立即更新。
