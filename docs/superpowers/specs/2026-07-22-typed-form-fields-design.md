# 类型化表单字段设计

## 目标

将现有 OA“表单填写”节点从仅支持必填单行文本，扩展为一张可配置的结构化表单。教师可以配置单行文本、多行文本、单项选择和多项选择；学生可以暂存未完成内容，但正式提交必须通过前后端一致的字段校验。

本次扩展仍属于“表单填写”节点，不新增流程节点类型，不改变 DAG 开放、截止、审核、修订和下游失效规则。

## 业务边界

表单字段负责采集结构化或较短的文字信息：

- 单行文本：姓名、学号、联系电话等；
- 多行文本：申请理由、情况说明、总结等；
- 单项选择：多个选项中选择一项；
- 多项选择：多个选项中选择若干项。

正式承诺或协议确认继续使用“确认承诺”节点；附件材料继续使用“文件上传”节点；公告内容继续使用“通知公告”节点。

## 字段模型

新建或升级后的表单字段使用以下结构：

```ts
type FormFieldType = "text" | "textarea" | "radio" | "checkbox";

type FormFieldOption = {
  id: string;
  label: string;
};

type FormField = {
  id: string;
  label: string;
  type: FormFieldType;
  required: boolean;
  options?: FormFieldOption[];
  allowOther?: boolean;
  minLength?: number;
  maxLength?: number;
  minSelections?: number;
  maxSelections?: number;
};
```

字段 ID 和选项 ID 在创建时生成，后续修改标题、选项文字或顺序时保持不变。学生答案以字段 ID 和选项 ID 为关联依据，不使用可变标题作为新数据的键。

节点配置在兼容期内允许：

```ts
infoFields: Array<string | FormField>;
```

业务层在读取后立即归一化为 `FormField[]`，组件和校验函数不直接处理两套结构。

## 字段配置规则

### 通用规则

- 字段标题去除首尾空格后不能为空；
- 同一节点内字段 ID 不得重复；
- 同一节点内字段标题不得重复；
- 每个字段均可独立设置“必填”或“选填”；
- 已发布节点的字段类型、标题、选项和校验规则全部锁定；
- 发布后仍只允许修改节点标题、节点说明、起始时间和截止时间。

### 单行文本

- 只配置字段标题和必填状态；
- 不提供最少或最多字符设置；
- 提交值必须是字符串；
- 必填时，去除首尾空格后不得为空。

### 多行文本

- 使用较大的多行输入区域；
- 可分别设置最少字符数和最多字符数，未设置表示不限制；
- 限制值必须是非负整数；
- 同时设置时，最少字符数不得大于最多字符数；
- 必填字段不得提交空白文本；
- 选填字段留空时不执行字符数限制，填写后执行；
- 字符数按去除首尾空格后的 Unicode 字符数量计算，换行计为一个字符。

### 单项选择

- 至少配置两个标题非空的普通选项；
- 同一字段内选项 ID 和去除首尾空格后的选项标题不得重复；
- 可启用“其他”选项；
- 必填时必须选择一个有效选项；
- 选择“其他”时，补充内容去除首尾空格后不得为空；
- 未选择“其他”时不保存残留的补充内容。

### 多项选择

- 至少配置两个标题非空的普通选项；
- 可启用“其他”选项；
- 可配置最少选择数和最多选择数，未设置表示不施加对应限制；
- 限制值必须是非负整数，最少选择数不得大于最多选择数；
- 最多选择数不得超过普通选项与“其他”选项的总数；
- 必填字段的有效最少选择数至少为一；
- 选填字段完全留空时允许提交；一旦选择内容，必须满足已配置的最少和最多选择数；
- 提交的选项 ID 必须唯一且全部属于当前字段；
- “其他”计为一个选择，选中后补充内容必须填写。

## 教师端交互

“采集用户信息”区域由简单输入行调整为字段配置卡片：

1. 点击“添加字段”；
2. 选择单行文本、多行文本、单项选择或多项选择；
3. 填写字段标题并设置必填状态；
4. 按字段类型显示对应的附加配置；
5. 在字段卡片内完成选项添加、删除和排序；
6. 保存节点设置，发布时执行完整配置校验。

多行文本卡片显示最少、最多字符设置；单选和多选卡片显示选项编辑器及“允许其他内容”开关；多选卡片额外显示最少、最多选择数。

字段配置错误应显示在对应卡片内，并阻止流程发布。节点设置的普通页面内修改仍只保存到当前前端状态，提交发布后才写入流程版本。

## 学生端交互

- 单行文本渲染为普通输入框；
- 多行文本渲染为较高的文本区域，并显示当前字符数和最大字符数；
- 单项选择渲染为纵向单选按钮组；
- 多项选择渲染为纵向复选框组，并显示选择数量要求；
- 选择“其他”后，在该选项下方展开补充输入框；
- 首次打开表单时不主动显示错误；字段失焦或点击提交后显示字段级错误；
- 点击提交时定位并聚焦第一个错误字段；
- 暂存不因内容缺失或数量不足而被阻止；
- 正式提交只有在全部字段通过校验后才发出请求；
- 后端拒绝时，错误继续显示在对应字段下方，并保留当前填写内容。

已通过节点继续使用现有只读模式。只读内容按字段标题和选项标题展示，不显示字段 ID、选项 ID或原始 JSON。

## 提交数据

新字段的表单答案使用字段 ID 作为键：

```json
{
  "field-text-id": "张三",
  "field-textarea-id": "较长的申请理由",
  "field-radio-id": {
    "selectedOptionId": "option-a",
    "otherText": null
  },
  "field-checkbox-id": {
    "selectedOptionIds": ["option-a", "option-b"],
    "otherText": null
  }
}
```

选择“其他”时使用保留选择值 `other`，并在同一字段答案中保存 `otherText`。普通选项 ID 不得使用该保留值。

后端在暂存和提交前按当前节点配置规范化答案：

- 只保留当前配置中存在的字段；
- 文本值保持原内容，但使用去除首尾空格后的内容执行校验；
- 单选只保留一个有效选择；
- 多选去重后按字段选项顺序保存；
- 未选择“其他”时移除 `otherText`；
- 不保存客户端附加的未知字段或未知选项。

## 校验与错误响应

发布流程时，后端必须校验字段配置，不能依赖教师端 UI。配置非法时拒绝发布，并返回可定位到节点和字段的中文错误信息。

学生正式提交时，前端和后端执行相同的必填、字符数量、选项范围、选择数量和“其他”补充内容校验。后端是最终可信边界。

字段校验失败时，提交接口返回结构化错误：

```json
{
  "detail": {
    "message": "表单内容未通过校验",
    "fieldErrors": {
      "field-textarea-id": "至少填写 200 个字符",
      "field-checkbox-id": "请选择 2 至 4 项"
    }
  }
}
```

节点未开放、已经截止、名单无权限等运行态错误继续使用现有错误语义，不混入字段错误结构。

## 历史兼容

本次不批量改写数据库，也不改变历史流程版本和历史提交快照。

- 旧 `infoFields: string[]` 在运行时按“必填单行文本”解释；
- 旧字段答案继续按字段标题读取；
- 旧版已发布流程继续按原配置填写、提交和只读展示；
- 可编辑的旧草稿在首次保存新配置时转换为对象字段，并一次性生成稳定字段 ID；
- 转换后不再退回字符串字段；
- 旧数据若已经存在重复字段标题，继续维持原有读取语义，不尝试猜测或拆分历史答案；新流程发布时禁止重复标题。

兼容逻辑集中在单一归一化函数中，避免教师端、学生端和后端校验分别实现不同的旧格式判断。

## 发布与修订

字段配置属于节点核心业务结构。流程首次发布后，不允许修改：

- 字段数量、顺序和标题；
- 字段类型和必填状态；
- 选项、“其他”开关；
- 字符限制和选择数量限制。

发布后仍只允许修改节点标题、节点说明、起始时间和截止时间，沿用现有节点及下游重新完成规则。由于字段配置不可修订，本次不新增字段结构变化导致的历史提交迁移逻辑。

## 安全与一致性

- 字段规则必须从已发布流程版本读取，不接受客户端上传字段定义；
- 学生只能暂存和提交自己有权访问的节点；
- 未知字段和未知选项不得进入提交快照；
- 前端禁用按钮或隐藏字段不能替代后端校验；
- 只读展示必须使用提交所属流程版本的字段定义，不能使用当前草稿配置；
- 字段 ID、选项 ID和保留值必须在发布时检查唯一性。

## 验收标准

1. 教师可以新增单行文本、多行文本、单项选择和多项选择字段。
2. 每个字段可以独立设置必填或选填。
3. 多行文本可以设置最少和最多字符数，并显示字符计数。
4. 单选和多选可以维护至少两个普通选项，并可启用“其他”。
5. 多选可以设置最少和最多选择数。
6. 学生选择“其他”后必须填写补充内容。
7. 暂存允许不完整答案，正式提交拒绝不合规答案。
8. 前端提供字段级提示，后端不能被绕过。
9. 提交快照不包含未知字段、未知选项或未选中的“其他”内容。
10. 已提交内容按字段和选项标题只读展示，不显示 JSON。
11. 旧字符串字段流程无需数据库迁移即可继续使用。
12. 已发布节点不能修改字段结构和校验规则。
13. 字段标题调整或排序不会使新格式答案错位。

## 预计改动范围

- `frontend/src/types.ts`：新增表单字段与选项类型，并兼容旧字段配置；
- `frontend/src/features/academic-flow/academicFlowData.ts`：创建默认字段配置和旧字段归一化；
- `frontend/src/features/academic-flow/AcademicFlowDesigner.tsx`：教师字段卡片、选项编辑器和发布前提示；
- `frontend/src/features/academic-flow/StudentRuntimePage.tsx`：类型化字段渲染、即时校验、提交和只读展示；
- `frontend/src/features/academic-flow/api.ts`：识别结构化字段错误响应；
- `frontend/src/styles.css`：教师配置卡片、选项列表和学生字段状态样式；
- `backend/app/domain/workflow.py`：发布配置校验；
- `backend/app/domain/workflow_runtime.py`：字段归一化、答案规范化和提交校验；
- `backend/app/repositories/flow_instances.py`：暂存和提交前使用规范化结果；
- `backend/app/api/routes/student_flows.py`：返回结构化字段错误。

实施阶段可根据现有模块边界将纯函数放入更小的同目录文件，但不引入新的表单库或校验依赖。

## 非目标

- 不增加数字、日期、邮箱、手机号、身份证或正则表达式字段类型；
- 不增加富文本或 Markdown 编辑器；
- 不增加条件显示、字段联动、分页表单或计算字段；
- 不允许学生动态增加选项；
- 不改变文件上传、确认承诺和通知公告节点；
- 不改变 DAG 开放、截止、延期、审核和重新发布状态机；
- 不运行数据库批量迁移；
- 不引入第三方表单构建器或校验框架。

## 验证边界

按照当前项目开发约定，实施期间只做业务逻辑与静态代码审计，不运行自动化测试、构建或浏览器测试。完成实现后以本地非 Docker 方式重启前后端，由用户手动验证教师配置、学生暂存、提交校验和只读展示。
