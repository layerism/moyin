# OA 节点修订时间窗口与文件模板设计

## 1. 目标

本次设计增加两项相互关联的节点能力：

1. 教师修订已发布 OA 时，旧节点只允许修改描述、起始时间和截止时间；任一允许字段变化后，该节点及所有可达下游节点必须由学生重新按照 DAG 完成。
2. 教师可在首次发布前为文件节点上传可选模板至 OSS；学生必须先点击下载当前节点模板，之后才能上传填写后的文件。

本设计沿用现有流程版本快照、DAG 迁移、学生名单鉴权、学生文件 OSS 存储和审核脚本，不引入独立模板管理后台。

## 2. 已确认的业务规则

### 2.1 已发布节点修订白名单

已发布旧节点只允许修改：

- `requirement`：节点描述；
- `startAt`：统一起始时间；
- `deadlineAt`：统一截止时间。

下列内容均不可修改：

- 节点标题、类型和位置；
- 表单采集字段；
- 文件扩展名和大小限制；
- 审核脚本及参数；
- 文件模板；
- 其他节点业务字段。

前端以只读控件和锁图标表达限制，后端在保存草稿、预览修订影响和发布三个边界重复校验。任何非白名单差异均返回 `409`，不能只依赖 UI 禁用状态。

### 2.2 DAG 结构修订

- 已发布旧节点不可移动或删除。
- 已发布旧连线不可删除、改向或替换。
- 修订期间可以新增节点；新增节点可以完整配置。
- 可以增加连接新节点的连线，但每条新增连线必须至少连接一个新增节点。
- 不能仅在两个已发布旧节点之间增加新连线。

### 2.3 修订影响

只要旧节点的描述、起始时间或截止时间发生变化，该节点即计入 `changedNodeIds`。设变化节点集合为 \(C\)，需要失效的节点集合为：

$$
I=\operatorname{ReachableSuccessors}(G,C)
$$

集合 \(I\) 包括变化节点自身。对每个学生：

- 删除这些节点的草稿、提交和审核任务；
- 删除节点级个别延期；
- 删除模板下载记录；
- 重建节点实例并按新 DAG、起始时间和截止时间计算状态；
- 不在 \(I\) 中的节点继续保留原状态。

### 2.4 时间字段

起始时间和截止时间均可为空：

- `startAt = null`：前置节点全部通过后立即开放；
- `deadlineAt = null`：节点不自动过期；
- 两者都有值：必须满足 `startAt < deadlineAt`。

统一起始时间和截止时间只允许通过版本修订修改。现有“填写进度”中的统一截止时间修改入口移除；针对单个学生的延期功能继续保留，个别延期只覆盖该学生的截止时间。

### 2.5 文件模板

- 模板为文件节点的可选配置，未上传模板也可发布。
- 每个文件节点最多配置一个模板。
- 模板扩展名和大小必须满足该节点的学生上传限制。
- 首次发布前，或修订中新建节点发布前，教师可以上传、替换或删除模板。
- 已发布旧节点无论是否已有模板，都不能新增、替换或删除模板。
- 学生端模板下载使用独立按钮，点击后直接下载，不提供在线预览或 OSS 页面跳转。
- 配置模板的节点必须先产生有效下载记录，之后才允许学生上传。
- 未配置模板的文件节点维持现有直接上传流程。

### 2.6 模板下载记录生命周期

- 节点首次填写前必须下载当前模板。
- 节点因流程修订失效并重建时，旧下载记录随旧节点实例删除，学生必须重新下载。
- 仅因审核不通过而重新提交时，节点实例和下载记录保留，不要求重复下载。
- 重复上传或更换学生文件不要求再次下载。
- 通用运行时只强制下载流程，不推断上传文件是否由模板派生；内容级结构校验继续交给节点审核脚本。

## 3. 方案选择

采用“版本固化的模板资产”方案：模板由后端管理并存储在 OSS，发布版本建立不可变模板引用，学生通过后端鉴权获取短期签名下载地址。

不采用以下方案：

- 将 OSS 对象信息仅写入节点 JSON：不利于对象归属、删除保护和下载审计。
- 保存教师填写的 OSS 链接：签名链接会过期，公开链接存在泄漏风险，且无法可靠验证版本归属。

## 4. 节点配置契约

`AcademicFlowNode` 增加：

```ts
type NodeTemplateAsset = {
  assetId: string;
  contentType: string;
  originalName: string;
  sha256: string;
  sizeBytes: number;
};

type AcademicFlowNode = {
  // existing fields
  startAt?: string | null;
  deadlineAt?: string | null;
  templateAsset?: NodeTemplateAsset | null;
};
```

约束：

- 非文件节点的 `templateAsset` 必须为空。
- `templateAsset` 中不包含 OSS 对象键和签名 URL。
- 发布时整个节点配置继续写入 `flow_versions.config_snapshot`。
- 后端使用关系表再次固化流程版本与模板资产的关系，不以客户端 JSON 作为资产归属依据。

## 5. 数据库设计

### 5.1 `flow_template_assets`

保存教师上传的不可变模板资产：

| 字段 | 类型 | 约束与含义 |
|---|---|---|
| `id` | TEXT | 主键，UUID |
| `flow_id` | TEXT | 外键，所属 OA |
| `node_key` | TEXT | 稳定节点 ID |
| `storage_key` | TEXT | 唯一，OSS 对象键 |
| `original_name` | TEXT | 原始文件名 |
| `content_type` | TEXT | MIME 类型 |
| `size_bytes` | INTEGER | 非负 |
| `sha256` | TEXT | 文件摘要 |
| `etag` | TEXT | OSS ETag |
| `created_by` | INTEGER | 上传教师账号 |
| `created_at` | TEXT | UTC 时间 |

资产记录不可原地修改。替换模板时先上传并创建新资产，再切换草稿引用。只有未被任何已发布版本引用的旧资产才允许删除。

### 5.2 `flow_version_templates`

固化发布版本与模板资产：

| 字段 | 类型 | 约束与含义 |
|---|---|---|
| `flow_version_id` | TEXT | 外键，级联删除 |
| `node_key` | TEXT | 节点 ID |
| `template_asset_id` | TEXT | 外键，限制删除 |

主键为 `(flow_version_id, node_key)`。发布时只为配置了模板的文件节点写入记录。

### 5.3 `template_download_events`

记录学生已完成模板下载动作：

| 字段 | 类型 | 约束与含义 |
|---|---|---|
| `node_instance_id` | TEXT | 外键，节点实例删除时级联删除 |
| `template_asset_id` | TEXT | 外键，当前模板 |
| `student_account_id` | INTEGER | 外键，学生账号 |
| `downloaded_at` | TEXT | 最近成功请求下载的 UTC 时间 |

主键为 `(node_instance_id, template_asset_id)`。重复点击下载更新 `downloaded_at`。

## 6. 教师模板上传事务

教师上传前，前端先保存当前节点草稿，使后端能够从服务端草稿读取节点类型、扩展名和大小限制。

上传流程：

```text
校验教师与 OA 归属
-> 校验节点存在且为文件节点
-> 校验节点是否允许编辑模板
-> 校验文件名、扩展名和大小
-> 上传新对象到 OSS
-> 创建不可变资产记录
-> 原子更新 flows.draft_config 中的 templateAsset
-> 返回更新后的节点模板元数据
```

替换失败时保留旧模板引用。替换成功后，旧资产若未被任何版本引用，可执行 OSS 和元数据清理；清理失败不回滚已经成功的新模板切换，但保留错误日志供后续处理。

## 7. 发布时间与模板校验

发布前执行：

1. 校验 DAG 和节点时间区间。
2. 校验所有模板资产属于当前 OA 和节点。
3. 再次校验模板扩展名和大小符合节点限制。
4. 对所有历史已发布节点执行字段白名单比较。
5. 校验所有历史连线仍存在且方向不变。
6. 校验新增连线至少连接一个新增节点。
7. 计算修订影响并迁移学生实例。
8. 写入 `flow_versions` 和 `flow_version_templates`。

当前已有运行时统一截止时间覆盖的历史版本需要兼容：

- 教师第一次进入新修订时，以当前有效统一截止时间作为该节点的修订基线；
- 如果教师未改变该时间，不计为节点变化；
- 新版本发布后，统一截止时间完全来自节点 `deadlineAt`；
- 不再创建新的运行时统一截止时间覆盖。

## 8. 节点运行状态

新增运行状态 `scheduled`，表示前置条件已满足但尚未到起始时间。

对尚未提交的节点，状态优先级为：

```text
前置节点未全部通过 -> locked
前置节点已通过且截止时间已过 -> expired
前置节点已通过且起始时间未到 -> scheduled
前置节点已通过且处于开放窗口 -> available
```

审核中、已通过等提交后状态继续沿用现有逻辑；截止时间到达不会撤销截止前已经提交并进入审核的材料。

后端在以下入口重新计算并校验状态：

- 获取流程实例；
- 保存草稿；
- 下载模板；
- 上传学生文件；
- 提交节点；
- 重试审核。

运行时响应增加：

```ts
type RuntimeNodeInstance = {
  // existing fields
  effectiveStartAt: string | null;
  effectiveDeadline: string | null;
  template: {
    assetId: string;
    contentType: string;
    originalName: string;
    sizeBytes: number;
  } | null;
  templateDownloaded: boolean;
};
```

## 9. API 设计

### 9.1 教师模板

- `POST /api/workflows/{flow_id}/nodes/{node_key}/template`
  - `multipart/form-data` 上传一个模板。
  - 返回模板元数据和更新后的草稿哈希。
- `DELETE /api/workflows/{flow_id}/nodes/{node_key}/template`
  - 删除当前可编辑草稿模板。
  - 已发布旧节点返回 `409`。

### 9.2 学生模板下载

- `POST /api/student/node-instances/{node_instance_id}/template/download`
  - 校验学生、名单、当前流程版本、节点状态和模板资产。
  - 写入或更新下载事件。
  - 返回 `{ url, originalName, sizeBytes }`，其中 `url` 为短期签名地址。

### 9.3 时间管理

- 移除前端对 `PATCH /api/workflow-admin/versions/{version_id}/nodes/{node_key}/deadline` 的调用和统一截止时间 UI。
- 后端不再通过该接口产生新的统一截止时间覆盖；个别学生延期接口保持不变。

## 10. 教师 UI

### 10.1 开放时间窗口

节点设置中使用独立的厚重卡片：

- 深灰蓝标题栏、2px 边框、明显阴影和圆角；
- 左侧时钟图标，右侧状态徽标；
- 起始时间和截止时间为两个实体区块，中间使用粗时间轴连接；
- 显示大号日期、时间和清除按钮；
- 底部显示开放时长或时间校验错误；
- 移动端改为上下排列。

状态徽标包括“未设置”“定时开放”“开放中”“已截止”。

### 10.2 修订锁定

修订已发布旧节点时：

- 描述和时间卡片可编辑；
- 其他控件仍可见但禁用，显示锁图标和“已发布节点不可修改”；
- 模板区域显示已固化文件信息，不能操作；
- 历史节点没有模板时显示“该节点发布时未配置模板，修订中不可新增”。

新增节点保持完整编辑能力。

### 10.3 模板资产卡

- 未上传：显示拖拽或选择文件区域。
- 已上传：显示文件名、扩展名、大小和上传时间。
- 可编辑阶段提供“替换模板”和“删除模板”。
- 文件不符合节点限制时在上传前提示并阻止。

## 11. 学生 UI

### 11.1 时间状态

- `locked`：展示前置条件未完成。
- `scheduled`：展示开放时间和倒计时，不显示可写操作。
- 页面只为最近一个未来起始时间设置定时刷新；到点后重新请求实例。
- `expired`：展示截止信息，不允许继续写入。

### 11.2 模板与上传步骤

配置模板的文件节点显示：

1. 高对比度“下载填写模板”按钮，以及模板文件名和大小；
2. “上传已填写文件”区域。

下载 API 成功并触发浏览器下载后，上传区域解锁。下载失败时不解锁。未配置模板的节点不显示步骤编号，直接使用现有上传区域。

## 12. 错误处理与安全

- OSS 未配置：`503`，提示“模板存储服务未配置，请联系管理员”。
- OSS 上传或签名失败：`502`。
- 节点或模板不存在：`404`。
- 已发布节点尝试修改锁定字段或模板：`409`。
- 未下载模板直接上传：`409`，提示“请先下载当前节点模板”。
- 节点未开放或已截止：`409` 或现有时间错误状态，拒绝下载和写操作。
- 文件格式、大小或时间区间无效：`422`。
- OSS 对象键、密钥和数据库路径不返回前端。
- 下载地址沿用系统短期签名有效期和 `Content-Disposition` 文件名。
- 所有模板上传、替换、删除和学生下载均记录审计信息。

## 13. 历史兼容

- 缺少 `startAt` 的旧节点按 `null` 处理。
- 缺少模板的旧文件节点按“无模板”处理。
- 旧节点在修订中不能借机补传模板。
- 旧流程版本、旧提交、学生已上传文件和审核记录不做破坏性迁移。
- 只有因新修订分析进入失效集合的节点才按现有迁移规则重建。

## 14. 验收标准

1. 节点只有在前置节点全部通过且达到起始时间后才开放。
2. 学生页面保持打开时，到达起始时间后自动刷新并开放。
3. 描述、起始时间或截止时间任一变化，节点及全部下游重新完成。
4. 旧节点的其他字段、位置、模板和旧连线均无法通过 UI 或 API 修改。
5. 新节点可以完整配置并连接到现有 DAG。
6. 新文件节点可以不上传模板直接发布。
7. 新文件节点发布前可以上传、替换和删除符合限制的模板。
8. 配置模板的节点，学生未下载不能上传，下载后可以上传。
9. 修订失效后必须重新下载；审核驳回后不要求重新下载。
10. 无模板文件节点维持现有上传、提交和审核流程。
11. 个别学生延期继续有效，不影响其他学生。
12. 历史流程和历史提交保持可访问。

## 15. 验证约束

遵循仓库规则，实施阶段不运行自动化测试、构建、浏览器或 Playwright。只执行静态业务审计、差异范围检查、缓存清理和本地服务重启，由用户按验收标准手动验证。
