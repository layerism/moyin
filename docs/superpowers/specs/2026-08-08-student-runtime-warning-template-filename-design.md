# 学生运行时警告弹窗与模板文件名兼容设计

## 1. 目标

本次修改解决两个相互关联的学生端文件节点问题：

1. 节点操作失败目前显示为页面顶部红色文字，容易被忽略；应改为与现有文件上传警告一致的确认式弹窗。
2. 已绑定模板的文件节点目前要求学生文件名与模板完全相同；应允许学生在模板主名后追加任意后缀，同时保留 `.docx` 格式。

本次不增加数据库字段，不引入第三方 UI 组件，不追溯修改历史上传文件。

## 2. 文件名规则

### 2.1 形式化定义

设教师模板文件名为：

```text
<template_stem>.docx
```

学生允许上传的文件名为：

```text
<template_stem><optional_suffix>.docx
```

其中：

- `<template_stem>` 必须与模板主名完整一致，并位于学生文件名最前方；
- `<optional_suffix>` 可以是任意字符串，也可以为空；
- 最终扩展名必须为 `.docx`，扩展名比较忽略大小写；
- 模板主名比较保持大小写敏感；
- 比较前清除客户端伪造路径、去除文件名前后空白并执行 Unicode NFC 规范化。

### 2.2 示例

模板为 `个人承诺书.docx` 时：

| 学生文件名 | 结果 | 原因 |
| --- | --- | --- |
| `个人承诺书.docx` | 允许 | 后缀为空 |
| `个人承诺书-张三.docx` | 允许 | 模板主名后追加后缀 |
| `个人承诺书_2020208764417.DOCX` | 允许 | 扩展名忽略大小写 |
| `张三-个人承诺书.docx` | 拒绝 | 模板主名不在开头 |
| `个人承诺.docx` | 拒绝 | 模板主名不完整 |
| `个人承诺书-张三.pdf` | 拒绝 | 扩展名不是 `.docx` |

### 2.3 成功后的权威文件名

上传成功后保留学生实际文件名。例如学生上传 `个人承诺书-张三.docx`，则以下链路均使用该名称：

- OSS 对象键中的可读文件名部分；
- `uploaded_files.original_name`；
- 学生草稿和提交快照；
- 审核脚本输入；
- 后续下载与只读展示。

不再把成功文件名改写为模板原名，否则学生追加的识别后缀会丢失。

## 3. 后端数据流

现有 `validate_template_filename(uploaded_filename, template_filename)` 继续作为共享校验入口，但比较语义由“完全相同”改为“模板主名前缀匹配”。

```text
学生选择文件
  -> 后端取得节点及模板权威元数据
  -> 清理并规范化模板文件名与学生文件名
  -> 检查模板扩展名和学生扩展名均为 .docx
  -> 检查学生主名是否以完整模板主名开头
  -> 失败：返回 422，终止上传
  -> 成功：沿用学生实际文件名执行大小、类型和权限校验
  -> 计算哈希并写入 OSS
  -> 使用学生实际文件名保存上传记录和草稿
```

名称校验必须位于完整文件读取、哈希计算及 OSS 写入之前。校验失败时不得：

- 写入新 OSS 对象；
- 新增或更新 `uploaded_files`；
- 删除或覆盖此前尚未提交的文件；
- 修改草稿、节点状态或审核状态。

无模板节点继续使用现有文件名逻辑。异常模板元数据继续按服务端配置错误处理，不降级为无模板上传。

## 4. 前端警告弹窗

### 4.1 组件边界

在 `StudentRuntimePage.tsx` 内提取轻量的 `RuntimeWarningDialog`，复用现有上传警告的结构和 CSS，不新增依赖或独立组件目录。

该组件接收：

- 警告分类文案；
- 标题；
- 错误消息；
- 关闭回调。

现有节点局部 `uploadWarning` 与新增页面级 `actionWarning` 共用该组件：

- `uploadWarning`：文件选择或上传阶段失败，标题为“文件上传未通过”；
- `actionWarning`：暂存、提交、重新审核或模板下载失败，标题为“操作未完成”。

### 4.2 交互规则

- 使用 `role="alertdialog"`、`aria-modal="true"` 及关联标题和消息；
- 使用项目既有白色面板、灰色边框、红色警告语义、蓝色主按钮和圆角；
- 弹窗只能通过“我知道了”按钮关闭，点击遮罩不关闭；
- 弹窗关闭后返回原操作位置，底层节点窗口保持打开；
- 错误不得清空草稿、已上传文件或表单输入；
- 上传错误仍由节点局部状态管理，避免关闭底层文件节点窗口；
- 成功、处理中以及审核状态自动刷新失败继续使用非阻塞页内提示；
- 初次流程加载失败继续显示在加载区域，因为流程主体尚未建立。

## 5. 错误文案

文件名校验失败时返回：

```text
文件名必须以“<模板主名>”开头，并使用 .docx 格式。
```

该文案表达必要条件，不要求用户将文件重命名为唯一固定名称。

后端原始错误消息继续由前端弹窗展示，不通过中文字符串猜测错误类型。前端在各操作的 `catch` 分支显式写入 `actionWarning`，成功分支继续写入原有 `notice`。

## 6. 兼容性与安全边界

- 不修改数据库结构或 API 响应模型。
- 不追溯校验、重命名或迁移历史上传文件。
- 文件名规则只能减少普通误传，不能证明文件内容来自教师模板。
- 现有文件大小、节点扩展名限制、名单授权、开放时间、模板下载记录和审核逻辑保持不变。
- 不增加内容指纹、文档结构比对或自动重命名功能。

## 7. 验收标准

1. 模板原名可以上传。
2. 模板主名后追加任意后缀且以 `.docx` 结尾时可以上传。
3. 模板主名不在开头、主名不完整或扩展名不是 `.docx` 时，在 OSS 写入前拒绝。
4. 上传成功后，草稿、提交记录、审核输入和展示均保留学生实际文件名。
5. “文件不存在、已提交或不属于当前节点”等提交错误使用项目风格警告弹窗展示。
6. 暂存、提交、重新审核和模板下载失败使用操作警告弹窗；成功与进度信息保持非阻塞。
7. 警告弹窗关闭后节点窗口和用户已填写内容保持不变。
8. 无模板节点、历史文件和其他流程状态逻辑不受影响。

## 8. 验证边界

按项目约定，本次开发不运行自动化测试、构建或浏览器测试。实施完成后进行静态业务审计，包括：

- 文件名规范化、前缀比较和 `.docx` 扩展名判断；
- 名称校验位于文件读取与 OSS 写入之前；
- 成功链路保留学生实际文件名；
- 所有指定失败分支进入警告弹窗；
- 成功和进度分支仍使用页内提示；
- 无无关数据库、API 或 UI 改动。

完成静态审计后重启本地 FastAPI 与 Vite 服务，交由用户手动验收。
