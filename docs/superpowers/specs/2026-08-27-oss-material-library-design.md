# OSS 学生材料库设计

> 状态：方案已确认，等待设计文档最终审阅。本文定义教师侧 OSS 云盘的真实数据来源、只读目录交互和权限边界。

## 1. 目标

教师点击“OSS 云盘”后，不再进入模拟文件管理页，而是查看本人当前已发布流程产生的学生文件。材料按“流程 → 节点 → 学生 → 文件”组织，支持逐层浏览、当前层搜索和单文件下载。

该页面是流程提交记录的只读归档视图，不允许新建、上传、重命名、移动或删除文件。侧栏保留“+ 新建”和“上传”的既有视觉入口，但两个按钮不绑定事件，不触发弹窗、接口或状态变化。

## 2. 数据范围

目录只展示同时满足以下条件的文件：

1. 流程属于当前登录教师，且 `flows.status = 'published'`。
2. 文件关联的版本是该流程当前 `status = 'published'` 的 `flow_versions` 版本。
3. 节点来自该发布版本的不可变 `config_snapshot`，并且是文件节点，或需要上传扫描件的确认节点。
4. 学生在该流程的 `flow_roster_entries` 中仍为 `active`，且姓名、学号对应正式学生账号。
5. 文件已关联正式 `submissions` 记录，不包含尚未提交的临时上传文件。
6. 提交属于节点当前 `attempt_no`，状态为 `reviewing`、`approved`、`rejected` 或 `audit_error`。

不展示被新尝试替代、流程修订失效、已取消或仅暂存的历史文件。流程和会产生文件的节点即使暂时没有文件也保留；没有有效文件的学生不生成目录。

超级管理员沿用当前教师资源归属规则，只查看自己拥有的流程，不获得跨教师浏览能力。

## 3. 后端设计

### 3.1 目录接口

新增教师接口：

```text
GET /api/workflow-admin/material-library
```

响应只包含目录展示所需的业务标识和文件元数据，不包含 OSS `storage_key`：

```json
{
  "flows": [
    {
      "flowId": "flow-1",
      "versionId": "version-3",
      "name": "毕业材料收集",
      "nodes": [
        {
          "nodeKey": "node-2",
          "title": "提交申请表",
          "students": [
            {
              "rosterEntryId": 18,
              "studentNo": "20240001",
              "name": "张三",
              "files": [
                {
                  "fileId": "file-1",
                  "originalName": "申请表.docx",
                  "contentType": "application/vnd.openxmlformats-officedocument.wordprocessingml.document",
                  "sizeBytes": 28672,
                  "createdAt": "2026-08-27T10:20:00Z",
                  "submittedAt": "2026-08-27T10:22:00Z",
                  "submissionStatus": "approved"
                }
              ]
            }
          ]
        }
      ]
    }
  ]
}
```

流程按现有流程列表顺序返回；节点严格按发布快照中的节点顺序返回；学生按学号排序，并使用有效名单记录 ID 作为稳定标识；同一学生的文件按 `display_order`、创建时间和文件 ID 排序。页面中的“提交时间”使用 `submissions.submitted_at`，不以文件上传时间代替。

目录查询放在 `backend/app/repositories/teacher_materials.py`，复用现有材料节点判定和有效提交状态常量。查询使用当前发布版本和有效名单作为授权与数据边界，不从 `flow_instances` 反推名单授权。

### 3.2 单文件下载接口

新增教师接口：

```text
GET /api/workflow-admin/material-library/files/{file_id}/download
```

仓储层按照目录接口的全部条件重新校验文件当前仍然可见。校验通过后，路由层调用对象存储服务生成短期签名地址，返回：

```json
{
  "fileId": "file-1",
  "originalName": "申请表.docx",
  "url": "https://signed-download-url"
}
```

文件不存在、已失效或不属于当前教师时统一返回 404，避免泄露资源是否存在。OSS 未配置返回 503，签名生成失败返回 503。

## 4. 前端设计

### 4.1 页面结构

保留 `/` 作为 OSS 云盘页面地址。侧栏显示“+ 新建”“上传”、“教务流程”和选中的“OSS 云盘”；其中“+ 新建”和“上传”只保留 UI，不执行任何实际动作。

主区域沿用现有白色面板、灰色边框、蓝色操作按钮和文件表格风格：

```text
OSS 云盘
└── 流程
    └── 节点
        └── 学号－姓名
            └── 文件
```

- 根目录显示当前已发布流程文件夹。
- 流程目录显示会产生文件的节点文件夹。
- 节点目录只显示已有有效文件的学生文件夹，名称为“学号－姓名”。
- 学生目录显示文件名、大小、提交时间、审核状态和下载操作。
- 流程与节点行显示下一级数量；学生行显示文件数量。
- 面包屑每一级均可点击返回；刷新页面后回到 OSS 根目录。
- 搜索框只筛选当前目录，不执行跨层级全局检索。

### 4.2 页面状态

- 首次进入显示目录加载状态。
- 目录加载失败时保留 OSS 页面框架，显示错误和“重新加载”按钮。
- 各层分别显示空状态；无文件流程显示“该流程暂无学生提交文件”。
- 下载期间只禁用当前文件的下载按钮，并显示下载中状态。
- 下载失败只在当前文件区域显示错误，不清空已加载目录。

### 4.3 组件与状态调整

- `frontend/src/features/home/OssMaterialLibraryView.tsx`：新增独立的真实只读材料目录组件，负责加载、逐层导航、搜索和下载状态。
- `frontend/src/features/home/HomeView.tsx`：删除原模拟文件管理组件，只保留既有教务流程列表组件。
- `frontend/src/features/academic-flow/api.ts`：增加材料目录类型、目录请求和单文件下载请求。
- `frontend/src/App.tsx`：删除仅用于模拟云盘的 `homeFolders`、`homeFiles`、`homeActiveFolder` 状态和回调。
- `frontend/src/types.ts`、`frontend/src/features/home/HomeDialogs.tsx`：删除不再使用的模拟文件、文件夹、右键菜单与移动对话框类型和组件；保留教务流程仍使用的名称、复制和删除对话框。
- `frontend/src/styles.css`：增加目录层级、数量、文件状态、加载、空状态和错误样式，不建立新的视觉体系。

## 5. 调用链

```text
教师点击 OSS 云盘
→ 前端进入 `/` 并请求材料目录
→ 后端按教师、当前发布版本、发布快照、有效名单和当前提交筛选
→ 前端按流程、节点、学生、文件逐层展示
→ 教师点击单个文件下载
→ 后端按同一规则重新鉴权
→ 对象存储生成短期签名地址
→ 浏览器下载文件
```

## 6. 不在本次范围

- 不展示未发布草稿流程、历史发布版本、失效提交或未提交临时文件。
- 不提供模板文件、公告图片或答案数据浏览。
- 不提供批量下载；现有节点资料包功能保持原位。
- 不提供跨流程搜索、分页、手工 OSS 文件管理或跨教师浏览。
- 不修改数据库结构、OSS 对象键、学生端和流程设计器行为。

## 7. 验证边界

依项目规范，代码修改过程中不运行自动测试、前端构建或浏览器检查。实现完成后进行以下静态审计：

1. 目录与下载查询均检查教师归属、当前发布版本、有效名单、当前节点尝试和有效提交状态。
2. 发布快照决定节点标题与顺序，数据库 ID 和 `node_key` 用于关联，不以显示名称作为标识。
3. 目录响应不包含 OSS 对象键，下载接口在每次请求时重新鉴权。
4. 前端逐层导航、搜索、空状态、重试和单文件下载错误互不污染。
5. 模拟 CRUD 删除后不存在残留属性、类型、事件处理或不可达组件。
6. 通过差异检查和引用搜索后提交结果，清理限定缓存，并以非 Docker 方式重启服务，核对 8000、5173 端口及进程工作目录。
