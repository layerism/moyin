# 学生运行弹窗横向溢出修复设计

## 问题

学生运行弹窗固定为约 620 px 宽，但确认承诺节点中的扫描件文件名和五个操作按钮被安排在同一行。操作区不可收缩，现有换行规则又只按浏览器视口宽度触发，不能反映弹窗内部的实际可用宽度。因此内部网格产生过大的最小内容宽度，弹窗出现横向滚动条，模板卡片和右侧按钮被裁切。

## 目标

- 学生运行弹窗在任何视口宽度下都不出现横向滚动条。
- 弹窗内容仍可按现有规则纵向滚动。
- 扫描件文件名完整占用第一行，并保持省略号截断。
- 上移、下移、下载、替换、删除操作位于第二行右侧；空间不足时允许自然换行。
- 保持现有白色面板、灰色边框、蓝色主色、圆角和间距，不改变业务逻辑或交互行为。

## 实现

只修改 `frontend/src/styles.css`：

1. 将 `.runtime-node-dialog` 的滚动策略调整为纵向自动滚动、横向隐藏，并设置 `min-width: 0`。
2. 为弹窗表单、模板步骤、模板下载卡片、扫描件工作区和扫描件列表补充 `min-width: 0`，切断 CSS Grid 默认最小内容宽度向外传递。
3. 在学生运行弹窗内，将扫描件列表项固定为上下两行布局，不再依赖页面级 `@media (max-width: 760px)`。
4. 扫描件操作区允许换行并右对齐；按钮样式、顺序和可用状态保持不变。

不修改 `StudentRuntimePage.tsx`、`ScanUploadWorkspace.tsx` 或任何后端代码。

## 验证边界

依据项目规范，修改过程中不运行测试、不使用浏览器插件。完成后使用源代码审计和 `git diff --check` 确认：弹窗横向滚动被禁止、内部容器允许收缩、扫描件操作区可换行，且差异仅包含样式和本任务文档。随后清理限定缓存，提交结果并重启本地前后端服务。
