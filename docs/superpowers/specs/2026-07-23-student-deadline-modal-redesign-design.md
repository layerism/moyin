# 教师端个别节点延期弹窗重设计

## 1. 背景

教师在“学生填写进度”侧边面板中点击“设置延期”后，当前表单会作为跨列行嵌入进度表格。进度表格自身允许横向滚动，表单操作区又右对齐到表格内容末端，导致“取消”和“保存延期”按钮可能超出侧边面板的可视区域。教师需要横向滚动才能找到操作按钮，容易误判表单缺少保存入口。

本次仅重设计延期编辑区域的呈现方式，不改变延期业务规则、接口、数据结构或保存反馈。

## 2. 目标

- 延期编辑操作脱离表格横向滚动上下文。
- “取消”和“保存延期”始终完整、清晰地显示在弹窗底部。
- 学生身份、节点选择和截止时间信息保持明确。
- 二级弹窗打开后，背景进度面板、页面和流程画布完全不可操作。
- 桌面端与窄屏下均不出现字段或按钮横向裁切。

## 3. 范围

### 3.1 包含

- 将现有表格行内延期表单改为居中的二级弹窗。
- 调整延期弹窗的字段、操作栏、滚动和响应式样式。
- 补充弹窗语义、焦点进入和关闭后的焦点恢复。
- 删除不再使用的行内展开表单样式。

### 3.2 不包含

- 不修改延期读取或写入接口。
- 不修改前后端延期校验规则。
- 不修改学生进度表字段和数据加载逻辑。
- 不新增组件库、弹窗依赖或通用模态框抽象。
- 不调整其他弹窗、学生端页面或流程画布。

## 4. 交互设计

### 4.1 打开

每名学生行继续显示“设置延期”按钮。点击后：

1. 记录当前学生；
2. 按现有规则筛选该学生可延期的节点；
3. 默认选择第一个可延期节点；
4. 初始化新截止时间和延期原因；
5. 打开二级延期弹窗。

表格内不再插入跨列编辑行，也不再显示“收起”状态。弹窗打开后，触发按钮继续保留在原学生行中，关闭弹窗后焦点返回该按钮。

### 4.2 弹窗结构

弹窗分为三个固定区域：

1. **标题区**：显示“设置节点延期”、学生姓名、学号和右上角关闭按钮。
2. **内容区**：显示节点、当前生效截止时间、新截止时间和延期原因。
3. **操作区**：显示“取消”和主操作“保存延期”。

内容区可以纵向滚动；标题区和操作区不随内容滚动。操作区与字段之间使用边框分隔，使保存入口始终醒目。

桌面端字段采用两列网格：

- 第一行：节点、当前生效截止时间；
- 第二行：新截止时间、延期原因。

窄屏下改为单列，字段顺序保持不变。操作按钮保持完整可见，不允许出现文字裁切。

### 4.3 关闭边界

二级弹窗打开后：

- 背景进度面板、页面和流程画布禁止点击、拖动、滚动及缩放；
- 点击弹窗遮罩不关闭；
- 仅右上角关闭按钮和“取消”按钮可以主动关闭；
- 弹窗内容区域是唯一允许滚动和操作的区域；
- 保存请求进行中时，保存按钮禁用并显示“保存中…”。

关闭时清空当前延期草稿并恢复默认延期原因，保持现有取消行为。

### 4.4 无可延期节点

若所选学生没有可延期节点，仍打开弹窗并显示：

> 该学生当前没有可延期节点

此时不显示“保存延期”，仅保留关闭按钮和“取消”。

### 4.5 保存结果

沿用现有行为：

- 保存成功：关闭弹窗、清空草稿、刷新学生进度，并显示“个别学生延期已保存”；
- 保存失败：保持弹窗和输入内容，显示后端错误信息；
- 保存成功但刷新失败：关闭弹窗，并显示“延期已保存，但进度刷新失败”。

## 5. 视觉设计

### 5.1 弹窗容器

- 居中显示于全屏遮罩之上；
- 桌面端使用适合双列字段的固定最大宽度；
- 实际宽度不得超过视口可用宽度；
- 使用现有项目的白色面板、浅灰边框、圆角和阴影风格；
- 最大高度受视口约束，避免上下超出屏幕。

### 5.2 操作层级

- “保存延期”使用现有蓝色主按钮视觉；
- “取消”使用白底描边次按钮；
- 两个按钮保持稳定间距和完整文本；
- 窄屏下允许按钮扩展到可用宽度，但不隐藏、不折叠文字。

### 5.3 背景隔离

二级遮罩层级高于教师进度面板。遮罩覆盖整个视口，阻断对进度面板和流程画布的指针事件。弹窗关闭前，不允许背景滚动穿透。

## 6. 可访问性

- 弹窗使用 `role="dialog"` 和 `aria-modal="true"`。
- 弹窗通过可关联标题提供可访问名称。
- 关闭按钮具有明确的 `aria-label`。
- 打开后将焦点移入弹窗；关闭后恢复到对应学生的“设置延期”按钮。
- 所有操作按钮显式使用 `type="button"`。
- 保留现有键盘焦点可见样式。

## 7. 状态与数据流

继续复用现有延期草稿、保存状态和接口调用。当前 `expandedInstanceId` 的语义调整为“正在编辑的学生实例”，不再控制表格展开行：

```text
点击设置延期
  -> 选择学生并初始化草稿
  -> 打开二级弹窗
  -> 前端校验
  -> 调用现有 setStudentDeadline
  -> 成功后关闭并刷新 / 失败时保留弹窗
```

不新增全局状态，不修改 `workflowApi.setStudentDeadline`，不改变进度数据类型。

## 8. 预计改动

- `frontend/src/features/academic-flow/TeacherProgressPanel.tsx`
  - 移除表格行内展开结构；
  - 在表格之后渲染二级延期弹窗；
  - 增加弹窗语义与焦点恢复；
  - 保留现有字段、校验、保存和反馈逻辑。
- `frontend/src/styles.css`
  - 删除行内延期卡片和跨列表格行样式；
  - 增加全屏遮罩、居中弹窗、固定标题区和操作区样式；
  - 增加桌面双列与窄屏单列布局。

不新增文件、依赖或只使用一次的抽象。

## 9. 验收标准

1. 点击任一学生的“设置延期”后，出现居中的二级弹窗。
2. 表格不再插入行内延期编辑区域。
3. “取消”和“保存延期”始终完整可见，不需要横向滚动。
4. 桌面端字段为两列，窄屏字段为单列，均无横向裁切。
5. 弹窗打开后，背景进度面板、页面和流程画布不能操作或滚动。
6. 点击遮罩不会关闭弹窗；关闭按钮和“取消”可以关闭。
7. 无可延期节点时显示明确空状态，且不显示保存按钮。
8. 保存校验、接口调用、成功反馈、失败保留输入和刷新失败提示均保持原有行为。
9. 关闭弹窗后，焦点返回触发该弹窗的学生行按钮。
10. 后端文件、接口和数据库均无改动。

## 10. 验证边界

按项目约定，开发过程中不运行自动化测试、构建或浏览器测试，只执行静态结构、状态流和业务逻辑审计。实现完成后清理开发产生的缓存，使用本地 Uvicorn 与 Vite 重启服务，由用户按照上述验收标准手动验证。
