# 发布后审核规则原位置热更新设计

## 目标

教师查看已发布流程节点时，继续在节点原有的审核配置位置修改提示词或脚本参数，不再使用独立的“已发布审核规则”区域。

## 业务规则

- 已发布节点的审核脚本、审核开关和审核模式继续锁定，不能借热更新改变审核类型。
- 确认节点的审核提示词，以及文件节点当前脚本声明的配置参数，可在原有控件中编辑。
- 点击右上角关闭、底部“完成”或按 `Escape` 时，若审核规则有变化，则先调用现有节点审核策略接口保存，成功后再关闭。
- 保存失败、参数不合法或 generation 冲突时保留弹窗和教师输入，并在现有底部区域显示错误。
- 热更新只取消该节点尚未完成的审核；已经通过的学生不重新审核，具体事务继续由现有后端策略更新逻辑负责。
- 标题、说明和起止时间仍属于流程修订草稿，重新发布后生效；审核规则参数通过独立策略接口即时生效。两类保存语义必须在原页面中明确说明。
- 未发布流程及新增节点继续使用现有草稿编辑逻辑，不调用已发布策略接口。

## 交互设计

- 删除“已发布审核规则”卡片及其单独保存按钮。
- 确认节点继续显示原有“审核方式”和“形式审核标准/评分标准”；审核方式只读，文本框可编辑。
- 文件节点继续显示原有“材料审核脚本”和脚本参数；脚本选择只读，参数控件可编辑。
- 正在读取、保存、保存失败等状态复用节点弹窗底部区域，不增加新的交互区块。
- 保存过程中禁用关闭动作和可编辑审核参数，避免重复请求。

## 实现范围

- 复用 `GET/PUT /api/workflows/{flow_id}/nodes/{node_key}/audit-policy`、`expectedGeneration` 和现有取消任务逻辑。
- 不修改后端接口、数据表、审核 worker 或发布快照结构。
- 前端加载策略后，以接口返回的参数和参数定义覆盖原位置控件的显示值；保存成功后同步当前设计器节点，避免同一页面再次打开时显示旧值。
- 发布后策略更新不得进入 `filterPublishedNodeRevisionPatch()`，避免审核热更新被误记为待重新发布的流程修订字段。

## 验证边界

遵循项目开发规范，本次只更新对应测试预期并进行静态业务逻辑审计，不执行测试、构建或浏览器检查。完成后以本地非 Docker 方式重启前后端服务。
