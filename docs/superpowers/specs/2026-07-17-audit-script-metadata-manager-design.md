# 预置审核脚本元信息管理设计

## 1. 目标

在教务流程列表页的“创建流程”旁增加“审核脚本”入口。超级管理员可在弹窗中查看 `backend/scripts` 下的预置脚本，并修改名称和功能说明。

## 2. 边界

- 保留当前“脚本由开发人员部署到 `backend/scripts`”的架构。
- 不恢复模板下载、脚本上传、代码编辑、版本更新或删除能力。
- 仅 `super_admin` 可看到入口并调用元信息修改 API；普通教师仍可读取脚本列表并在文件上传节点中选择。
- 不引入新依赖，复用现有 React、FastAPI、Pydantic 和弹窗样式。

## 3. 数据与一致性

`manifest.json` 继续是脚本元信息的唯一真源。修改接口只接收 `name` 和 `description`，后端保留 `id`、`language`、`version` 和 `entry` 原值，通过同目录临时文件与原子替换写回清单。脚本入口文件、版本号和 SHA-256 不变，因此已发布流程的固定版本执行语义不受影响。

名称和说明在去除首尾空白后必须非空，长度分别不超过 120 和 500 字符；名称按不区分大小写方式保持唯一。修改后的 `updatedAt` 取清单和当前版本入口文件中较新的修改时间。

## 4. 交互

弹窗打开后读取脚本列表，展示名称、说明、语言、版本和更新时间。每行提供“编辑”操作；点击后在同一弹窗内切换为名称与说明表单。保存期间禁用重复提交，成功后回到列表并展示新值；失败时保留输入并在弹窗内显示后端错误。

## 5. API

- `GET /api/workflow-admin/audit-scripts`：登录教师读取有效脚本。
- `PATCH /api/workflow-admin/audit-scripts/{script_id}/metadata`：仅超级管理员修改名称与说明，返回更新后的列表项。

## 6. 错误处理

- 脚本不存在、ID 重复或清单已无效：`404`/`422` 且不写文件。
- 名称重复或字段非法：`409`/`422`。
- 文件写入失败：保留原清单，返回统一失败信息，不暴露服务器路径。
- 列表为空时显示明确空状态；读取失败可在弹窗中重试。

## 7. 验收标准

1. 超级管理员可从“创建流程”旁打开管理弹窗，普通教师不显示入口。
2. 弹窗完整表达加载、空列表、读取失败、编辑、保存中和保存失败状态。
3. 修改名称和说明后，节点选择器的新读取结果使用新元信息。
4. 修改元信息不改变脚本 ID、语言、版本、入口文件或哈希。
5. 不存在脚本上传、删除、代码编辑或版本更新入口。
