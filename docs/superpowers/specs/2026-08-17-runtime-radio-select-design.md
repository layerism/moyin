# 学生端单选题下拉框设计

## 目标

将学生运行表单中的单项选择题从完整单选按钮列表改为单行下拉框，减少选项较多时的纵向占用，并保持教师“学生预览”与学生实际填写界面一致。

## 当前实现

`RuntimeFormFields` 当前将 `radio` 字段的所有选项渲染为纵向单选按钮。每个答案仍以对象形式保存在字段对应的 `answerKey` 下：

```ts
{
  otherText: null,
  selectedOptionId: option.id,
}
```

答案校验、草稿保存、提交和只读格式化均依赖 `selectedOptionId`，不依赖具体输入控件。

## 设计方案

- 将 `radio` 字段改为原生 `<select>`。
- 下拉框第一项为不可提交的空值提示“请选择”。
- 每个业务选项的 `value` 使用稳定的 `option.id`，显示文本使用 `option.label`。
- 当前答案存在时，通过 `selectedOptionId` 回显对应选项；未选择时使用空字符串。
- 选择变化后继续写入原有答案对象，不改变草稿和提交数据结构。
- 下拉框失焦时继续调用现有 `onBlur(field.id)`，维持错误提示的显示时机。
- 错误存在时继续通过 `aria-describedby` 关联现有错误文本。

优先复用 `styles.css` 中现有的 `runtime-form-field-select` 和下拉框样式，只在必要时补充焦点或错误状态，不引入自定义弹层组件。

## 作用范围

`RuntimeFormFields` 同时用于教师“学生预览”和学生实际填写，因此两处同步生效。

以下内容不变：

- 多项选择题继续使用复选框列表及选择数量提示；
- 文本框和多行文本框；
- 已提交内容的只读展示；
- 表单字段编辑器中的题型和选项编辑方式；
- 单选答案校验、暂存、提交和后端持久化格式。

## 状态与错误处理

- 未选择时，下拉框值为空，提交校验仍返回“请选择一项”。
- 已保存的有效 `selectedOptionId` 正常回显。
- 已保存但不在当前选项集合中的值不在下拉框中显示，现有校验继续将其识别为“选择内容无效”。
- 选择新选项时将 `otherText` 重置为 `null`，与现有单选按钮行为一致。

## 可访问性与视觉

- 使用原生 `<select>`，保留浏览器键盘导航和移动端原生选择体验。
- 字段标题继续作为上方可见标签；错误信息继续通过 `aria-describedby` 关联。
- 下拉框宽度占满字段卡片，沿用灰色边框、白色背景和现有圆角。

## 验证边界

按项目规范不运行测试和浏览器自动化。实施后进行静态业务逻辑审计，确认单选答案对象、失焦回调、错误关联和多选题分支保持正确；运行 `git diff --check`，清理限定缓存，并以本地方式重启前后端服务。
