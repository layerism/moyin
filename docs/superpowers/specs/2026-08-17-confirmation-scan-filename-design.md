# 确认承诺扫描件文件名提交校验设计

## 目标

确认承诺节点配置 DOCX 模板后，学生提交节点时，所有待提交扫描件的文件名必须以模板主文件名开头。只有全部文件名通过校验，系统才创建提交记录并进入审核阶段。

## 文件名规则

- 模板名称取发布版本绑定模板的 `original_name`，并移除末尾 `.docx` 扩展名。
- 扫描件名称取待提交文件的 `original_name`，并移除末尾 `.jpg`、`.jpeg` 或 `.png` 扩展名。
- 模板名称和扫描件名称先进行 Unicode NFC 规范化，再执行区分大小写的严格前缀匹配。
- 扫描件主文件名可以等于模板主文件名，也可以在其后追加任意字符。
- 扫描件原有格式、数量、页数与归属校验保持不变。

例如模板为 `安全责任书.docx`：

- `安全责任书.jpg`：通过。
- `安全责任书第1页.png`：通过。
- `安全责任书(1).jpeg`：通过。
- `我的安全责任书.jpg`：不通过。
- `安全责任.jpg`：不通过。

## 后端约束

校验位于 `submit_node()` 的确认承诺扫描件分支内：

1. 读取发布版本中当前节点绑定模板的权威 `original_name`。
2. 读取当前学生、当前节点全部未提交扫描件。
3. 在写入 `submissions`、关联文件、创建 `audit_jobs` 和更新节点状态之前逐一校验文件名。
4. 任一文件名不合规时抛出业务冲突，整个提交事务不产生提交记录或审核任务，节点维持原可编辑状态。

错误信息指出首个不合规文件及要求，例如：

> 文件“扫描件1.jpg”名称不符合要求，请改为以“安全责任书”开头后重新上传。

模板绑定或模板名称异常时提示学生联系教师，不以客户端传入值作为权威模板名称。

## 前端反馈

- `getScanSubmitBlocker()` 接收运行实例返回的模板名称和当前扫描件列表。
- 按同一规则检查扫描件名称；存在不合规文件时禁用“提交节点”。
- 在提交按钮下显示首个不合规文件的修改提示。
- 上传、替换、排序、删除和暂存不受该规则阻断，学生可通过替换文件完成修正。
- 后端仍执行最终校验，前端校验不作为安全边界。

## 范围边界

- 仅影响配置模板并要求扫描件的确认承诺节点。
- 不改变普通文件节点现有上传文件名规则。
- 不自动重命名学生文件，不改变 OSS 对象或已上传文件元数据。
- 不改变审核脚本、审核 worker、节点解锁和下游推进语义。

## 验收条件

1. 全部扫描件名称合规时，可以提交并按原规则进入审核阶段。
2. 任一扫描件名称不合规时，前端显示明确提示且不能提交。
3. 绕过前端直接调用提交接口时，后端仍拒绝不合规文件。
4. 后端拒绝后不创建 submission 或 audit job，不关联扫描件，不更新节点为 reviewing。
5. 多扫描件场景逐一校验，允许模板名后使用不同附加字符。
