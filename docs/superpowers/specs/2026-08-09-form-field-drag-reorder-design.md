# 表单字段与选项拖拽排序设计

## 目标

将表单字段及单选/多选选项的顺序调整方式由“上移/下移”按钮改为专用拖拽手柄。交互统一支持鼠标、触控笔与触屏设备，同时保留键盘可访问的排序方式。

## 范围

- 所有表单字段均可通过字段摘要或标题栏左侧的拖拽手柄排序，包括单行文本、多行文本、单项选择和多项选择。
- 单项选择与多项选择内部的选项可通过选项行左侧拖拽手柄排序。
- 仅拖拽手柄能够启动排序；标题编辑、选项输入、必填开关、折叠控制和操作菜单不启动拖拽。
- 字段和选项的“⋯”菜单保留删除操作，移除可见的“上移/下移”操作。
- 不修改表单字段及选项的数据结构、校验规则和后端接口。

## 交互设计

### 指针拖拽

1. 用户按下拖拽手柄后进入待拖拽状态；超过小幅移动阈值后正式开始拖拽，避免点击抖动造成误排序。
2. 拖动中的原项目降低透明度，当前候选插入位置显示蓝色插入线。
3. 指针经过其他项目的上半区时插入其前方，经过下半区时插入其后方。
4. 松开指针时一次性提交新顺序；如果顺序未变化，不调用 `onChange`。
5. 指针取消、目标失效或项目已删除时取消拖拽，保持原顺序。
6. 拖拽期间捕获指针，鼠标、触控笔和触屏使用同一套 Pointer Events 逻辑；手柄设置 `touch-action: none`，避免页面滚动抢占手势。

### 字段排序

- 文本字段的手柄位于字段标题栏左侧。
- 单选/多选字段的手柄位于折叠摘要栏最左侧。
- 拖动字段时不改变当前展开字段；字段 ID 保持不变，因此展开状态随字段移动。

### 选项排序

- 选项行左侧显示六点手柄和自动序号。
- 排序完成后序号按新顺序重新计算。
- 选项文本输入与删除菜单保持现有行为。

### 键盘排序

- 拖拽手柄可获得焦点，并提供明确的 `aria-label`。
- 手柄获得焦点后，`Alt + ArrowUp` 和 `Alt + ArrowDown` 分别向前、向后移动一位。
- 到达列表边界时不移动，也不产生数据变更。

## 状态与数据流

- 组件仅保存当前拖拽来源、候选目标和指针信息等瞬时 UI 状态。
- 排序过程中不持续修改业务数据；仅在有效放置时调用既有字段或选项排序函数。
- 字段排序继续通过 `onChange` 提交完整字段数组；选项排序继续更新所属字段的 `options`。
- 当组件进入锁定状态、字段被删除或选项被删除时，立即清除关联拖拽状态。

## 视觉反馈

- 手柄默认使用低对比度六点图标，悬停或聚焦时变为蓝色。
- 拖动项目使用轻微透明度和蓝色轮廓，目标位置使用 2px 蓝色插入线。
- 光标在手柄上显示 `grab`，拖动中显示 `grabbing`。
- 反馈保持紧凑，不改变卡片主体尺寸和现有信息层级。

## 边界与错误处理

- 锁定或发布后不可编辑的字段不显示可操作拖拽状态，键盘排序同样禁用。
- 只有一个项目时允许显示手柄，但排序不会产生数据变更。
- 拖动输入区域、复选框、折叠按钮或菜单不会触发排序。
- 拖拽结束后始终清理指针捕获和临时状态，避免残留高亮。

## 验证边界

按项目规则不运行自动化测试、构建或浏览器自动化。实现完成后进行以下静态业务审计，并交由用户手动验证：

- 字段和选项菜单不再包含上移/下移。
- 鼠标、触控和键盘排序调用同一业务排序路径。
- 无变化放置不提交数据。
- 锁定状态无法排序，但仍可查看字段内容。
- 数据结构、校验逻辑和后端文件无改动。
