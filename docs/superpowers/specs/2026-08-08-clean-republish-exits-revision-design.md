# 无改动重新发布退出修订设计

## 目标

已发布流程解锁编辑后，如果用户没有产生任何设计改动，点击“重新发布”应直接退出修订模式，不创建或覆盖流程版本。

## 根因

当前 `publishButtonState` 在“已发布、修订中、无未发布改动”状态下禁用“重新发布”按钮。按钮无法触发退出操作；而现有发布路径一旦调用后端 `publish_flow`，后端会创建新的版本记录。

## 状态设计

为发布按钮状态增加 `finish-revision` 动作：

- 条件：流程已发布、已进入修订模式、`revisionDirty` 为 `false`。
- 文案：继续显示“重新发布”。
- 状态：按钮可点击；仅受正在保存、弹窗确认等系统操作锁影响。
- 行为：退出修订模式，将界面恢复为已发布只读状态。
- 提示：显示“未检测到改动，已退出编辑”。

存在实际改动时仍使用原有 `republish` 动作，继续执行表单校验、修订影响预览和发布确认流程。

## 数据流

1. `getPublishButtonState` 根据 `published`、`revisionEditing` 和 `hasUnpublishedChanges` 返回 `finish-revision`。
2. 点击处理器识别 `finish-revision`，将本地工作副本恢复为当前已发布 `process`。
3. 清除修订请求、脏状态、修订影响和待发布副本。
4. 设置退出提示并返回，不调用 `getRevisionImpact` 或 `onPublishProcess`。

## 边界

- 不新增或覆盖 `flow_versions` 记录。
- 不修改后端发布接口。
- 不修改流程节点、连线、学生实例或已发布快照。
- 节点检查面板可以保持打开，但退出后转为只读。
- 学生名单为空不阻止无改动退出，因为该操作不是发布。
- 操作锁生效时仍禁用按钮，避免与保存或弹窗状态冲突。

## 验证边界

遵循项目约定，不运行自动化测试或浏览器测试。通过按钮状态、点击处理器、API 调用边界和最终差异的源码审计确认实现范围；界面行为由用户手动验证。
