# 登录账号记忆设计

## 目标

降低教师和学生重复输入姓名、工号或学号的成本，同时保持密码与会话凭据的安全边界。

## 设计

- 登录页始终以空白字段打开，不自动回填历史账号。
- 点击或聚焦姓名、工号/学号输入区域时，显示当前角色的账号历史下拉列表。
- 每条历史记录保存姓名与工号/学号组合；选择后同时填写两个字段。
- 仅在登录成功且勾选“记住账号”后加入历史；不保存失败或未提交的输入。
- 教师和学生历史分别保存，按工号/学号去重，最近使用项优先，单角色最多保留 5 项。
- 历史下拉列表支持删除单项记录；取消“记住账号”只影响当前登录，不清空已有历史。
- 注册页不读取或写入账号记忆。
- 密码、Cookie、Session ID 和 Token 不写入 Web Storage；密码继续由浏览器密码管理器处理。
- 本地存储使用版本化键 `oa.auth.account-history.v2`，无效数据按空状态处理；旧键 `oa.auth.remembered.v1` 可迁移为历史列表。

## 表单规范

- 表单和输入框提供稳定的 `id`、`name`、`required` 与正确的 `autocomplete`。
- 姓名和工号/学号由项目内历史下拉提供，使用 `autocomplete="off"`，避免页面加载时自动写入通用表单信息。
- 登录密码使用 `autocomplete="current-password"`，注册密码使用 `autocomplete="new-password"`。

## 验证

- 单元测试覆盖角色隔离、损坏数据容错、去重、数量限制、旧格式迁移和单项删除。
- 浏览器验证初始字段为空、点击显示历史、选择后成对填写、身份切换隔离以及密码不进入本地存储。
- 运行前端测试和生产构建。
