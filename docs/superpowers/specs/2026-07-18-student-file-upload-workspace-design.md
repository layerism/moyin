# 学生文件上传工作区设计

## 目标

将学生节点弹窗中的文件上传控件改为具有明确过程反馈的上传工作区，使学生能清楚感知“选择文件、正在上传、文件已就绪、提交节点”四个阶段。

## 范围

仅调整 `StudentRuntimePage` 中 `file` 类型节点的可填写表单，以及对应 CSS。保留现有上传 API、文件元数据格式、暂存、提交、审核和只读查看逻辑。

## 交互状态

### 空状态

展示可点击、可拖拽的上传区域，文案为“点击选择或拖拽文件到此处”，附带“选择后将自动上传”的辅助说明。原生 `input[type=file]` 保留为隐藏的可访问控件。

### 拖拽状态

文件拖入区域时，以蓝色边框和浅蓝背景强调投放目标；离开或完成投放后恢复。

### 上传中状态

选择或投放文件后立即进入上传中状态，显示文件名和“正在上传，请勿关闭窗口”。上传控件、暂存和提交动作在上传完成前禁用，避免多次上传或错误提交。

### 已就绪状态

上传成功后展示绿色文件摘要：文件名、格式化后的文件大小与“文件已上传，可提交”。提供“更换文件”动作；提交节点按钮恢复可用。

### 失败状态

沿用现有顶层 `notice` 错误反馈；上传工作区恢复到可重新选择文件的状态，不伪造成功结果。

## 实现边界

- 将现有 `onUploadFile` 从同步回调改为返回 `Promise<void>`，以便上传工作区可靠地维护本地上传中状态；
- 使用已有上传接口与 `draft.file` 中的 `fileId` 识别“已就绪”文件；
- 文件节点的“提交节点”在无已就绪文件或上传中时禁用，并给出明确原因；
- 不新增依赖，不修改后端接口或文件校验规则；
- 使用现有蓝、绿、灰色语义与现有按钮体系，不生成新视觉资产。

## 验收标准

- 文件节点不再显示浏览器默认文件选择控件；
- 支持点击选择与拖放一个文件；
- 上传过程可见，成功后可辨认文件名、大小和就绪状态；
- 未上传完成时不能提交文件节点；
- 已有文件上传、暂存、提交、审核与只读查看行为保持兼容。

## 验证边界

依据项目约定，仅执行静态源码、CSS 与 Git 范围审计，不运行自动化测试、构建或浏览器测试；由用户在学生流程页面手动验证上传交互。
