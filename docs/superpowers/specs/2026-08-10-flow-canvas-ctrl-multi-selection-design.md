# 流程画布 Ctrl 逐个多选设计

## 目标

在现有左键拉框多选基础上，增加 `Ctrl + 鼠标左键`逐个增选和减选节点的能力，并继续使用同一套整体拖动逻辑。

## 交互规则

1. 普通左键点击未选节点时，清除原多选集合，只选中当前节点。
2. `Ctrl + 左键`点击未选中的可移动节点时，将其加入当前集合。
3. `Ctrl + 左键`点击已选中的可移动节点时，将其从当前集合移除。
4. 锁定节点忽略 Ctrl 多选，不加入或移出集合；普通左键仍可选择该节点查看信息。
5. 移除当前活动节点后，剩余集合中的第一个节点成为活动节点；集合为空时不显示节点快捷操作。
6. Ctrl 点击只负责切换选择，不启动节点拖动。完成选择后，释放 Ctrl，再拖动任一已选节点可整体移动。
7. 左键拉框、右键画布平移、Ctrl+滚轮缩放、节点连线和双击设置保持现有行为。

## 实现方式

复用 `FlowNodeCanvas` 已有的 `selectedNodeIds`，不增加新的选择状态或全局键盘监听。

在节点 `pointerdown` 阶段读取 `event.ctrlKey`：

- Ctrl 按下时，对当前节点执行集合切换并立即结束，不建立 `draggingNodes`；
- Ctrl 未按下时，继续执行现有单选或整组拖动快照逻辑。

节点 `click` 处理同样识别 `event.ctrlKey`，避免 Ctrl 减选后又被普通点击逻辑重新选中。连接点已经阻止指针事件冒泡，不参与该逻辑。

活动节点仍由父级 `activeNodeId` 管理。Ctrl 增选时把新加入节点设为活动节点；Ctrl 减选活动节点时，把剩余集合首项传给 `onSelectNode`。集合为空时保留父级 ID 但不渲染选中样式或快捷操作，避免为纯界面状态修改流程数据。

## 状态边界

- 多选集合仍只存在于当前页面会话，不写入流程配置。
- 节点删除、流程切换和画布锁定继续由现有 effect 清理无效 ID。
- Ctrl 多选只允许 `canMoveNode(node.id)` 为真的节点，保持与拉框多选一致。

## 实施范围

修改：

- `frontend/src/features/academic-flow/AcademicFlowDesigner.tsx`

不修改：

- 后端、数据库和流程数据结构；
- 框选矩形与整组位移算法；
- 学生端画布；
- Shift、Meta、Command 等其他组合键；
- 批量删除、复制或对齐功能。

## 静态审计标准

按仓库规则不运行测试、构建或浏览器插件，仅检查：

- Ctrl 增选、减选和普通单选三个分支互斥；
- Ctrl 点击不会建立拖动快照；
- 锁定节点不会进入 Ctrl 多选；
- 减选活动节点后活动节点切换正确；
- 原有框选和整体移动逻辑没有被复制或绕过。
