# 教师流程真实预览设计

## 目标

在教师发布流程前提供真实学生端预览。预览必须复用现有学生运行页面、上传、提交、AI 审核和节点推进链路，同时与正式学生、正式版本、名单、进度和统计完全隔离。

## 产品规则

- 教师编辑页顶部增加“预览”按钮，与“暂存”“提交发布”并列。
- 存在未暂存修改时禁止预览，并提示教师先暂存。
- 预览使用数据库中的最新已暂存草稿，不读取浏览器中的未保存状态。
- 预览在新标签页打开，不经过学生登录页。
- 预览页面复用 `StudentRuntimePage`，视觉、节点表单、文件上传、模板下载、提交和审核反馈与正式学生端一致。
- 预览页显示的学生身份名称为“学生预览测试”。页面左上角返回按钮关闭预览标签页，不进入正式学生首页。
- 预览忽略所有节点起始时间、截止时间和延期时间。
- 预览仍严格遵守前置节点是否通过、退回、AI 审核结果和下游节点开放逻辑。
- 每位教师只绑定一个隐藏虚拟学生；所有流程预览均复用该身份。
- 每次创建预览前，清空该教师虚拟学生此前的全部预览业务数据和上传文件。

## 数据模型与隔离

### 虚拟学生

在 `student_accounts` 增加：

- `account_kind`: `normal | preview`，既有账号迁移为 `normal`。
- `preview_owner_teacher_id`: 可空教师外键；`preview` 账号必须绑定教师，且每位教师唯一。

虚拟学生使用内部生成的不可知密码散列，但学生注册、登录、学生首页和名单匹配均只接受 `account_kind = normal`。虚拟学生不能通过公开接口登录，也不写入 `flow_roster_entries`。

### 临时版本

预览使用当前流程已暂存的 `draft_config` 创建 `flow_versions.status = preview` 的临时版本。正式运行和发布相关查询继续只接受 `status = published`。临时版本复制当前草稿关联的模板映射和审核脚本配置，因此模板下载与 AI 审核使用真实配置。

### 预览会话

新增 `flow_preview_sessions`：

- `id`: 随机会话 ID。
- `teacher_account_id`: 教师 ID。
- `preview_student_account_id`: 该教师唯一虚拟学生 ID。
- `flow_id`: 当前流程 ID。
- `flow_version_id`: 临时版本 ID。
- `flow_instance_id`: 临时实例 ID。
- `token_hash`: 随机预览令牌的哈希值。
- `status`: `active | cleaning`。
- `expires_at`: 创建后 24 小时。
- `created_at`: 创建时间。

每位教师最多存在一个预览会话。提交、草稿、审核任务和上传文件通过临时实例及节点实例的外键关系自然归入预览范围，不在每个下游表重复添加范围字段。

## 身份与权限

新增教师鉴权接口：

```text
POST /api/workflows/{flow_id}/preview
```

接口只允许流程所有者调用。返回 `instanceId`、`previewToken` 和预览 URL。

前端在预览标签页的 `sessionStorage` 保存令牌，并为学生运行 API 请求增加 `X-Flow-Preview-Token`。后端运行时身份依赖按以下顺序解析：

1. 存在预览令牌时，同时校验教师 Cookie、令牌哈希、会话状态、有效期、实例归属和流程所有权，然后映射为该教师的虚拟学生。
2. 不存在预览令牌时，保持现有学生 Cookie 鉴权。

预览令牌不能单独使用，且不创建或覆盖 `oa_session`，因此不会影响浏览器中已有的真实学生登录状态。

## 创建预览数据流

1. 教师点击“预览”。
2. 前端使用现有脏状态判断阻止未暂存流程。
3. 前端同步创建空白新标签页，避免异步请求完成后触发浏览器弹窗拦截。
4. 后端校验教师和流程所有权。
5. 后端清理该教师旧预览会话。
6. 后端取得或创建该教师唯一虚拟学生。
7. 后端读取最新 `draft_config`，执行流程配置、模板和审核配置校验。
8. 后端创建 `preview` 临时版本、模板映射、预览会话、流程实例和节点实例。
9. 根节点状态直接设为 `available`；其他节点初始为 `locked`，不计算时间限制。
10. 后端返回随机令牌和实例 ID。
11. 新标签页写入令牌并跳转到 `/student/flows/{instanceId}?preview=1`。
12. `StudentRuntimePage` 使用相同组件和学生运行 API 完成后续操作。

## 运行时差异

预览身份获取实例时：

- `effectiveStartAt` 和 `effectiveDeadline` 均返回 `null`。
- 状态重算忽略 `startAt`、全局截止时间和学生延期时间。
- 根节点及已满足全部前置通过条件的节点为 `available`。
- 未满足前置条件的节点保持 `locked`。
- 提交、自动通过、AI 审核、退回、重试和下游推进继续调用正式运行逻辑。
- 现有 `autoApprove = false` 且未配置 AI 审核的节点会与正式学生端一致地停留在“审核中”；本需求不新增人工审核接口。

除时间规则和返回按钮行为外，不在学生运行组件中建立独立预览分支。

## 清理与并发

每次创建预览时清理该教师此前的全部预览，不限旧预览所属流程：

1. 将旧会话改为 `cleaning`，使旧标签页立即失去写权限。
2. 查询旧实例关联的全部 `uploaded_files.storage_key`。
3. 逐一删除 OSS 对象。
4. 仅当 OSS 清理成功后，在数据库事务中删除旧会话、实例、节点实例、草稿、提交、审核任务、模板下载事件、上传文件、模板映射和临时版本。
5. 任一 OSS 删除失败时停止创建新预览，保留可重试的清理记录并向教师返回明确错误。

创建预览时同时扫描并清理所有超过 24 小时的预览会话。浏览器关闭事件不作为清理依据。正在执行的旧审核任务在写回前必须确认预览会话仍为 `active`；会话失效后不得写回结果或推进节点。

## 前端交互与错误处理

- 未暂存：不创建标签页，显示“请先暂存当前修改后再预览”。
- 浏览器阻止新标签页：不创建预览，提示允许本站打开新标签页。
- 创建失败：关闭已打开的空白页，在教师页面显示后端错误。
- 清理失败：不创建新实例，提示“旧预览文件清理失败，请重试”。
- 草稿不满足运行条件：不创建临时版本，展示与发布校验一致的错误。
- 预览令牌失效或过期：预览页显示会话失效，不回退到真实学生登录。

## 查询隔离审计

以下正式查询必须排除预览数据：

- 学生登录、学生首页和可访问流程。
- 流程学生名单。
- 教师学生进度、提交详情和延期管理。
- 流程版本、修订影响和发布基准。
- 统计、数据库业务视图和正式审核队列。

审核任务消费者只能处理仍处于 `active` 会话的预览任务；正式任务行为不变。

## 验收与验证范围

按项目约束，开发过程不运行测试、构建或浏览器插件，仅执行静态业务逻辑审计：

- 预览只能基于已暂存草稿创建。
- 每位教师只能取得自己的虚拟学生和预览会话。
- 虚拟学生不能通过公开登录接口登录。
- 新预览会使同一教师的旧预览失效并清空。
- 清理查询只能命中 `preview` 临时版本和对应虚拟学生数据。
- 正式名单、进度、统计和版本查询均显式排除预览根实体。
- 预览忽略时间，但保持前置通过和审核推进逻辑。
- 真实学生运行 API 在没有预览令牌时保持原鉴权与行为。
- 完成后清理开发缓存、提交修改并以本地方式重启服务，不使用 Docker。
