# 教师邀请注册与统一登录入口设计

## 1. 背景

当前登录页通过查询参数在教师与学生之间切换，并同时向教师公开“注册新账户”入口。后端 `POST /api/auth/teacher/register` 也允许未认证访问者直接提交姓名、工号和密码创建教师账号。页面隐藏、独立 URL 或五位工号格式均不能证明注册者具有教师身份，因此必须由后端建立教师账号发放边界。

本设计采用“统一访问入口默认展示学生登录，教师通过弱化入口进入独立登录页；教师首次注册必须使用超级管理员生成的一次性邀请链接”的方案。

## 2. 目标

- `/login` 作为统一访问入口，默认展示学生登录。
- 学生登录页不再展示教师/学生切换标签，在页面底部提供低强调度的“教师登录”入口。
- 教师使用独立的 `/teacher/login` 登录已有账号，页面不提供公开注册入口。
- 超级管理员可以生成绑定教师姓名和五位工号的一次性邀请链接。
- 邀请令牌必须由后端校验，且只能使用一次、可以过期和撤销。
- 关闭无需邀请即可创建教师账号的公开接口。
- 保留已有教师账号、学生账号、会话、流程实例和提交数据。

## 3. 非目标

- 不引入学校统一身份认证、LDAP 或 CAS。
- 不合并现有 `student_accounts` 与 `teacher_accounts`。
- 不修改教师与学生现有 Session Cookie 的隔离方式。
- 不使用秘密登录 URL 代替账号密码认证。
- 不复用学生流程分享链接使用的 `share_tokens`。
- 不允许邀请创建 `super_admin` 账号。

## 4. 页面与路由

### 4.1 统一入口

`/login` 默认显示学生登录表单，保留学生注册与忘记密码入口。页面底部增加低强调度文字入口“教职工用户？教师登录 ›”，点击后进入 `/teacher/login`。

学生页不显示角色切换标签，避免学生误入教师认证流程。

### 4.2 教师登录

`/teacher/login` 仅显示教师姓名、五位工号、密码、记住账号和登录操作。页面不显示“注册新账户”，只提供“返回学生登录”。教师注册完成后，以后均通过该稳定地址登录，不要求每次重新使用邀请链接。

### 4.3 教师邀请注册

邀请地址为 `/teacher/invitations/:token`。页面首先向后端验证令牌，再只读展示管理员预设的姓名和工号。教师只填写密码与确认密码。

注册成功后自动创建教师 Session，并进入教师流程管理首页。邀请无效、过期、已使用或已撤销时，统一显示“邀请链接无效或已失效”，并提供返回教师登录的操作。

### 4.4 旧地址兼容

- `/auth/login?role=student` 与 `/auth/login` 跳转到 `/login`。
- `/auth/login?role=teacher` 跳转到 `/teacher/login`。
- `/auth/register?role=student` 跳转到 `/student/register`。
- `/auth/register?role=teacher` 跳转到 `/teacher/login`，并提示“教师账号需由超级管理员邀请注册”。

## 5. 超级管理员邀请管理

超级管理员拥有独立的“教师邀请”管理页，而不是依赖通用数据库行编辑器创建邀请。

生成邀请时必须填写：

- 教师姓名；
- 五位数字工号，格式为 `^\d{5}$`；
- 有效期，默认 24 小时。

生成后只展示一次包含原始令牌的完整链接，并提供复制按钮。数据库不保存可恢复的原始令牌；管理员关闭结果弹窗后如需重新发送，应撤销原邀请并重新生成。

邀请列表展示姓名、工号、状态、创建时间、过期时间和操作。状态包括：

- `active`：待注册；
- `used`：已注册；
- `expired`：已过期；
- `revoked`：已撤销。

有效邀请可以撤销。已过期邀请可以重新生成；重新生成前先将同工号旧邀请归档为过期或撤销，确保同一工号最多只有一个有效邀请。

## 6. 数据模型

新增 `teacher_invitations` 表：

| 字段 | 含义 |
| --- | --- |
| `id` | UUID 主键 |
| `employee_no` | 邀请绑定的五位工号 |
| `name` | 邀请绑定的教师姓名 |
| `token_hash` | 原始令牌的 SHA-256 哈希，唯一 |
| `status` | `active`、`used`、`expired` 或 `revoked` |
| `expires_at` | 过期时间 |
| `created_by` | 创建邀请的超级管理员账号 ID |
| `created_at` | 创建时间 |
| `used_by_teacher_id` | 注册成功后关联的教师账号 ID |
| `used_at` | 使用时间 |
| `revoked_at` | 撤销时间 |

邀请令牌使用 `secrets.token_urlsafe(32)` 生成。数据库仅保存 SHA-256 哈希，原始值仅在创建接口响应中返回一次。

## 7. API 设计

### 7.1 公开认证接口

- `POST /api/auth/student/register`
- `POST /api/auth/student/login`
- `POST /api/auth/teacher/login`
- `GET /api/auth/teacher-invitations/{token}`：验证邀请并返回只读姓名、工号与过期时间。
- `POST /api/auth/teacher-invitations/{token}/accept`：接收密码并完成教师注册。

现有 `POST /api/auth/teacher/register` 被关闭，不再接受无邀请注册。

### 7.2 超级管理员接口

- `GET /api/admin/teacher-invitations`：读取邀请列表。
- `POST /api/admin/teacher-invitations`：生成绑定姓名、工号和有效期的邀请。
- `POST /api/admin/teacher-invitations/{id}/revoke`：撤销仍有效的邀请。

所有管理员接口继续使用 `get_current_super_admin` 作为后端最终权限边界。

## 8. 核心业务流程

### 8.1 创建邀请

1. 后端验证调用者为超级管理员。
2. 姓名去除首尾空白，工号必须为五位数字。
3. 检查 `teacher_accounts` 中不存在相同工号。
4. 将同工号已经自然过期但仍标记为 `active` 的记录更新为 `expired`。
5. 若仍存在有效邀请，则拒绝重复创建。
6. 生成高强度随机令牌，仅持久化其哈希。
7. 写入邀请记录和审计日志。
8. 将原始令牌随本次响应返回一次。

### 8.2 接受邀请

接受邀请在一个 `BEGIN IMMEDIATE` 数据库事务中完成：

1. 根据令牌哈希读取邀请。
2. 验证状态为 `active` 且未过期。
3. 从邀请记录读取姓名和工号，不信任客户端提交的身份字段。
4. 再次确认工号尚未注册。
5. 创建角色固定为 `teacher` 的教师账号。
6. 将邀请更新为 `used`，写入教师账号 ID 和使用时间。
7. 写入审计日志并提交事务。
8. 事务提交后创建教师 Session Cookie，返回教师身份。

事务失败时不得将邀请标记为已使用，教师可以在邀请仍有效时重新提交。

### 8.3 撤销邀请

只有 `active` 且未使用的邀请可以撤销。撤销操作记录管理员、邀请 ID、绑定工号和时间；已使用邀请不得回退为有效状态。

## 9. 校验与错误处理

- 教师工号在邀请创建和教师登录模型中都使用五位数字格式校验。
- 密码沿用现有至少 8 位的要求。
- 邀请不存在、哈希不匹配、过期、已使用或已撤销统一返回相同的失效提示，避免泄露令牌状态。
- 工号已经注册时终止邀请使用并提示联系管理员，不覆盖现有账号。
- 非超级管理员访问邀请管理接口返回 `403`。
- 邀请接受接口只能创建 `teacher`，客户端不能提交角色字段。
- 页面路由分离只负责交互清晰，所有权限仍由后端依赖项、邀请状态和 Session 校验决定。

## 10. 前端组件边界

- 将当前可变角色的认证页调整为固定角色页面，删除登录表单内部的角色切换状态。
- 学生登录与教师登录可以复用基础表单样式和账号记忆能力，但路由、文案、导航入口和可调用接口必须固定。
- 新增教师邀请注册页，身份字段只读，密码为唯一可编辑业务输入。
- 新增独立的超级管理员教师邀请管理页，负责生成、复制、列表和撤销；生成结果使用页内弹窗展示，但不把令牌明文写入浏览器持久化存储。

## 11. 兼容性与数据保护

- 不迁移或修改现有 `teacher_accounts`、`teacher_sessions`、`student_accounts`、`student_sessions`。
- 不删除任何流程、实例、节点草稿、提交、文件或审核历史。
- 已有教师继续使用原工号和密码登录。
- 已有学生继续使用现有学生账号，学生公开注册行为保持不变。

## 12. 完成标准与验证边界

完成标准：

- 默认登录入口展示学生表单，教师入口为底部低强调度链接。
- 学生与教师页面均不再提供角色标签切换。
- 未持有有效邀请时无法通过 UI 或直接 API 创建教师账号。
- 有效邀请只能创建绑定姓名、绑定工号的一个普通教师账号。
- 邀请使用、过期或撤销后无法再次注册。
- 超级管理员可以生成、查看和撤销邀请。
- 旧登录地址按设计跳转，新旧教师账号登录不受影响。

按照项目约定，实施阶段只进行静态业务逻辑审计，不运行自动测试或浏览器自动操作。完成后以非 Docker 方式重启前后端，并核对 `5173`、`8000` 监听进程及工作目录；交付时明确说明验证边界。
