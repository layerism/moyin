# 流程画布方向键移动节点设计

## 目标

教师在流程画布选中一个或多个可移动节点后，可以使用键盘四个方向键按网格步长移动节点，减少精细调整布局时反复拖拽的成本。

## 交互规则

- `ArrowUp`：全部已选可移动节点上移 16px。
- `ArrowDown`：全部已选可移动节点下移 16px。
- `ArrowLeft`：全部已选可移动节点左移 16px。
- `ArrowRight`：全部已选可移动节点右移 16px。
- 单选时只移动当前节点；框选或 `Ctrl` 多选时保持节点之间的相对位置整体移动。
- 按住方向键时沿用浏览器键盘重复事件，可连续按 16px 步长移动。
- 处理成功的方向键调用 `preventDefault()`，避免页面随方向键滚动。

## 触发边界

仅在以下条件同时成立时处理方向键：

- 画布未锁定；
- 至少存在一个已选且 `canMoveNode(nodeId)` 为真的节点；
- 按键是四个无修饰方向键之一；
- 事件目标不位于 `input`、`textarea`、`select` 或可编辑内容区域。

当 `Ctrl`、`Alt`、`Meta`、`Shift` 中任一修饰键按下时不移动节点，不扩展加速或精细步长语义。

已发布修订中受保护的节点继续由 `canMoveNode` 排除。选择集合中若同时出现可移动和不可移动节点，只移动其中允许移动的节点；现有框选逻辑本身仍只选入可移动节点。

## 坐标和边界

方向键先形成固定的期望位移：

```ts
const directionDeltas = {
  ArrowUp: { x: 0, y: -16 },
  ArrowDown: { x: 0, y: 16 },
  ArrowLeft: { x: -16, y: 0 },
  ArrowRight: { x: 16, y: 0 },
};
```

节点初始坐标来自当前 `layoutNodes`。整组位移继续通过现有 `constrainCanvasGroupDelta(points, desiredDelta, canvasGridSize)` 约束，保证任一节点都不会越过画布左侧或顶部 16px 最小边界。

边界约束后的位移若为零，则不调用位置更新；否则一次生成全部目标坐标并只调用一次 `onUpdateNodePositions()`，保持节点相对位置和单次草稿更新语义。

## 组件边界

键盘监听放在 `FlowNodeCanvas` 内，通过 `window` 的 `keydown` 事件读取该组件已经维护的 `selectedNodeIds`、`layoutNodes`、`locked` 和 `canMoveNode`。

为保持主组件聚焦，方向键到位移的映射和“事件目标是否为编辑控件”的判断作为小型函数放入现有 `canvasPan.ts`，由画布组件调用。不新增后端接口、状态字段或持久化结构。

## 现有行为兼容

以下行为保持不变：

- 鼠标单选、`Ctrl` 多选和空白区域框选；
- 已选节点整体拖动与 16px 网格吸附；
- 连线创建和删除；
- 右键平移和 `Ctrl` 滚轮缩放；
- 双击打开节点设置；
- 节点位置通过现有批量回调写入流程草稿。

现有删除连线的键盘监听只处理 `Backspace` 和 `Delete`，与方向键监听没有按键冲突。

## 验证边界

按项目规范不运行测试和浏览器自动化。实施后进行静态业务逻辑审计，确认四个方向映射、批量移动、边界约束、锁定状态、编辑控件忽略和单次位置更新均闭环；运行 `git diff --check`，清理限定缓存，并以本地方式重启前后端服务。
