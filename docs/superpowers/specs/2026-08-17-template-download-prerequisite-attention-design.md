# 模板未下载时的上传引导设计

## 问题

确认承诺节点要求学生先下载模板，再上传签署后的扫描件。当前模板未下载时，扫描件文件输入被直接禁用；用户点击上传区域不会得到任何反馈，难以判断无法上传的原因。

## 目标

- 明确告诉用户必须先下载并填写模板。
- 将用户注意力引导至第 1 步“下载模板”。
- 不自动下载模板，不打开文件选择器，不使用模态弹窗。
- 不改变现有模板下载记录、上传接口和后端校验。

## 交互设计

模板尚未下载时，用户点击上传区、按键激活上传区或把文件拖入上传区：

1. 阻止文件选择和文件上传。
2. 第 1 步模板下载卡片执行一次约 320ms 的轻微水平振动，同时显示红色边框和浅红色外发光。
3. 上传区保持稳定，不执行振动。
4. 上传区下方显示红色就地提示：`请先下载并填写模板，再上传签署后的扫描件。`
5. 将键盘焦点移动到“下载模板”按钮，使用户可直接按回车继续。

红框与外发光显示约 600ms 后自动恢复为原有蓝色边框；用户成功下载模板后，就地提示与注意状态自动清除，上传区恢复正常文件选择和拖拽上传能力。

## 组件与状态边界

- `RuntimeNodeDialog` 继续以服务端返回的 `runtime.templateDownloaded` 作为模板是否已下载的事实来源。
- `ScanUploadWorkspace` 增加“因模板未下载而锁定”的交互语义和提醒回调，不自行判断模板业务状态，也不承担振动动画。
- 隐藏的文件输入在模板未下载时保持 `disabled`，避免通过文件选择入口绕过前置条件。
- 上传区外层保留点击、键盘和拖拽事件；锁定时只触发提醒，解锁后才触发文件选择或上传。
- 注意状态只属于当前节点弹窗，不写入后端，不影响草稿和已上传扫描件。
- 注意状态由独立定时器在约 600ms 后清除，不依赖 CSS `animationend`，确保减少动态效果模式下也能自动恢复。

## 视觉与无障碍

- 复用现有白色面板、蓝色主操作和红色错误语义，不增加新的颜色体系或弹窗组件。
- 第 1 步模板下载卡片的振动只播放一次，连续点击会重新计时并重播，不持续循环。
- 注意状态使用红色边框 `#ef4444` 和浅红色外发光 `0 0 0 3px rgb(239 68 68 / 18%)`，结束后恢复原有蓝色边框。
- 就地提示使用 `role="alert"`，上传区锁定时暴露 `aria-disabled="true"`。
- 上传区支持 Enter 和 Space 键触发相同提醒。
- 当系统启用 `prefers-reduced-motion: reduce` 时取消振动，红框与外发光仍显示约 600ms，并保留文字提示和焦点引导。

## 异常与边界情况

- 拖入多个文件时仍只显示一次提醒，不读取文件内容，也不调用上传 API。
- 模板下载失败时沿用现有下载错误处理；上传区继续保持锁定和提示能力。
- 节点处于忙碌状态时维持现有禁用逻辑，不把“处理中”误报为“模板未下载”。
- 模板已下载后，不再出现本设计中的前置条件提醒。

## 验收条件

1. 模板未下载时点击、键盘激活或拖拽到上传区，均不会打开文件选择器或调用上传 API。
2. 每次无效操作都会使第 1 步下载卡片轻微振动，并显示明确的就地提示；上传区自身不振动。
3. 第 1 步下载卡片显示红色边框和浅红色外发光约 600ms，“下载模板”按钮获得焦点。
4. 不自动触发模板下载。
5. 模板下载成功后提示消失，扫描件选择与拖拽上传恢复正常。
6. 减少动态效果模式下无振动，但红框、信息和焦点反馈完整，且红框会自动恢复。
