# 教务流程一键复制设计

## 目标

在教务流程列表中为每个流程提供明确的复制入口。用户必须为副本设置与原流程不同且唯一的名称。复制成功后得到一个未发布、无学生名单、无运行数据且所有节点可完整编辑的新流程。

## 复制边界

### 复制的内容

- 流程说明。
- 全部节点和连线，包括布局坐标。
- 表单字段、节点说明、起始时间和截止时间。
- 文件类型、大小限制等文件节点配置。
- 审核脚本的固定版本、配置哈希和参数。审核脚本属于教师可用的全局目录，副本继续引用同一固定版本。
- 已上传的学生填写模板。每个模板的 OSS 对象、资产记录和资产 ID 都必须为新副本，新旧流程不共用模板资产。

### 不复制的内容

- 学生名单，包括已撤销名单。
- 发布版本、版本号和版本模板关联。
- 分享令牌和学生链接。
- 学生流程实例、节点实例、草稿、提交、审核任务和上传文件。
- 个别截止时间覆盖和原流程的运行审计历史。

## 副本状态与可编辑性

新流程仅创建 `flows` 草稿记录、完整 `draft_config` 和独立模板资产：

- `status` 固定为 `draft`。
- 不创建 `flow_versions`，因此 `publishedVersionId` 为空、`publishedNodeIds` 为空数组。
- 没有历史已发布节点，所有节点的标题、说明、类型配置、模板、位置和连线均可编辑或删除。
- 节点与连线内部标识保持不变。它们均按流程范围使用，不需要为副本重新映射。

## 名称规则

- 复制弹窗默认填入“`<原流程名> - 副本`”并自动选中。
- 名称去除首尾空格后不能为空，长度不超过 120 个字符。
- 新名称不能与原流程名称相同，也不能与当前教师其他未归档流程重名。
- 前端先做即时校验，后端在事务边界内做最终校验。

## 后端架构

增加专用端点：

```text
POST /api/workflows/{flow_id}/clone
{ "name": "新流程名" }
```

端点仅允许流程所属教师调用，成功时返回完整新流程对象，字段与列表接口中的单个流程一致。

复制步骤：

1. 核验来源流程归属、状态和新名称。
2. 从来源 `flows.draft_config` 读取当前服务端可编辑蓝图。列表不能观察到已被放弃的前端本地临时改动，这些改动不在复制范围内。
3. 读取配置中每个 `templateAsset.assetId` 对应的来源资产，校验其属于来源流程和对应节点。
4. 将源 OSS 对象复制到以新流程 ID 为路径的新对象键，并收集已创建的对象键用于失败补偿。
5. 模板全部复制成功后，在一个数据库事务中创建新 `flows` 记录、新 `flow_template_assets` 记录，并将草稿配置中的模板资产 ID 替换为新 ID。
6. 写入 `workflow_cloned` 审计日志，`before_data` 记录来源流程 ID，`after_data` 记录新流程 ID 和名称。

OSS 复制中途失败时，尽力删除已复制对象且不写入数据库。数据库事务失败时回滚元数据，并尽力删除已复制 OSS 对象。因 OSS 与 SQLite 不共享事务，这是补偿式原子性；清理失败应写入错误日志，但不能将残缺副本返回为成功。

## 错误语义

- `404`：来源流程不存在、已归档或不属于当前教师。
- `409`：新名称与原流程相同或与其他未归档流程重名。
- `422`：新名称为空或超出长度限制。
- `502`：模板 OSS 对象复制失败。原流程保持不变，不返回新流程。

## 列表交互

### 复制入口

每条流程右侧增加独立“复制”按钮，使用双层方框图标和文字。按钮使用明确边框、浅背景和轻微阴影；悬停时上移 `1px` 并加深边框和阴影。删除按钮保持独立，不使用更多菜单或悬浮操作组。

### 命名弹窗

使用专用复制弹窗，而非通用单行命名弹窗。弹窗包含：

- “复制流程”标题和双层方框图标。
- 来源流程卡片，展示原名称和当前发布状态。
- 数据边界说明：“将复制：节点、连线、规则、模板”与“不会复制：学生名单、发布状态、填写数据”。
- 自动选中的名称输入框。
- “取消”和“创建流程副本”按钮。

复制期间禁用关闭、取消和重复提交，主按钮文案变为“正在复制模板…”。

### 成功确认

复制成功后不直接跳转，而是将同一弹窗切换为成功状态：

- 展示绿色完成图标、新流程名称和“未发布 · 可完整编辑”。
- “留在流程列表”关闭弹窗，新流程保持置顶并短暂高亮。
- “进入编辑”跳转到新流程设计器。

弹窗在非复制阶段支持 Escape、遮罩关闭、Enter 提交和关闭后焦点回归触发按钮。所有图标按钮必须有可读 `aria-label`，状态和错误使用 `aria-live` 或 `role="alert"` 通知。

## 前端数据流

1. `AcademicFlowView` 保存当前复制源、名称、校验错误、提交状态和复制结果。
2. 前端通过 `workflowApi.cloneFlow(flowId, name)` 调用专用后端端点。
3. `App` 将返回的服务端流程映射为 `AcademicProcess`，插入列表首位，并将新流程 ID 返回弹窗。
4. 成功确认的“进入编辑”使用现有 `onOpenProcess` 导航；“留在流程列表”仅关闭弹窗。

## 审计与可观测性

成功复制时写入 `workflow_cloned` 审计日志，实体 ID 为新流程 ID。`before_data` 仅记录来源：

```json
{
  "sourceFlowId": "source-id"
}
```

`after_data` 记录副本结果：

```json
{
  "newFlowId": "clone-id",
  "newName": "新流程名",
  "templateCount": 2
}
```

补偿删除失败应通过服务器日志记录具体对象键和异常，不向前端暴露 OSS 存储键。

## 验证边界

补充但不运行以下测试代码：

- 普通流程复制后，新流程配置与来源一致，但状态为草稿且无版本、名单、分享令牌和实例。
- 名称与来源相同、与现有流程重名、来源不属于当前教师时被拒绝。
- 模板资产产生新 ID 和新 OSS 对象键，草稿配置引用新资产，原资产不变。
- OSS 复制失败时不创建流程，已复制对象会触发补偿删除。
- 前端命名校验、成功状态和新流程列表置顶使用纯逻辑测试覆盖。

按项目约定，开发阶段不运行自动化测试、构建或浏览器验证，仅进行业务逻辑和静态差异审计，最终由用户手动验证交互与真实 OSS 复制行为。
