# 预览前强制暂存设计

## 背景

教师端流程预览由后端根据 `flows.draft_config` 创建临时版本和运行实例。当前前端在存在未暂存修改时只提示教师先暂存并终止预览，导致预览操作需要额外点击一次“暂存”。

## 目标

点击“预览”时，无论当前页面是否存在未暂存修改，均先调用既有流程暂存接口。只有暂存成功后，才创建预览并跳转到预览页面，确保预览内容来自刚刚持久化的当前工作副本。

## 交互流程

1. 用户点击“预览”。
2. 前端同步打开空白标签页，避免异步暂存完成后被浏览器判定为非用户触发弹窗。
3. 若空白标签页被浏览器阻止，则显示“请允许本站打开新标签页”，不执行暂存和预览创建。
4. 成功打开空白标签页后，前端强制调用现有 `saveWorkingDraft(workingProcess, "")`。
5. 暂存成功后，调用现有预览创建接口，将预览令牌写入新标签页的 `sessionStorage`，再跳转至后端返回的预览地址。
6. 暂存或预览创建失败时关闭空白标签页，停留在当前设计器并显示既有错误信息。

## 状态与并发

- 整个“暂存后创建预览”过程使用现有预览创建状态锁定相关操作，防止重复点击和并发保存。
- 复用现有暂存逻辑更新全局流程状态、工作副本和 `revisionDirty`，不新增第二套保存状态。
- 暂存成功不显示中间成功提示，避免在即将跳转预览时产生无意义反馈。

## 变更范围

- 仅调整 `AcademicFlowDesigner.tsx` 中 `openPreview` 的调用顺序和失败处理。
- 不修改后端接口、数据库结构、预览会话隔离规则或发布逻辑。
- 不改变独立“暂存”按钮的行为。

## 验收条件

- 有未暂存修改时，点击“预览”会先保存当前工作副本，再展示包含这些修改的预览。
- 无未暂存修改时，点击“预览”仍会执行一次暂存，再创建预览。
- 暂存失败时不调用预览创建接口，不跳转，并关闭已打开的空白标签页。
- 浏览器阻止新标签页时不执行暂存或预览创建。
- 预览创建失败时保持现有错误提示和空白标签页关闭行为。
