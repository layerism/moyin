# 教师端学生填写进度轻量管理设计

> 状态：交互方案 A 已确认。本文定义最小范围改动，不表示功能已经实现。

## 1. 目标

在现有“学生填写进度”侧栏基础上增加以下能力：

1. 教师可以下载指定节点全部学生的当前材料；
2. 教师可以下载全部材料节点的当前材料，并按流程节点层次整理；
3. 教师查看单个学生的单个节点时，可以下载该节点全部材料；
4. 教师可以对已提交材料的节点人工审核通过；
5. 保留现有单个学生节点延期功能；
6. 页面适当加宽，以容纳新增按钮，但不改变现有表格和弹窗的主要结构。

本设计不重做教师进度页面，不增加学生详情抽屉、复杂筛选、复选框、跨页选择或下载任务中心。

## 2. 现有交互保留

继续保留当前页面结构：

- 右侧覆盖式管理侧栏；
- “学生、状态、完成、逾期、最后活动、操作”六列表格；
- 每名学生的“设置延期”按钮；
- 每个已提交扫描节点的“查看扫描件 · 节点名称”按钮；
- 现有节点延期弹窗；
- 现有扫描件提交详情弹窗及逐文件下载链接。

学生进度列表仍只展示已创建正式运行实例的学生。本次不扩展到尚未进入流程的名单学生。

## 3. 页面布局

### 3.1 侧栏宽度

将 `.teacher-progress-panel` 宽度从：

```css
width: min(760px, 94vw);
```

调整为：

```css
width: min(1100px, 96vw);
```

其余背景、阴影、边框、圆角、表格间距和按钮视觉继续使用项目现有样式。

### 3.2 批量下载工具栏

在页面标题和进度表之间增加一行工具栏：

```text
下载范围：[实习安全责任书                         ▼]
          [下载材料]
```

工具栏规则：

- 下拉框第一项为“全部节点（按层级整理）”，其后只列出流程中能够产生上传材料的节点；
- 默认选择“全部节点（按层级整理）”；
- 流程不存在材料节点时不显示工具栏；
- 下载期间按钮显示“正在打包…”，并禁止重复点击；
- 下载完成或失败后按钮恢复；
- 工具栏不承担筛选学生、选择提交批次或查看下载历史的功能。

### 3.3 表格操作区

表格列保持不变，仅利用增加后的宽度容纳原有按钮：

```text
学生       状态    完成    逾期    最后活动          操作
张三       进行中  4/6     1       8月19日 14:20    [设置延期]
                                                    [查看扫描件 · 责任书]
```

不在每一行新增节点选择器，也不把人工通过直接放到主表，避免操作区变得拥挤。

## 4. 单个学生、单个节点操作

点击“查看扫描件 · 节点名称”后，继续打开现有扫描件提交详情弹窗。弹窗增加两个操作：

1. “下载本节点全部材料”；
2. “人工审核通过”。

弹窗保留逐文件下载，因此教师可以选择：

- 下载一个具体文件；
- 下载该学生在当前节点的全部文件；
- 核验材料后人工通过。

### 4.1 下载本节点全部材料

- 只下载该节点当前有效提交关联的材料；
- 不包含草稿文件、已取消提交或历史 attempt；
- 一个文件也统一返回 ZIP，保持按钮行为一致；
- ZIP 名称：`学号-姓名-节点名称.zip`；
- ZIP 内保留学生上传时的原始文件名；
- 同名文件追加 `(2)`、`(3)`，避免覆盖。

### 4.2 人工审核通过资格

人工通过必须同时满足：

- 当前节点存在提交记录；
- 提交 `attempt_no` 等于节点当前 `attempt_no`；
- 当前提交至少关联一个上传文件；
- 节点状态为 `reviewing`、`rejected` 或 `audit_error`；
- 当前教师拥有该流程；
- 节点尚未通过。

未提交、已取消、锁定、待提交、逾期或已通过节点不显示人工通过按钮。

### 4.3 人工通过确认

教师点击“人工审核通过”后显示确认弹窗：

```text
人工审核通过

学生：张三（202301）
节点：实习安全责任书
当前状态：AI 未通过
材料：2 个文件

人工审核备注：[材料已人工核验，签字和日期完整]

确认后将按审核通过处理，并开放后续节点。
                           [取消] [确认人工通过]
```

人工审核备注必填，长度为 1–500 个字符。备注只写入现有 `audit_logs.reason`，不作为学生端审核原因。

## 5. 指定节点与全部节点批量下载

### 5.1 材料范围

批量包只包含下载范围内各学生的当前有效提交：

- `submissions.attempt_no = node_instances.attempt_no`；
- 提交状态属于 `reviewing`、`approved`、`rejected` 或 `audit_error`；
- `uploaded_files.submission_id` 指向该提交。

以下内容不进入批量包：

- 学生草稿和未提交暂存文件；
- `cancelled` 提交；
- 历史 attempt；
- 指定节点下载时，其他节点的材料；
- 教师预览实例的数据。

没有当前材料的学生直接跳过，不创建空目录。

### 5.2 指定节点 ZIP 结构

```text
实习安全责任书/
  202301-张三/
    实习安全责任书.pdf
  202302-李四/
    实习安全责任书.png
```

流程、节点、学号、姓名和文件名必须过滤路径分隔符、控制字符和 `..`。所有 ZIP 条目使用相对路径，防止路径穿越。

ZIP 文件名：

```text
流程名称-节点名称-材料.zip
```

### 5.3 全部节点 ZIP 结构

“全部节点”按照发布版本 `config_snapshot.nodes` 中的稳定顺序编号，只包含能够产生上传材料的节点：

```text
流程名称/
  01-实习安全责任书/
    202301-张三/
      实习安全责任书.pdf
  02-实习总结材料/
    202301-张三/
      实习总结.docx
    202302-李四/
      实习总结.pdf
```

没有当前材料的学生和节点均不创建空目录。ZIP 文件名：

```text
流程名称-全部节点材料.zip
```

### 5.4 直接下载，不建立任务系统

本功能使用一次普通下载请求：

```text
教师点击批量下载
  → 后端校验流程、版本、节点和教师归属
  → 查询当前有效提交及文件
  → 在独立临时目录下载 OSS 文件
  → 生成 ZIP
  → 直接返回文件响应
  → 响应结束后清理临时目录
```

不新增：

- 导出任务数据表；
- 独立材料导出 Worker；
- 下载任务中心；
- 下载历史和断点恢复。

服务重启、请求中断或打包失败时，本次下载失败，教师重新点击即可。

## 6. 人工通过与 AI 通过使用相同结果

人工通过不新增独立业务表，也不给 `audit_jobs` 增加字段。后端在一个 SQLite 写事务内：

1. 重新校验教师归属、当前提交、材料数量和节点状态；
2. 将对应 `audit_jobs.status` 更新为 `succeeded`；
3. 使用标准审核结果覆盖 `audit_jobs.result_json`；
4. 清除 `error_message` 和 `cancellation_reason`；
5. 将 `submissions.status` 更新为 `approved`；
6. 将 `node_instances.status` 更新为 `approved`，写入 `approved_at`；
7. 调用现有 `advance_downstream()`；
8. 调用现有 `complete_flow_if_ready()`；
9. 写入现有 `audit_logs`。

人工结果为：

```json
{
  "schemaVersion": "1.0",
  "passed": true,
  "reason": "经由人工审核通过",
  "details": {
    "reviewSource": "manual",
    "reviewerId": 12,
    "reviewedAt": "2026-08-19T16:30:00+08:00"
  }
}
```

覆盖规则：

- AI 审核中：人工通过后通知当前审核子进程停止；
- AI 未通过：删除旧的不通过理由，以人工通过结果替代；
- AI 评分：删除旧评分，不伪造 100 分，最终显示“经由人工审核通过”；
- AI 审核异常：清除错误信息，以人工通过结果替代；
- AI 子进程稍后返回时，因为任务已不是 `running`，不得覆盖人工结果。

人工审核备注只保存在 `audit_logs.reason`。`audit_logs` 不保存被覆盖的 AI 不通过理由或旧评分。

## 7. 延期

延期交互保持现状：

- 从学生行点击“设置延期”；
- 在原弹窗选择节点；
- 显示当前生效截止时间；
- 设置更晚的新截止时间；
- 填写延期原因；
- 写入现有 `student_deadline_overrides` 和 `audit_logs`。

延期只适用于已经有生效截止时间的节点，新时间必须晚于当前时间和当前生效截止时间。无截止时间的节点不能通过此入口新增个人截止时间。

## 8. 接口

继续使用现有接口：

```http
GET /api/workflow-admin/versions/{version_id}/progress
GET /api/workflow-admin/node-instances/{node_instance_id}/submission-detail
PUT /api/workflow-admin/instances/{instance_id}/nodes/{node_key}/deadline
```

新增：

```http
GET  /api/workflow-admin/versions/{version_id}/materials/download?nodeKey={node_key}
GET  /api/workflow-admin/node-instances/{node_instance_id}/materials/download
POST /api/workflow-admin/node-instances/{node_instance_id}/manual-approve
```

人工通过请求：

```json
{
  "submissionId": "当前有效提交 ID",
  "reason": "材料已人工核验，签字和日期完整"
}
```

`submissionId` 用于防止旧页面覆盖学生的新提交。如果当前提交已经变化，返回 `409` 并刷新提交详情。

下载接口直接返回 ZIP 文件，不返回 OSS 永久地址。后端必须按当前教师重新解析文件归属，不能信任浏览器传入的学生、提交或 OSS 对象键。

## 9. 数据库

本设计不新增数据表，也不修改现有表结构。

复用：

- `audit_jobs`：保存 AI 或人工最终审核结果；
- `submissions`：保存当前提交状态；
- `node_instances`：保存节点状态和通过时间；
- `uploaded_files`：定位当前提交材料；
- `student_deadline_overrides`：保存延期；
- `audit_logs`：保存人工操作人、时间、状态变化和备注。

因此不再增加原设计中的：

- `submission_manual_reviews`；
- `material_export_jobs`；
- `material_export_items`。

## 11. 错误处理

- 所选节点没有任何当前材料：返回“该节点暂无可下载材料”；
- 单个学生节点没有材料：禁用“下载本节点全部材料”和“人工审核通过”；
- OSS 文件下载失败：本次 ZIP 下载失败，清理临时目录并返回明确错误；
- 人工通过时提交已变化：返回 `409`，前端重新读取详情；
- 人工通过时 AI 已经通过：直接刷新为已通过，不重复写入；
- 教师无权访问流程或文件：返回 `404`，避免泄露资源存在性；
- 浏览器取消下载：后端结束后清理临时文件，不保留导出记录。

## 12. 非目标

- 不增加学生详情抽屉；
- 不改变现有进度表列结构；
- 不增加进度筛选、分页或跨页选择；
- 不支持选择部分学生批量下载；
- 不支持任意勾选多个节点下载；“全部节点”是固定范围；
- 不支持批量人工通过或批量延期；
- 不支持撤销人工通过；
- 不保存下载任务和下载历史；
- 不引入 Redis、Celery 或新的 Worker。

## 13. 验收标准

1. 进度侧栏加宽后，现有表格和操作按钮不再因新增功能明显拥挤。
2. 教师能从顶部选择一个材料节点并下载该节点全部学生的当前材料。
3. 教师能选择“全部节点”，并获得按流程、节点、学生分层整理的 ZIP。
4. 批量 ZIP 只包含下载范围内的当前有效提交和正式学生实例。
5. 教师能在扫描件详情中逐文件下载或下载该学生当前节点的全部材料。
6. 只有存在当前材料且状态允许的节点显示人工通过按钮。
7. 人工通过与 AI 通过使用相同的 `audit_jobs.result_json`，最终原因显示“经由人工审核通过”。
8. AI 不通过理由、旧评分和审核异常在人工通过后不再出现在当前结果中。
9. 人工通过能正常开放下游节点，运行中的旧 AI 结果不能覆盖人工结果。
10. 现有延期弹窗及其业务规则保持不变。
11. 整项功能不新增数据表、不新增导出任务系统，也不改变学生端交互。
