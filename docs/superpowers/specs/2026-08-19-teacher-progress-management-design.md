# 教师端学生填写进度管理设计

> 状态：设计已确认，等待用户审阅文档。本文只定义交互、业务规则和技术边界，不表示功能已经实现。

## 1. 背景

现有“学生填写进度”以学生汇总表为中心，已经支持查看总体完成数、设置个别节点延期，以及查看部分扫描件提交详情。当前交互存在以下不足：

- 单行同时堆放延期和多个扫描件按钮，流程节点增多后操作区失控；
- 不能从一名学生的视角连续查看全部节点、提交和审核状态；
- 教师不能在核验真实提交材料后覆盖 AI 结论；
- 教师只能逐个下载文件，不能按学生、节点或筛选结果批量归档；
- 当前进度接口只返回已经创建运行实例的学生，未进入流程的名单学生不可见。

本设计把该入口升级为教师运行管理面板，在不改变学生端交互的前提下，集中提供学生进度查询、节点延期、人工通过、单项下载和批量下载。

## 2. 已确认的业务决策

1. 人工通过必须绑定当前有效提交及其真实材料，不能让未提交、锁定或未开始的节点直接通过。
2. 人工通过只适用于当前有效提交状态为 `reviewing`、`rejected` 或 `audit_error` 的节点。
3. 延期只适用于已经存在生效截止时间的节点，只能向后延长，不能创建新的个人截止时间、提前截止或清除截止时间。
4. 批量下载支持三种范围：当前学生全部材料、当前节点全部学生材料、当前筛选或勾选范围内的材料。
5. 批量下载只包含每个节点当前有效提交的材料；历史提交只能在详情中单独查看和下载。
6. 人工通过和延期不提供批量操作，批量能力仅用于材料下载。
7. 教师预览不进入正式进度统计、人工通过或材料归档范围。

## 3. 方案选择

### 3.1 采用：学生主视图与详情抽屉

主表一行对应一名名单学生，适合教师发现异常后按学生连续处理。点击学生后，在同一管理面板右侧展开该学生的全部节点详情；节点筛选又能把主表转换为某一节点的集中处理视图。

该方案兼顾两种主要场景：

- 辅导学生时，查看一名学生的全部流程进度；
- 集中收材料时，筛选一个节点下所有待审核、未通过或逾期学生。

### 3.2 不采用：纯节点主视图

节点主视图适合集中审核一项材料，但教师无法快速理解单个学生的完整进度，需要反复切换节点。

### 3.3 不采用：学生乘节点矩阵

矩阵能紧凑展示状态，但节点较多时产生大规模横向滚动，材料、延期和人工审核操作也无法在单元格内保持清晰。

## 4. 页面信息架构

现有右侧面板从 `760px` 扩展为宽管理面板，建议宽度为 `min(1180px, 96vw)`，继续覆盖在流程设计器之上，避免教师丢失当前流程上下文。

```text
┌ 学生填写进度 ───────────────────────────── 下载任务(1)  × ┐
│ 全部 358  已完成 126  进行中 214  存在异常 18             │
│ [姓名/学号] [全部节点] [状态] [材料] [仅看异常] [查询]    │
│                                                          │
│ □ 学号    姓名    完成    异常      最后活动      操作    │
│ □ 202301  张三    4/6     1 项逾期  8月19日       详情    │
│ □ 202302  李四    5/6     审核异常  8月18日       详情    │
│                                                          │
│ 已选择 2 名学生                    [下载所选当前材料]     │
└──────────────────────────────────────────────────────────┘
```

### 4.1 名单范围

主表以流程当前有效名单为基准，而不是只查询 `flow_instances`：

- 已进入流程的学生显示当前发布版本的运行实例和节点进度；
- 尚未进入流程的学生显示“未进入”，不创建运行实例，也不提供延期、人工通过或材料下载；
- 已撤销名单授权的学生不出现在默认列表，历史数据仍由数据库保留；
- 教师查看旧发布版本时，仅展示实际绑定该版本的实例，避免把当前名单误认为旧版本参与者。

名单懒创建原则保持不变：教师查看进度不得代替学生创建运行实例。

### 4.2 筛选器

未选择具体节点时提供：

- 姓名或学号搜索；
- 学生总体状态：全部、未进入、进行中、已完成；
- 是否存在异常：逾期、未通过、审核异常；
- 是否存在当前有效材料。

选择具体节点后，增加该节点的状态筛选：

- 未开始：`locked`、`scheduled`；
- 待提交：`available`、`draft`、`expired`；
- 审核中：`reviewing`；
- 未通过：`rejected`；
- 审核异常：`audit_error`；
- 已通过：`approved`。

筛选和分页由服务端执行。筛选条件改变后清空原选择，避免下载不可见范围。

### 4.3 跨页选择

主表复选框的选择单位是学生：

```text
已选择当前页 50 名学生
[选择全部 326 条筛选结果]
```

- “当前页全选”只选择可见学生；
- “选择全部筛选结果”保存当前筛选表达式，由后端重新解析，不把大量学生 ID 全部传回浏览器；
- 选择具体节点时，批量包只包含该节点当前有效材料；
- 未选择节点时，批量包包含所选学生全部节点的当前有效材料。

## 5. 学生详情抽屉

点击表格行或“详情”后，在管理面板右侧展开详情抽屉。桌面端保留左侧列表，移动端以详情替换列表，并显示返回箭头。

抽屉头部显示：

- 姓名、学号和总体完成数；
- 当前异常数量和最后活动时间；
- “下载该生全部材料”快捷操作。

节点按流程顺序展示，每个节点卡片包含：

- 标题与当前业务状态；
- 全局截止时间、个人延期时间和当前生效时间；
- 当前有效提交时间和提交批次；
- 当前材料数量、页数、总大小；
- AI 审核模式、任务状态、评分、结论或异常原因；
- 人工通过记录及教师意见；
- 根据资格显示“设置延期”“查看材料”“下载材料”“人工通过”。

主表行不再堆放多个节点按钮，所有节点级高风险操作集中在详情抽屉。

## 6. 节点延期

### 6.1 可操作范围

节点必须已经有当前生效截止时间。允许状态包括 `locked`、`scheduled`、`available`、`draft`、`reviewing`、`rejected`、`audit_error` 和 `expired`。

- 已通过表单节点可延期，以继续支持截止前修改；
- 已通过的文件或确认节点不允许延期，因为其内容已锁定，延长时间不会产生实际业务效果；
- 没有原始截止时间的节点不允许通过此入口新增个人截止时间。

### 6.2 交互

弹窗显示学生、节点、全局截止时间、已有个人延期和当前生效截止时间。教师填写新的截止时间和延期原因。

请求携带页面读取到的 `expectedEffectiveDeadline`。后端必须重新校验：

1. 教师拥有该流程；
2. 节点属于该学生当前发布实例；
3. 节点仍有截止时间且当前生效时间未变化；
4. 新时间晚于服务器当前时间和当前生效截止时间；
5. 节点状态仍允许延期。

截止时间已被其他操作修改时返回 `409`，前端刷新详情，不覆盖新值。保存成功后直接更新截止时间和状态；`expired` 节点按现有前驱、开始时间和草稿情况恢复为 `available`、`draft`、`scheduled` 或 `locked`。

延期继续写入 `student_deadline_overrides` 和 `audit_logs`。

## 7. 人工通过

### 7.1 资格规则

必须同时满足：

- 节点存在 `submission_id`，且该提交的 `attempt_no` 等于节点当前 `attempt_no`；
- 当前提交至少关联一个材料文件；
- 提交未被取消，节点状态属于 `reviewing`、`rejected` 或 `audit_error`；
- 教师拥有对应流程，且发布版本仍有效；
- 节点尚未被人工通过。

未提交、已取消、锁定、待提交、已逾期或已通过节点均不显示人工通过按钮。

### 7.2 确认交互

教师必须先进入提交详情查看材料，再执行人工通过。确认弹窗显示：

```text
人工通过确认

学生：张三（202301）
节点：确认承诺
提交时间：2026-08-19 14:20
材料：2 个文件
当前状态：AI 审核中

通过原因：[材料已人工核验，签字和日期完整]

确认后将终止本次 AI 审核，并开放后续节点。
                              [取消] [确认人工通过]
```

原因必填，长度为 1–500 个字符。第一阶段不提供撤销人工通过，因为下游节点可能已被开放或完成，直接撤销会产生级联回滚歧义。

### 7.3 事务规则

请求携带当前 `submissionId` 作为乐观并发令牌。后端在一个 SQLite 写事务内：

1. 校验教师归属、当前提交批次、节点状态和材料数量；
2. 对 `pending` 或 `running` 审核任务设置 `cancelled/manual_approved`；
3. 已经 `succeeded` 或 `failed` 的审核任务及其原始结果保持不变，作为历史证据；
4. 新增 `submission_manual_reviews` 记录；
5. 把当前 `submissions.status` 和 `node_instances.status` 改为 `approved`，写入 `approved_at`；
6. 调用统一的下游推进和流程完成判断；
7. 写入审计日志。

事务提交后通知本进程取消注册表，终止仍在运行的相关审核子进程。即使子进程未及时停止，审核任务状态和节点状态的条件写入也必须阻止旧 AI 结果覆盖人工结论。

如果 AI 在教师确认前已经改变节点状态，接口返回 `409` 并要求刷新。人工通过评分模式的节点时不伪造分数；原 AI 分数仍作为原始审核结果保存，最终结论显示“人工通过”。

### 7.4 人工审核记录

新增表：

```text
submission_manual_reviews
  id                PRIMARY KEY
  submission_id     UNIQUE, FOREIGN KEY
  node_instance_id  FOREIGN KEY
  reviewer_id       FOREIGN KEY teacher_accounts
  decision          固定为 approved
  reason
  reviewed_at
```

独立记录用于区分 AI 结果与最终人工结论，不能只依赖一条自由文本审计日志恢复业务状态。

## 8. 材料查看与单项下载

提交详情只展示当前有效提交，历史提交放在折叠的“历史提交”区域。默认批量操作不选择历史材料。

每个文件显示原始文件名、类型、大小、页数和上传时间，并提供单文件下载；扫描件组同时提供“下载本节点全部材料”。材料列表内可勾选若干文件进行小范围下载。

教师下载必须使用独立管理端接口。后端重新校验文件所属流程、版本和教师，不复用只接受学生身份的下载接口，也不直接返回永久 OSS 地址。单项下载仍返回短期 OSS 签名地址。

## 9. 批量下载

### 9.1 下载入口

提供三个快捷入口：

1. 学生详情：“下载该生全部材料”；
2. 选中节点：“下载当前节点全部学生材料”；
3. 主表批量栏：“下载所选或全部筛选结果的当前材料”。

创建任务前显示预计学生数、文件数和未压缩总大小。材料数为零时禁用确认按钮。

### 9.2 当前有效材料定义

批量包只选择：

- `submissions.attempt_no = node_instances.attempt_no`；
- 提交状态属于 `reviewing`、`approved`、`rejected` 或 `audit_error`；
- 文件已经关联该提交。

`cancelled` 提交、草稿暂存文件和历史 attempt 不进入批量包。

### 9.3 ZIP 目录

```text
2023级毕业实习材料/
  材料清单.csv
  实习安全责任书/
    202301-张三/
      实习安全责任书.pdf
    202302-李四/
      实习安全责任书.png
  实习申请表/
    202301-张三/
      实习申请表.docx
```

规则：

- 保留学生上传时的原始文件名；
- 流程、节点、学号、姓名和文件名必须过滤路径分隔符、控制字符与 `..`；
- 同一目录重名文件追加 `(2)`、`(3)`；
- ZIP 条目只使用相对路径，防止路径穿越；
- `材料清单.csv` 使用 UTF-8 BOM，记录学号、姓名、节点、提交时间、文件名、大小、审核状态、审核方式、打包结果和失败原因；
- 单个文件读取失败时继续打包其他文件，任务完成为 `completed_with_warnings`；全部文件失败时任务为 `failed`。

### 9.4 异步导出

批量下载不得在创建任务的 HTTP 请求中逐个下载和压缩。新增持久化任务：

```text
material_export_jobs
  id
  flow_id
  flow_version_id
  teacher_id
  scope_json
  status              pending | running | completed | completed_with_warnings | failed | expired
  total_files
  processed_files
  failed_files
  total_bytes
  output_storage_key
  output_size_bytes
  error_message
  expires_at
  created_at
  started_at
  finished_at

material_export_items
  id
  job_id
  uploaded_file_id
  storage_key
  original_name
  size_bytes
  student_no
  student_name
  node_key
  node_title
  submitted_at
  status              pending | completed | failed
  error_message
```

创建任务时，后端根据教师权限、版本、筛选表达式和当前有效提交生成不可变导出快照。浏览器不能提交 OSS 地址或任意对象键。

导出使用独立材料导出 Worker，默认单进程内一个线程，不占用 AI 审核 Worker。Worker 把 OSS 文件下载到独立临时目录，顺序写入 ZIP，上传到受控临时 OSS 前缀后删除本地临时文件。

默认单任务上限为 5,000 个文件或 10 GiB 未压缩材料，任一超限时拒绝创建并要求缩小筛选范围。上限通过后端配置管理，不在前端接受任意覆盖。

ZIP 下载地址有效期 24 小时。到期后状态转为 `expired`，教师可基于当前条件重新生成，不复用过期签名地址。

### 9.5 任务恢复

服务启动时把遗留 `running` 导出任务恢复为 `pending`。导出条目拥有逐文件状态，Worker 可以从尚未完成的条目继续读取；ZIP 必须重新生成，不能续写未知完整性的旧临时文件。

同一教师默认只允许一个 `pending/running` 导出任务，防止重复点击占满磁盘和 OSS 带宽。其他教师任务按创建时间排队。

## 10. API 设计

### 10.1 进度与详情

```http
GET /api/workflow-admin/versions/{version_id}/progress
GET /api/workflow-admin/instances/{instance_id}/progress-detail
GET /api/workflow-admin/node-instances/{node_instance_id}/submissions
```

进度接口支持 `query`、`nodeKey`、`studentStatus`、`nodeStatus`、`hasMaterial`、`onlyException`、`page` 和 `pageSize`。响应包含总数和各状态汇总，不再一次返回每名学生的全部节点。

详情接口按需返回一名学生的节点列表。提交历史接口只在教师展开历史区域时加载。

### 10.2 延期与人工通过

```http
PUT  /api/workflow-admin/instances/{instance_id}/nodes/{node_key}/deadline
POST /api/workflow-admin/node-instances/{node_instance_id}/manual-approve
```

延期请求：

```json
{
  "expectedEffectiveDeadline": "2026-08-20T10:00:00+00:00",
  "deadlineAt": "2026-08-27T10:00:00+00:00",
  "reason": "批准个别延期"
}
```

人工通过请求：

```json
{
  "submissionId": "当前有效提交 ID",
  "reason": "材料已人工核验，签字和日期完整"
}
```

### 10.3 下载与导出

```http
GET  /api/workflow-admin/files/{file_id}/download
POST /api/workflow-admin/versions/{version_id}/material-exports
GET  /api/workflow-admin/material-exports/{job_id}
GET  /api/workflow-admin/material-exports/{job_id}/download
POST /api/workflow-admin/material-exports/{job_id}/regenerate
```

批量导出请求使用互斥作用域：

- `student`：一个运行实例；
- `node`：一个节点及当前筛选；
- `selectedStudents`：明确的实例 ID 集合；
- `filteredStudents`：服务端可重放的筛选表达式。

后端模型禁止额外字段，并为每种作用域重新校验流程和教师归属。

## 11. 状态反馈与错误处理

- 进度读取失败：在表格区域显示错误和“重新读取”，保留教师已输入的筛选条件；
- 延期冲突：提示“截止时间已变化”，刷新该节点；
- 人工通过冲突：保持详情打开，提示“提交或审核状态已变化”，刷新当前提交；
- 单文件下载失败：仅反馈该文件，不关闭提交详情；
- 导出部分失败：显示“已完成，存在异常”，下载包中的材料清单列出失败项；
- 导出全部失败：保留任务记录与可读原因，允许重新生成；
- 导出地址过期：不返回旧签名地址，显示“已过期，可重新生成”；
- 权限失效：详情、延期、人工通过和下载均由后端拒绝，前端退出当前详情并刷新列表。

管理面板头部提供“下载任务”入口。任务可以在后台继续，教师关闭进度面板后再次进入仍能查看进度。页面不使用阻塞式轮询；任务运行时按有限间隔刷新，完成或失败后停止。

## 12. 权限与安全

- 所有操作以当前教师身份和 `flows.owner_id` 为最终授权边界；
- 不信任浏览器传入的学生、提交、文件、节点、版本或 OSS 对象归属；
- 单项和批量下载都只返回短期签名地址，不记录签名 URL；
- ZIP 文件名和条目路径严格规范化；
- 导出临时目录按任务隔离，完成或失败后清理；
- 审计日志不记录材料内容，只记录教师、流程、学生、节点、提交、动作、原因和时间；
- 人工审核记录不可通过普通管理接口编辑或删除。

## 13. 可访问性与视觉规范

- 继续使用项目既有白色面板、灰色边框、蓝色主操作和红色错误语义；
- 状态不仅依赖颜色，同时显示文字；人工通过使用绿色状态标签；
- 所有弹窗具备明确标题、焦点圈定、`Escape` 关闭和关闭后的焦点恢复；
- 高风险人工通过需要独立确认弹窗，主按钮文案为“确认人工通过”；
- 表格、筛选器、详情抽屉和下载任务均支持键盘操作；
- 移动端详情替换列表，不能把桌面双栏压缩成不可读的窄列。

## 14. 非目标

- 不支持批量人工通过；
- 不支持批量延期；
- 不支持撤销人工通过或级联回滚下游；
- 不把历史提交混入默认批量下载；
- 不允许教师修改、删除或替换学生上传的材料；
- 不在本阶段生成材料内容预览或在线编辑器；
- 不引入 Redis、Celery 或外部消息队列。

## 15. 验收标准

1. 当前名单中的未进入学生能够显示为“未进入”，且查看进度不会创建运行实例。
2. 教师可从学生主表进入一名学生的完整节点详情，不再在表格行堆放节点按钮。
3. 只有存在当前有效材料且状态为 `reviewing`、`rejected` 或 `audit_error` 的节点能人工通过。
4. 人工通过在一个事务内记录人工意见、处理审核任务、通过节点并推进下游；旧 AI 结果不能覆盖人工结论。
5. 人工通过评分节点不生成虚假分数，原 AI 结果与最终人工结论可以同时追溯。
6. 只有已有截止时间的节点可以延期，新时间必须晚于当前生效截止时间；并发修改返回冲突。
7. 教师可以逐文件下载、下载当前学生全部材料、下载当前节点全部学生材料，以及下载选择或筛选范围材料。
8. 所有批量包只包含当前有效提交，目录按节点和“学号-姓名”组织，并包含材料清单。
9. 单个 OSS 文件失败不阻断其他文件打包，失败项在材料清单和任务状态中可见。
10. 批量导出使用独立持久化 Worker，不占用 AI 审核 Worker；服务重启后任务可恢复。
11. 普通教师无法访问其他教师流程的进度、提交、文件、人工审核或导出任务。
12. 教师预览实例不会进入正式进度、人工通过或批量下载统计。

## 16. 实施边界

该功能同时涉及教师进度查询分页、名单合并、学生详情、延期并发控制、人工审核事务、审核子进程取消、教师文件下载、持久化导出任务和前端管理面板。实施时应作为一个连续功能拆分为可审查步骤，但必须保持以下共享边界：

- 下游推进只调用现有统一运行状态函数；
- 人工结论与 AI 原始结果分别保存；
- 单项下载和批量导出共用教师文件归属校验；
- 导出任务与 AI 审核任务使用不同队列和 Worker；
- 所有筛选、选择和文件范围以服务端重新解析结果为准。
