# 登录账号历史与密码空白设计

## 目标

登录页首次打开时，姓名、学号/工号和密码均为空。用户聚焦姓名或学号/工号输入框后，继续显示应用保存的历史账号；选择历史账号只回填姓名和学号/工号，密码始终由用户重新输入。

## 现状与根因

- `AuthPortal` 的 React 初始表单已经为空，应用账号历史仅保存 `name` 和 `identifier`。
- 登录密码框使用 `autocomplete="current-password"`，会允许浏览器密码管理器自动填充密码，并可能连带填充账号字段。
- 分享链接登录页同时使用 `autocomplete="username"` 和 `autocomplete="current-password"`，存在相同行为。

## 方案

采用原生表单属性的最小修正：

1. 保留 `rememberedAccount`、账号历史弹层和“记住账号”逻辑，不改变本地存储结构。
2. 主登录表单设置 `autoComplete="off"`；登录模式下姓名、学号/工号和密码字段均关闭浏览器自动填充。
3. 分享链接登录表单采用相同策略，保证两个学生登录入口行为一致。
4. 注册模式继续使用 `new-password`，避免影响浏览器对新密码创建的正确语义。
5. 不使用隐藏诱饵输入框、延迟 `readOnly` 或 DOM 清空脚本；这些方案更脆弱，并可能影响键盘操作和密码管理器兼容性。

## 数据与安全边界

- 应用仍只在 `localStorage` 的 `oa.auth.account-history.v2` 中保存姓名和学号/工号，不保存密码。
- 历史账号只有在用户点击对应输入框时显示；页面加载不主动选择或回填历史账号。
- 本次不修改后端认证、密码哈希、会话 Cookie、数据库或 OA 业务逻辑。

## 修改范围

- `frontend/src/features/auth/AuthPortal.tsx`
- `frontend/src/features/auth/StudentAccessGate.tsx`

## 验收标准

1. 教师和学生主登录页首次打开时三个字段均为空。
2. 点击姓名或学号/工号后仍能选择历史账号。
3. 选择历史账号后仅姓名和学号/工号被填入，密码保持为空。
4. 分享链接学生登录页首次打开时姓名、学号和密码均为空。
5. 注册页的新密码字段语义保持不变。

## 验证约束

遵循仓库规则，不运行自动化测试、构建或浏览器测试；实现后仅做静态业务审计并重启本地 Vite 服务，由用户手动验证浏览器实际行为。
