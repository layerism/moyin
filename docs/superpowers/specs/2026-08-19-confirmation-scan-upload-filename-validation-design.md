# 确认节点扫描件上传文件名即时校验设计

## 问题与目标

普通文件节点会在上传接口写入 OSS 前校验文件名是否以模板主文件名开头；确认节点扫描件目前只在点击“提交节点”时校验。因此，不符合模板名称的扫描件仍会先上传并显示在列表中，学生直到提交时才收到反馈。

本次目标是统一两类节点的校验时机：确认节点在选择、拖拽或替换扫描件时立即提示，并由后端上传接口在写入 OSS 前执行相同校验。提交阶段的最终校验继续保留。

## 文件名规则

沿用现有确认节点规则，不新增命名语义：

- 权威模板名称取当前流程版本绑定模板的 `original_name`，客户端传入的模板名称不作为后端依据；
- 模板必须是 `.docx`，扫描件必须是 `.jpg`、`.jpeg` 或 `.png`；
- 文件名先进行路径清理和 Unicode NFC 规范化；
- 扫描件主文件名必须以完整模板主文件名开头，可以追加页码、下载后缀等字符；
- 多文件选择逐一校验，任一文件不符合要求时，本批文件均不发起上传。

## 前端行为

- `ScanUploadWorkspace` 接收模板文件名，在选择、拖拽和替换入口调用现有纯函数校验。
- 校验失败时在扫描件工作区显示现有错误样式，不调用上传或删除接口。
- 替换文件先校验新文件名，再删除旧文件，避免错误文件导致原扫描件被删除。
- 已上传扫描件的提交前警告弹窗和提交按钮行为保持不变。

## 后端约束

- `POST /api/student/node-instances/{node_instance_id}/scans` 从上传上下文读取发布版本模板名称。
- 在读取文件内容、计算摘要和写入 OSS 前，使用现有 `validate_confirmation_scan_filenames()` 校验本次文件名。
- 校验失败返回 `422`，不创建 OSS 对象和 `uploaded_files` 记录。
- `submit_node()` 保留对全部待提交扫描件的最终校验，防止历史数据或绕过上传接口的数据进入提交。

## 变更边界

- 仅影响带 DOCX 模板的确认节点扫描件上传。
- 普通文件节点、无模板节点、扫描件格式/数量/页数校验和审核链路保持不变。
- 不自动重命名文件，不迁移既有文件，不改变 API 数据结构。

## 验收条件

1. 选择、拖拽或替换名称不符合模板的扫描件时，学生立即看到明确提示，且不发起上传。
2. 批量选择中存在一个不合规文件时，本批文件均不上传。
3. 替换文件名不合规时，原扫描件保持不变。
4. 绕过前端调用扫描件上传接口时，后端在写入 OSS 前拒绝不合规文件。
5. 合规文件仍按现有流程上传、排序、替换并提交。
6. 提交阶段继续逐一校验全部扫描件。

## 验证边界

项目规范禁止代码功能改动过程中运行测试或使用浏览器插件。本次补充对应静态测试用例，并通过前后端调用链与失败分支审计确认行为；交付时明确说明自动化测试和浏览器回归均未运行。
