# 流程曲线连线与端口分流设计

## 背景

教师流程画布和学生运行拓扑当前都使用直角折线路径。当多个节点通过同一方向端口连接时，不同边可能长距离共线，造成视觉上看似存在额外依赖。例如三条边可能被误读为四条边，但运行时只会依据实际保存的显式边计算前驱。

## 目标

教师流程画布与学生运行拓扑同步改用三次贝塞尔曲线，并对共享来源端口和目标端口的边进行确定性的扇出、扇入分流，使每条边的主体、落点和箭头均可辨识。

## 方案选择

采用“贝塞尔曲线 + 端口扇出”方案，不采用仅替换路径命令的普通曲线，也不采用只能美化拐角的圆角直角线。

## 数据语义

- 不修改 `AcademicFlowEdge` 数据结构。
- 不修改边的 `source`、`target`、`sourcePort` 和 `targetPort`。
- 不根据曲线交叉、接近或共线自动推断新依赖。
- 下游节点仍只等待配置中真实存在的全部入边来源。
- 当前缺少的 `确认自己导师是谁 → 安全管理协议书` 仍需通过显式连线单独补充。

## 共享几何模块

新增 `frontend/src/features/academic-flow/edgeCurveGeometry.ts`，集中提供与视图无关的纯函数：

1. 根据边集合、节点位置和端口方向，对同一来源端口的边按目标中心坐标稳定排序，生成来源槽位。
2. 对同一目标端口的边按来源中心坐标稳定排序，生成目标槽位。
3. 将槽位转换为节点边界上的横向或纵向偏移；同组单边保持端口中心，多边围绕中心对称分布。
4. 根据分流后的起止点、端口方向和节点间距计算三次贝塞尔控制点。
5. 返回 SVG 路径和真实目标落点，供箭头、可点击热区和连线渲染共同使用。

槽位排序必须使用边 ID 作为最终稳定排序条件，避免节点移动或 React 重渲染时线路无规律换位。

## 曲线规则

- 上、下端口沿节点宽度方向分流；左、右端口沿节点高度方向分流。
- 分流间距使用固定小间距并设置最大偏移，防止边落点越出节点边界。
- 控制点首先沿端口法线离开节点，再向目标方向弯曲。
- 控制距离随起止点距离增长并设置上下限，避免近距离曲线过度弯折或远距离曲线过平。
- 多条边即使共享逻辑端口，也具有不同的可视起点、终点和箭头位置。

## 教师流程画布

- 最终边、选中边和透明删除热区使用同一曲线路径。
- 箭头使用共享几何返回的目标落点和原目标端口方向。
- 拖动创建连线时的预览线改为贝塞尔曲线；尚未确定目标时使用中心端口，不参与分流。
- 保留现有边选择、键盘删除、删除按钮、循环校验和端口连接行为。
- 移除仅服务于直角路由的候选折线路径与碰撞计分函数，避免保留两套失效算法。

## 学生运行拓扑

- `StudentFlowTopology` 使用与教师端相同的分流和贝塞尔控制点算法。
- 节点状态颜色、箭头颜色、缩放和平移行为保持不变。
- 学生端不新增边选择或编辑能力。

## 视觉与交互边界

- 曲线降低长距离重合，但不承诺消除所有几何交叉；交叉不表示依赖汇合。
- 不新增动画、渐变或新的颜色体系。
- 线宽、选中态、完成态和箭头尺寸沿用现有视觉语言。
- 对同一节点端口存在多条边时，箭头必须可分别辨识。

## 变更范围

- 新增 `frontend/src/features/academic-flow/edgeCurveGeometry.ts`。
- 修改 `frontend/src/features/academic-flow/AcademicFlowDesigner.tsx`。
- 修改 `frontend/src/features/academic-flow/studentTopologyGeometry.ts`。
- 按现有测试组织调整相关几何测试源文件，但依据项目规则，本任务执行过程中不运行测试。
- 不修改后端、数据库、流程草稿或已发布快照。

## 验收条件

- 教师画布和学生拓扑均显示曲线连线。
- 同一来源端口的多条边离开节点后可辨识。
- 同一目标端口的多条边具有独立落点和箭头。
- 相同输入始终产生相同槽位和路径。
- 教师端曲线可被选中、点击删除并通过键盘删除。
- 连线预览使用曲线，最终连接语义不变。
- 三条显式边不会在视觉上被误解为自动生成第四条依赖。
