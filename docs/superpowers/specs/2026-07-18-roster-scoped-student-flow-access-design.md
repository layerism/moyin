# 名单隔离的学生 OA 流程访问设计

## 目标

教师可以创建多个相互独立的 OA 流程，并为每个流程分别指定学生名单。学生登录后，只能查看和填写有效名单中包含自己的 OA 流程；其他流程不可见，也不能通过直接请求、实例地址或分享链接绕过名单限制。

本次只修正学生流程发现与访问控制，不调整现有 DAG 版本更新、实例迁移、节点状态、历史提交或审核任务逻辑。

## 核心规则

设教师拥有流程集合：

$$
F=\{f_1,f_2,\ldots,f_N\}
$$

每个流程 \(f_i\) 维护独立有效名单 \(R_i\)。对当前学生 \(s\)，其可见流程集合为：

$$
VisibleFlows(s)=\{f_i\in F\mid f_i.status=published\land s\in R_i\}
$$

名单成员匹配同时满足：

- 当前账号学号与名单 `student_no` 精确匹配；
- 当前账号姓名与名单 `name` 精确匹配；
- 名单记录状态为 `active`。

不同 OA 流程的名单互不影响。同一学生可以属于零个、一个或多个流程名单。

## 学生可见性

学生登录后，系统按当前账号查询全部有权访问的已发布 OA 流程，而不是只查询已经创建的个人流程实例。

| 条件 | 学生端结果 |
| --- | --- |
| 学生在 OA 有效名单中，尚无实例 | 显示 OA，状态为“待开始” |
| 学生在 OA 有效名单中，已有实例 | 显示 OA 及当前进行状态 |
| 学生不在 OA 名单中 | 不显示 OA |
| 学生已从 OA 名单移除 | 不显示 OA，既有实例也不可访问 |
| OA 尚未发布、已停用或已归档 | 不显示 OA |

流程是否可见由名单授权决定，与学生此前是否访问过教师分享链接无关。

## 学生首次进入

名单内学生首次点击“待开始”的 OA 时：

1. 服务端从登录会话读取学生 ID。
2. 重新读取学生账号姓名和学号。
3. 校验 OA 处于已发布状态。
4. 校验该 OA 存在姓名、学号同时匹配的 `active` 名单记录。
5. 读取 OA 当前发布版本。
6. 幂等创建或读取该学生的个人流程实例。
7. 返回实例并进入现有学生流程页面。

客户端不得传入学生 ID、姓名、学号或目标版本作为授权依据。

## 学生接口

### 查询可见 OA

`GET /api/student/flows`

返回当前学生有权访问的所有已发布 OA。每个逻辑 OA 只返回一条记录：

```json
{
  "flowId": "flow-id",
  "instanceId": null,
  "name": "流程名称",
  "status": "not_started",
  "lastActiveAt": null
}
```

状态范围为：

- `not_started`：名单内但尚未创建实例；
- `in_progress`：已有进行中实例；
- `completed`：已有已完成实例。

已有实例时返回 `instanceId` 和 `lastActiveAt`；未开始时两者为 `null`。

### 进入 OA

`POST /api/student/flows/{flowId}/enter`

服务端重新校验流程状态和有效名单。校验通过后幂等创建或读取当前发布版本实例；名单不匹配时返回 `403`。

### 分享链接入口

现有 `/s/{token}` 分享入口继续保留。令牌只用于定位流程，最终进入前仍调用相同的名单授权逻辑。获得分享链接但不在名单中的学生不能查看流程内容或创建实例。

## 名单变化

### 新增或恢复学生

教师将学生加入某个 OA 的有效名单后：

- 学生下次进入流程中心即可看到该 OA；
- 若此前没有实例，显示“待开始”；
- 若此前被移除但保留既有实例，恢复后继续原实例。

### 移除学生

教师将学生名单状态改为 `revoked` 后：

- 该 OA 立即从学生流程中心消失；
- 既有实例、草稿和提交数据继续保留；
- 实例读取、暂存、上传、提交和重新审核均返回 `403`；
- 后续恢复名单后，学生可以继续原实例。

## 数据查询原则

学生流程列表以 `flow_roster_entries` 为授权起点：

1. 匹配当前学生账号的姓名和学号；
2. 过滤 `flow_roster_entries.status = 'active'`；
3. 连接对应 `flows`，只保留已发布流程；
4. 左连接当前学生已有的 `flow_instances`；
5. 按逻辑 `flow_id` 去重，每个 OA 只返回一次。

本次不修改数据库表结构。现有流程发布和实例版本迁移继续保证已有实例指向当前有效发布版本。

## 前端行为

学生流程中心统一展示授权 OA：

- `not_started` 显示“待开始”；
- `in_progress` 显示“进行中”；
- `completed` 显示“已完成”；
- 点击“待开始”先调用进入接口，取得 `instanceId` 后跳转；
- 点击已有实例直接进入；
- 列表为空时显示“暂无可填写的 OA 流程”，不再要求学生必须先访问分享链接。

## 安全要求

- 所有学生流程接口必须依赖登录会话。
- 列表、进入、实例读取、暂存、上传、提交和重新审核使用同一名单授权规则。
- 名单外统一返回 `403`，不泄露其他学生名单、流程结构或版本信息。
- 前端隐藏不能替代后端权限校验。
- 教师只能维护自己 OA 流程的名单。

## 验收标准

1. 教师拥有任意数量的 OA 流程，每个流程可以维护不同名单。
2. 学生登录后看到全部包含自己的已发布 OA。
3. 学生不会看到任何不包含自己的 OA。
4. 名单内但未访问过分享链接的学生仍能看到 OA，并可首次进入。
5. 同时属于多个名单的学生可以看到对应的多个 OA。
6. 不属于任何有效名单的学生看到空列表。
7. 名单外学生直接请求进入接口返回 `403`。
8. 名单外学生持有分享链接仍不能进入。
9. 学生被移除后 OA 消失，所有运行写接口立即拒绝；恢复后继续原实例。
10. OA 重新发布后，现有 DAG 版本迁移行为保持不变。

## 预计改动范围

- `backend/app/repositories/flow_instances.py`：以名单为起点列出流程，并支持按逻辑流程进入。
- `backend/app/api/routes/student_flows.py`：新增流程列表和按 `flowId` 进入接口。
- `frontend/src/features/auth/authApi.ts`：调整学生流程摘要类型和接口。
- `frontend/src/features/auth/StudentAccountPage.tsx`：展示“待开始”并处理首次进入。
- `frontend/src/App.tsx`：首次进入成功后跳转到实例页面。
- 视接口复用位置，小幅调整 `frontend/src/features/academic-flow/api.ts`。

## 非目标

- 不修改现有 DAG 修订影响算法。
- 不修改重新发布时的实例迁移规则。
- 不新增提交历史版本字段或历史提交界面。
- 不修改审核任务状态机。
- 不修改名单导入、更新、撤销和恢复规则。
- 不新增班级、专业或组织机构级授权。
- 不要求教师逐个为名单学生预创建实例。
