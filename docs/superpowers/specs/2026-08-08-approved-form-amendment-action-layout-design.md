# 已通过表单修改按钮布局设计

## 问题

已通过表单的“修改内容”按钮直接使用 `.runtime-node-actions`，但该节点位于 `.runtime-node-form` 的内边距容器之外。因此按钮紧贴弹窗右下边界，与完成状态卡片的间距体系不一致。

## 设计

- 保留现有 `.runtime-node-actions` 作为通用按钮排列规则。
- 仅为已通过表单的只读操作区增加修饰类，不修改编辑状态下“暂存/提交”操作区。
- 桌面端操作区与弹窗右侧、底部保持 `24px` 留白，按钮继续右对齐。
- 窄屏下与现有完成提示和只读卡片保持一致，左右及底部留白收缩为 `18px`。
- 删除只读操作区中无语义的空 `<span />`，不改变按钮文案、交互和权限判定。

## 影响范围

仅修改 `StudentRuntimePage.tsx` 中已通过表单的操作区标记和 `styles.css` 中对应布局规则。文件上传、确认承诺、通知公告、普通表单编辑以及后端行为不受影响。

## 验收边界

- “修改内容/继续修改”按钮不再贴边，并与只读内容卡对齐。
- “暂存/提交”操作区布局不变。
- 不新增依赖、组件或业务状态。
- 按项目约定仅做静态审计，不运行测试、构建或浏览器验证。
