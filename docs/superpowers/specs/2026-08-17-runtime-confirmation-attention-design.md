# 节点提交确认项提醒设计

## 背景

学生运行页在“确认承诺”和“通知公告”节点中展示“我已阅读并确认以上内容”复选框。当前仅带扫描模板的确认承诺节点会通过 `scanBlocker` 阻止未确认提交；通知公告和不带扫描模板的确认承诺节点点击“提交节点”时没有前端确认校验，也没有局部视觉反馈。

## 目标

学生点击“提交节点”或“重新提交”时，如果当前节点展示确认复选框但尚未勾选，前端必须阻止提交，并通过短暂振动、红色高亮和行内提示将注意力引导到确认区域。

## 适用范围

- 适用于 `confirmation` 和 `announcement` 两类节点。
- 不影响 `form` 和 `file` 节点的既有提交校验。
- 不改变暂存行为、后端接口、节点状态流转或扫描件提交规则。

## 交互流程

1. 用户点击提交按钮。
2. 前端先执行既有表单字段校验。
3. 若节点需要确认且 `draft.confirmed !== true`，则阻止调用 `onSubmit`。
4. 确认区域短暂左右振动并显示红色边框和浅红背景。
5. 区域下方显示“请先勾选确认”，复选框获得焦点。
6. 用户勾选后立即清除红色高亮和行内提示；后续提交继续执行既有逻辑。

## 状态与可访问性

- `RuntimeNodeDialog` 使用局部布尔状态记录是否发生过未确认提交。
- 复选框通过 React `ref` 获得焦点，不使用全局 DOM 查询。
- 错误状态下复选框设置 `aria-invalid="true"`，并通过 `aria-describedby` 关联行内提示。
- 行内提示使用 `role="alert"`，使辅助技术能够感知错误。
- 在 `prefers-reduced-motion: reduce` 环境中禁用振动动画，但保留高亮和文字提示。

## 视觉规范

- 沿用项目红色错误语义，不新增颜色体系。
- 正常状态维持现有确认项布局。
- 错误状态使用红色边框、浅红背景和短促水平振动，不移动整个弹窗。
- 提示文字紧邻确认区域，避免依赖全局通知定位问题。

## 变更范围

- 修改 `frontend/src/features/academic-flow/StudentRuntimePage.tsx`：增加确认提交状态、校验、焦点和无障碍属性。
- 修改 `frontend/src/styles.css`：增加确认区域错误样式、振动关键帧和减少动态效果覆盖。
- 不修改后端代码和数据库结构。

## 验收条件

- 确认承诺或通知公告节点未勾选时，点击提交不会调用提交接口。
- 未勾选提交时，确认区域振动一次、保持错误高亮并显示“请先勾选确认”。
- 复选框获得焦点，辅助技术可以读取错误关联。
- 勾选复选框后错误高亮和提示立即消失。
- 已勾选时继续执行既有提交逻辑。
- 减少动态效果模式下不振动，但仍能看到高亮和提示。
