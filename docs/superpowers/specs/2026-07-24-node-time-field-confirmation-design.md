# 节点时间字段确认交互设计

## 1. 背景

节点设置中的“起始时间”和“截止时间”使用浏览器原生 `datetime-local`。当前用户在浏览器日期时间面板中选择时间后，`onChange` 会立即调用 `onUpdateNode`，把时间写入当前页面的流程工作副本。

浏览器原生日期时间面板由浏览器或操作系统绘制，网页不能向该面板内部插入自定义“确认”按钮。本次在网页字段旁增加独立确认按钮，通过本地待确认值实现明确的二阶段操作。

## 2. 目标

- 起始时间和截止时间分别提供独立的“确认”按钮。
- 浏览器日期时间面板中的选择先成为待确认值，不立即修改节点。
- 点击“确认”后才更新对应节点时间。
- 确认时间后保持节点设置弹窗打开。
- 未确认就关闭节点设置时，放弃待确认修改。
- 保留现有“清除”、时间状态、校验摘要、修订权限和发布逻辑。

## 3. 范围

### 3.1 包含

- 为两个 `datetime-local` 字段分别维护本地待确认值。
- 在每个时间字段旁增加“确认”按钮。
- 调整时间字段的三列布局和窄屏适配。
- 处理节点切换、确认、清除和未确认关闭时的状态同步。

### 3.2 不包含

- 不修改浏览器原生日期时间面板。
- 不新增自定义日历、日期组件或第三方依赖。
- 不修改后端、数据库、流程接口或时间数据结构。
- 不改变流程草稿保存、发布和发布后修订规则。
- 不调整节点设置中的其他字段。

## 4. 交互设计

### 4.1 待确认值

节点设置打开时：

- 起始时间待确认值初始化为节点当前 `startAt` 的本地日期时间；
- 截止时间待确认值初始化为节点当前 `deadlineAt` 的本地日期时间；
- 未设置的字段初始化为空。

用户通过原生日期时间面板或键盘修改输入时，只更新对应待确认值，不调用 `onUpdateNode`。节点状态徽标和底部时间摘要继续基于已确认的节点值计算。

### 4.2 确认

每个字段按照“输入框、确认、清除”排列。

“确认”按钮满足以下规则：

- 待确认值为空时禁用；
- 待确认值与节点当前已确认值相同时禁用；
- 待确认值发生有效变化后启用；
- 点击后将本地日期时间转换为 ISO 字符串，并仅更新当前字段；
- 更新后节点设置弹窗保持打开；
- 焦点保留在当前字段操作区域，教师可以继续设置另一个时间或其他节点属性。

起始时间确认只写入 `startAt`；截止时间确认只写入 `deadlineAt`。两个字段相互独立。

### 4.3 清除

保留现有“清除”按钮。点击后：

1. 立即将对应节点字段写为 `null`；
2. 同时清空该字段的待确认值；
3. 不关闭节点设置弹窗。

未设置时间时不显示“清除”，保持现有行为。

### 4.4 关闭与节点切换

- 点击节点设置的“完成”或关闭按钮时，不提交待确认值；组件卸载后待确认值自然丢弃。
- 若节点设置组件在不卸载的情况下切换到其他节点，两个待确认值必须重新同步到新节点的已确认值，不能继承上一个节点的输入。
- 后端刷新或其他现有操作导致节点已确认时间变化时，待确认值同步到最新已确认值。

## 5. 校验与反馈

- 继续使用原生 `datetime-local` 保证输入格式。
- 确认后继续由现有 `getTimeWindowSummary` 判断“起始时间必须早于截止时间”。
- 本次不新增阻断式跨字段校验，不改变现有允许先设置任一端时间的行为。
- 已发布旧节点的起始时间和截止时间仍可按现有修订规则修改。
- 当整个节点编辑器被锁定时，字段和按钮继续由外层 `fieldset` 统一禁用。

## 6. 视觉设计

### 6.1 桌面端

每个时间字段采用三列：

```text
[日期时间输入框] [确认] [清除]
```

- “确认”使用蓝色主操作视觉；
- “清除”保持现有白底灰色描边；
- 两个按钮均保持完整文字，不压缩输入框到不可操作；
- 起始时间和截止时间之间的时间轴保持不变。

### 6.2 窄屏

时间窗口卡片仍按现有规则改为上下排列。单个字段内部保留输入框与两个操作按钮，必要时允许操作按钮在输入框下方形成独立操作行，避免横向裁切。

## 7. 状态与数据流

```text
节点已确认时间
  -> 初始化字段待确认值
  -> 用户在原生面板中选择时间
  -> 仅更新待确认值
  -> 点击该字段“确认”
  -> 转换为 ISO 字符串
  -> 调用现有 onUpdateNode
  -> 当前页面流程工作副本更新
```

不新增全局状态，不修改 `AcademicFlowNode` 类型，也不改变 `commitDesignChange`。

不新增文件、依赖或通用日期组件。

## 9. 验收标准

1. 起始时间和截止时间旁分别显示“确认”按钮。
2. 选择新时间后，输入框显示待确认值，但节点状态和时间摘要尚未变化。
3. 点击对应“确认”后，仅该字段写入节点。
4. 点击确认后，节点设置弹窗保持打开。
5. 待确认值为空或未变化时，确认按钮禁用。
6. 未确认就关闭节点设置时，重新打开仍显示原已确认时间。
7. 点击“清除”后，对应节点时间和待确认值同时清空。
8. 切换节点或节点已确认时间变化时，不残留其他节点的待确认值。
9. 起始时间晚于截止时间时，确认后继续显示现有校验提示。
10. 桌面端与窄屏下，输入框、“确认”和“清除”均不被裁切。
11. 后端、接口、数据结构和发布规则均无改动。

## 10. 验证边界

按项目约定，开发期间不运行自动化测试、构建或浏览器测试，只执行静态状态流与样式审计。实现完成后清理项目缓存，使用本地 Uvicorn 与 Vite 重启服务，由用户按照上述验收标准手动验证。
