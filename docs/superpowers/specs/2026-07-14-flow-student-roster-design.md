# 流程学生名单与访问控制设计

## 目标

教师为每个 OA 流程维护独立学生名单。学生即使获得高熵分享链接，也只有在当前账号的姓名和学号同时匹配该流程有效名单时，才能创建或继续访问个人流程实例。

## 范围

- 支持上传 `.xlsx` 或 `.csv` 名单，并自动识别“姓名”“学号”列。
- 班级列允许存在但不保存、不参与权限判断。
- 支持发布前及发布后新增、更新和移除学生。
- 名单变化不修改已发布拓扑版本。
- 所有名单变更写入审计日志。
- 本轮不实现班级权限、批量物理删除或名单跨流程复用。

## 数据模型

新增 `flow_roster_entries`：

| 字段 | 说明 |
| --- | --- |
| `id` | 整数主键 |
| `flow_id` | 所属流程，流程删除时级联删除 |
| `student_no` | 学号；同一流程内唯一 |
| `name` | 学生姓名 |
| `status` | `active` 或 `revoked` |
| `created_at` | 首次加入时间 |
| `updated_at` | 最近变更时间 |
| `updated_by` | 操作教师 ID |

数据库约束为 `UNIQUE(flow_id, student_no)`。重新导入同一学号时更新姓名并恢复为 `active`；同一批次内同一学号对应多个姓名时整批拒绝。

## 导入与维护

前端复用现有 `read-excel-file`：

1. 教师在流程设计页打开“学生名单”。
2. 选择 Excel 后，前端识别表头并标准化姓名、学号，去除首尾空白。
3. 弹窗展示有效行、重复行和错误行；教师确认后提交结构化 JSON。
4. 后端重新校验空值、重复学号、流程归属和批次规模，再在单个事务中执行新增或更新。
5. Excel 中未出现的原名单成员不会自动移除。
6. 教师通过名单行上的移除操作将成员状态改为 `revoked`，不物理删除。

名单为空时禁止发布新流程。历史已发布流程在没有名单时采用安全默认值：所有学生均不可进入，教师需补充名单后恢复访问。

## API

- `GET /api/workflows/{flow_id}/roster`：教师读取本流程名单。
- `POST /api/workflows/{flow_id}/roster/import`：批量新增或更新名单。
- `DELETE /api/workflows/{flow_id}/roster/{entry_id}`：停用一名学生。

所有接口使用当前教师身份校验 `flows.owner_id`。导入请求限制单批最多 5000 行，避免异常文件造成过量写入。

## 学生访问控制

名单校验是持续授权，不是仅在首次进入时检查：

- 读取分享页公开元数据时不暴露名单。
- `enterShared` 在创建或返回实例前校验姓名、学号和 `active` 状态。
- 查看实例、保存草稿、提交节点时再次校验名单。
- 学生流程中心仅列出仍有访问权限的流程。
- 学生被移除后，已有实例和提交记录保留，但立即失去读取、暂存和提交权限；重新加入后可继续原实例。

未授权统一返回 `403` 和“你不在该流程的有效学生名单中”，不返回其他名单信息。

## 审计

使用现有 `audit_logs`：

- 批量导入写入 `roster_import`，记录新增、更新、恢复数量和来源文件名。
- 单人移除写入 `roster_revoke`，记录变更前后状态。
- 审计主体为当前教师 ID，实体为 `flow_roster`。

审计内容不保存完整名单，只保存必要摘要，减少个人信息复制。

## 界面

流程设计页顶部增加“学生名单”按钮。名单弹窗包括：

- Excel 上传区和表头识别结果；
- 导入预览及错误行提示；
- 当前有效/已移除人数；
- 按姓名或学号搜索的名单表格；
- 单行移除确认。

发布按钮在有效名单为空时禁用并显示明确原因。发布后名单按钮保持可用。

## 测试

- Excel 表头识别、空白清理、重复学号和缺失字段测试。
- 教师只能维护自己流程名单的 API 测试。
- 批量导入新增、更新、恢复及审计测试。
- 空名单不可发布测试。
- 名单内学生可进入，名单外学生返回 `403`。
- 移除后已有实例不可读取、暂存或提交，恢复后可继续。
- 学生流程中心过滤已失去权限的流程。
- 前端构建、后端全量测试及实际页面交互检查。
