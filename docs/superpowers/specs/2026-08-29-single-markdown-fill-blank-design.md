# 单一 Markdown 填空题设计

> 状态：交互与判分语义已确认，等待设计文档复核。

## 目标

将新建和可安全升级的填空题收敛为一个 Markdown 答题区。教师只配置题干、分值和一个标准答案；学生提交一份 Markdown 原文；系统去除师生答案首尾空白后进行精确匹配并自动判分。

本次不引入 LLM、模糊匹配、多个可接受答案、大小写开关、多个填空或部分得分。

## 当前问题

现有 `fill_blank` 同时承担“题干中的多个行内短答案”和“逐空精确判分”，因此公开题目依赖 `[[blank:<id>]]` 标记，私有答案依赖填空 ID、答案数组和大小写开关。仅隐藏这些控件会留下不可见的数据约束，并使教师界面与实际判分模型不一致。

## 教师端交互

新填空题固定显示以下字段：

1. 题干 Markdown；占位文案仅为“请输入题干”，不再提示或插入 `[[blank:...]]`；
2. 分值；与“必答”放在同一紧凑设置行，分值属于整道题；
3. 标准答案；使用现有单一 Markdown 原位编辑模式，输入时显示源码，失焦后渲染预览，不增加格式工具栏。

界面删除以下能力：

- 填空 ID 和标记展示；
- “添加填空”；
- “可接受答案（每行一个）”；
- “区分大小写”；
- 每个空单独设置分值。

折叠摘要统一显示“填空 · N 分”，不再显示填空数量。标准答案为空时继续使用现有“需修正”错误语义，并禁止完成当前答题卡配置。

## 学生端交互

题干使用教师端与学生端共享的 `AnswerSheetMarkdown` 渲染链。题干下方只有一个 Markdown 答题区：

- 点击预览区进入源码编辑；
- 失焦后原位渲染；
- 不显示工具栏；
- 提交内容为空时，必答校验失败；
- 只读结果页继续显示学生提交的 Markdown 渲染结果。

教师真实学生预览和正式学生页面继续复用同一运行时组件，不建立两套交互。

## 数据契约

答题卡协议升级为 `schemaVersion = "2.0"`、`graderVersion = "answer-sheet-v2"`。选择题结构和判分规则不变。新填空题使用显式模式，避免与旧版多空结构混淆。

公开题目：

```json
{
  "id": "question-id",
  "type": "fill_blank",
  "format": "single_markdown_exact",
  "content": "题干 Markdown",
  "points": 2,
  "required": true
}
```

私有标准答案：

```json
{
  "type": "fill_blank",
  "format": "single_markdown_exact",
  "answerMarkdown": "标准答案 Markdown"
}
```

学生提交：

```json
{
  "answerMarkdown": "学生答案 Markdown"
}
```

学生提交和标准答案均保留原始 Markdown。`trim()` 只在必答校验和判分比较时执行，不改写已保存内容。

## 自动判分

对新填空题计算：

```text
studentAnswer.trim() === standardAnswer.trim()
```

结果相同则获得整题分值，否则得 0 分。比较规则明确为：

- 仅去除字符串首尾空白；
- 不忽略大小写；
- 不合并内部空格或换行；
- 不进行 Unicode 归一化；
- 不比较 Markdown 渲染后的 HTML；
- 不接受同义表达或多个标准答案。

因此 Markdown 源码不同，即使视觉渲染近似，也判为不同答案。教师端在标准答案字段旁显示简短说明：“去除首尾空白后精确匹配”。

## 旧版兼容

已发布的 `schemaVersion = "1.0"` 快照及其 `answer-sheet-v1` 判分器保持不变，继续支持旧版标记、多空、多个可接受答案和大小写配置。历史提交与成绩不重新计算。

v2 校验器和判分器同时识别：

- 带 `format = "single_markdown_exact"` 的新填空题；
- 修订流程中原样保留的旧版填空题结构。

这样，已发布流程进入修订后可以保留旧题并添加新题，不要求一次性迁移全部历史题目。

对教师当前草稿中的旧版填空题，仅在满足以下条件时安全转换为新结构：

1. 恰好一个填空；
2. 该填空未启用区分大小写；
3. 最多一个非空可接受答案；
4. 题干中的对应标记恰好出现一次。

转换时删除题干标记，使用该空分值作为整题分值，并将唯一答案作为 `answerMarkdown`。不满足条件的旧题保持旧结构和旧编辑器，避免静默丢失既有判分语义；其摘要明确标为“旧版填空”。

## 导出与结果展示

- 题目导出中，“分值”写整题分值，“标准答案”写原始标准答案 Markdown；
- 学生节点导出中，学生答案写原始 Markdown，不拆分为填空 ID；
- 逐题成绩仍使用现有题号、得分和满分字段；
- 配置允许显示标准答案时，结果页通过共享 Markdown 渲染器展示标准答案，不输出内部格式标记。

## 错误边界

发布前必须拒绝以下配置：

- 新填空题缺少或包含未知字段；
- 分值不是正整数；
- 标准答案去除首尾空白后为空；
- 公开题目、私有答案的题号、类型或 `format` 不一致；
- v1/v2 判分器与协议版本不匹配。

学生提交继续拒绝未知题号、未知字段、非字符串答案和缺失的必答答案。判分结果不包含私有标准答案；标准答案仍只通过现有受控反馈路径提供。

## 影响范围

- 前端答题卡类型、创建、校验和草稿升级；
- 教师答题卡编辑器及紧凑样式；
- 学生填写、只读展示和提交载荷；
- 后端 v2 公私有协议校验、提交归一化和确定性判分；
- 题目与学生提交 Excel 导出；
- v1 已发布快照的兼容分发。

不修改 DAG 推进、及格线、作答次数、反馈策略、成绩存储表或已发布快照的不可变规则。

## 验收标准

1. 新建填空题没有 `[[...]]`、添加填空、可接受答案列表和区分大小写控件；
2. 教师只填写一个标准答案，学生只获得一个 Markdown 答题区；
3. 分值位于紧凑设置行，折叠摘要不显示填空数量；
4. 师生答案仅去除首尾空白后精确比较，正确得满分，错误得 0 分；
5. 教师预览、正式学生端、只读结果和导出使用同一数据语义；
6. 已发布 v1 流程及历史成绩不受影响；
7. 不满足安全转换条件的旧题不会被静默改写。
