# 学生流程“已通过”绿色状态设计

## 目标

学生端流程拓扑中，运行状态为 `approved` 的节点统一使用绿色成功语义，使“已通过”与灰色的“待开放”状态能够被直接区分。

## 根因

后端与前端组件均已正确输出 `approved` 状态；当前视觉错误来自 `frontend/src/styles.css`，其中拓扑图的 `approved` 图例、节点、序号、标签及连线被显式设置为灰色。

## 方案

仅修改现有 `.student-topology-*` 的 `approved` CSS 规则，不修改状态类型、运行时数据、React 渲染逻辑或交互权限。

绿色状态覆盖：

- “已通过”图例圆点；
- 已通过节点的边框、浅色背景及正文颜色；
- 节点序号圆形标记；
- 节点类型与“已通过”状态标签；
- 指向已通过节点的连线与箭头。

`locked`（待开放）继续使用灰色。现有可填写、审核中、审核异常、已截止等状态颜色保持不变。

## 颜色约束

复用项目已有成功状态配色，不引入新的设计变量或依赖：

- 深绿色正文：`#166534`；
- 中绿色强调：`#16a34a`；
- 绿色边框：`#86efac`；
- 浅绿色背景：`#f0fdf4`；
- 浅绿色标签背景：`#dcfce7`。

## 验收标准

- 学生流程拓扑中的已通过节点整体呈绿色成功状态；
- “已通过”图例与节点颜色一致；
- 指向已通过节点的连线呈绿色；
- 待开放节点仍为灰色，且与已通过节点有明确视觉差异；
- 不改变节点能否点击、状态流转、审核结果或其他业务行为。

## 验证边界

依据项目约定，本次仅做 CSS 范围与选择器静态审计，不运行自动化测试、构建或浏览器测试，由用户在现有页面手动确认视觉结果。
