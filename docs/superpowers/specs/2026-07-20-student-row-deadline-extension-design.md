# 教师端学生行级延期设置设计

## 1. 背景与目标

教师端“学生填写进度”面板已经具备个别学生节点截止时间覆盖能力，但当前入口集中在面板顶部，教师需要先选择学生，再选择节点。该交互与学生进度表脱节，容易选错学生，也无法直接判断该学生有哪些节点可以延期。

本次调整将延期入口移动到每名学生所在行，并补齐后端业务校验。教师只能为该学生尚未通过且原本存在截止时间的节点继续延后截止时间。

## 2. 范围

### 2.1 包含

- 在学生进度表中增加行级“设置延期”入口。
- 在选中学生行下方展开延期表单。
- 在教师进度接口中返回学生节点的精简延期摘要。
- 在现有个别延期写入接口中校验节点状态、原截止时间和新截止时间。
- 延期成功后沿用现有节点运行状态重算逻辑。

### 2.2 不包含

- 不新增数据库表或字段。
- 不新增延期写入接口。
- 不允许修改或取消已经保存的延期，只允许继续延后。
- 不改变流程版本、DAG、节点内容或学生既有提交。
- 不调整学生端页面。
- 不为无截止时间的节点新增截止限制。

## 3. 界面与交互

### 3.1 学生进度表

移除面板顶部现有“个别学生延期”表单，在进度表末尾增加“操作”列。每名学生显示“设置延期”按钮。

点击按钮后，在对应学生行下方插入一行跨列的延期编辑区域。学生姓名和学号固定展示，不提供学生选择框。同一时间只允许展开一名学生；点击另一名学生的按钮时，关闭原区域并展开新区域。再次点击当前学生的按钮或点击“取消”时收起。

### 3.2 行内延期表单

表单包含：

- 固定的学生姓名与学号；
- 节点选择；
- 当前生效截止时间，只读展示；
- 新截止时间，使用原生 `datetime-local` 控件；
- 延期原因，必填；
- “保存延期”和“取消”按钮。

节点下拉框只列出符合以下条件的节点：

1. 节点状态不是 `approved`；
2. 节点具有统一截止时间，或者已经存在个别延期截止时间。

若该学生没有可延期节点，编辑区域显示“该学生当前没有可延期节点”，不显示保存按钮。

### 3.3 保存反馈

- 保存成功：刷新进度数据、收起当前表单，并在面板顶部显示“个别学生延期已保存”。
- 保存失败：保持表单展开，在面板顶部显示后端返回的明确错误原因。
- 保存期间禁用保存按钮，避免重复提交。

## 4. 数据设计

### 4.1 教师进度接口

保留现有版本进度接口，在每个学生对象中增加 `nodes` 数组，不新增读取接口。每个节点摘要包含：

```ts
type WorkflowProgressNode = {
  effectiveDeadline: string | null;
  globalDeadline: string | null;
  nodeKey: string;
  overrideDeadline: string | null;
  status: RuntimeNodeStatus;
  title: string;
};
```

字段含义：

- `globalDeadline`：当前流程版本为该节点配置的统一截止时间；
- `overrideDeadline`：该学生该节点已保存的个别截止时间；
- `effectiveDeadline`：运行时实际采用的截止时间，个别截止时间优先于统一截止时间；
- `status`：该学生节点当前运行状态。

进度接口仅返回本流程版本、当前教师有权查看的学生实例，权限边界保持不变。

### 4.2 延期写入

继续使用：

```text
PUT /api/workflow-admin/instances/{instance_id}/nodes/{node_key}/deadline
```

请求结构不变：

```json
{
  "deadlineAt": "ISO-8601 时间",
  "reason": "延期原因"
}
```

## 5. 后端业务规则

后端是延期规则的最终可信边界。写入前必须在同一事务内读取最新节点和截止时间并校验：

1. 流程实例属于当前教师拥有的已发布流程版本；
2. 节点存在于该学生流程实例中；
3. 节点状态不是 `approved`；
4. 当前生效截止时间非空；
5. `deadlineAt` 是带时区的合法 ISO-8601 时间；
6. 新截止时间严格晚于服务器当前时间；
7. 新截止时间严格晚于当前生效截止时间；
8. 延期原因去除首尾空白后非空，且继续遵守现有长度上限。

不满足规则时返回 HTTP 422，并给出可直接展示的中文错误信息。不存在或不属于当前教师的实例、节点继续按现有安全边界返回 404，避免泄露其他教师数据。

保存合法延期后，继续复用现有 `student_deadline_overrides` 覆盖写入和节点状态重算逻辑：

- 已过期节点可根据草稿、起始时间和前置节点状态恢复为 `draft`、`available`、`scheduled` 或 `locked`；
- 节点起始时间与 DAG 前置节点条件不会被延期覆盖；
- 已提交、审核中、已拒绝等不属于现有可重算集合的状态保持不变；
- 不改变节点完成状态、既有提交或下游节点状态。

## 6. 前端校验

前端使用接口返回的 `nodes` 摘要筛选可延期节点，并提供即时提示：

- 新截止时间不得早于或等于当前生效截止时间；
- 新截止时间不得早于或等于浏览器当前时间；
- 延期原因不得为空。

原生日期时间控件的 `min` 取“当前生效截止时间”和“浏览器当前时间”中较晚者之后的最小可选分钟。前端校验只改善交互，不能替代后端校验；并发更新时以后端最新数据为准。

## 7. 错误处理

- 进度加载失败：沿用面板顶部提示区域展示错误。
- 延期提交失败：保持行内表单和用户输入，不自动切换学生。
- 保存期间：禁用保存按钮，防止重复请求。
- 保存后刷新失败：保留“延期已保存，但进度刷新失败”的明确提示，避免把写入成功误报为失败。

## 8. 改动位置

预计修改以下现有文件：

- `backend/app/repositories/flow_instances.py`：进度节点摘要与延期业务校验；
- `backend/app/api/routes/workflow_admin.py`：将业务校验错误转换为 HTTP 422；
- `frontend/src/features/academic-flow/runtimeTypes.ts`：进度节点摘要类型；
- `frontend/src/features/academic-flow/TeacherProgressPanel.tsx`：行级展开、表单状态和保存交互；
- `frontend/src/styles.css`：操作列与行内延期区域样式。

不引入新依赖，不抽取只使用一次的组件或工具函数。

## 9. 验收标准

1. 每名学生行均有独立的“设置延期”按钮。
2. 同一时间最多展开一名学生的延期表单。
3. 表单只显示未通过且已有截止时间的节点。
4. 当前生效截止时间清晰可见。
5. 新截止时间不能早于或等于当前生效截止时间，也不能早于或等于当前时间。
6. 已通过节点、无截止时间节点和非法直接调用均被后端拒绝。
7. 已有个别延期只能继续延长，不能缩短或取消。
8. 已过期节点延期后，仍须满足节点起始时间和 DAG 前置节点条件才能开放。
9. 保存成功后表单收起且进度刷新；保存失败时表单和输入保持不变。
10. 空学生列表的占位行适配新增“操作”列。

## 10. 验证边界

按项目约定，开发期间不运行自动化测试、构建或浏览器测试，仅执行静态调用链与业务逻辑审计。实现完成后清理中间缓存、本地方式重启服务，由用户按上述验收标准手动验证。
