# 文件审核脚本管理设计

## 1. 目标与范围

在教务流程列表页增加文件审核脚本管理入口，由超级管理员统一下载模板、上传新脚本和更新已有脚本。普通教师不能看到或调用管理功能，但可以在流程画布的“文件上传”节点中选择管理员预设的脚本。

本期交付脚本管理、版本保存、节点选择和后续执行解析入口，不执行上传脚本。

## 2. 权限边界

- `super_admin`：可查看脚本管理入口、下载 Python/JavaScript 模板、上传新脚本、更新已有脚本。
- 普通教师：教务流程页不显示脚本管理入口；可以读取可选脚本元信息并在文件上传节点中选择脚本。
- 所有前端权限限制均由后端再次校验。普通教师直接调用模板下载、上传或更新接口时返回 `403`。
- 教师接口不返回脚本源代码、服务器目录或其他运行时敏感信息。

## 3. 页面与交互

### 3.1 教务流程列表页

在“创建流程”按钮旁增加“审核脚本”按钮，仅超级管理员可见。

点击后打开“文件审核脚本”管理弹窗。弹窗包含：

- “下载 Python 模板”按钮；
- “下载 JavaScript 模板”按钮；
- “上传新脚本”按钮；
- 脚本列表，展示功能名称、功能描述、语言、当前版本、更新时间和操作；
- 每条脚本提供“更新版本”操作。

### 3.2 上传与更新表单

“上传新脚本”或“更新版本”均在管理弹窗内切换到表单视图，避免嵌套弹窗。表单字段包括：

- 功能名称：新增时可填写，更新时保持原名称；
- 功能描述：必填，更新时可修改；
- 脚本文件：仅允许 `.py` 或 `.js`。

新增成功后生成脚本 ID 和版本 `1`。更新成功后脚本 ID 不变、版本号递增、当前版本指针更新，且不允许改变脚本语言。

### 3.3 流程画布

“文件上传”节点的“审核脚本”区域只保留脚本选择下拉框，不再提供模板下载或上传入口。

节点保存：

- `auditScriptId`；
- `auditScriptVersion`；
- `auditScriptHash`；
- 用于展示的脚本名称和语言。

已配置节点继续使用原版本。管理员上传新版本后，已有节点不自动升级；新配置节点从列表中选择该脚本时使用当前最新版。

## 4. 数据模型

### 4.1 `audit_scripts`

在现有表上增加：

- `description TEXT NOT NULL DEFAULT ''`；
- `updated_at TEXT NOT NULL`。

保留现有 `id`、唯一名称、语言、当前版本、创建人、创建时间和归档时间字段。

### 4.2 `audit_script_versions`

继续保存不可变版本记录：脚本 ID、版本号、入口文件名、目录、SHA-256、文件大小、创建人和创建时间。

数据库迁移需要兼容已有脚本数据：历史记录的描述初始化为空字符串，`updated_at` 使用原 `created_at`。

## 5. 本地目录结构

```text
backend/scripts/global/<script_id>/
├── 1/
│   ├── handler.py 或 handler.js
│   └── manifest.json
├── 2/
│   ├── handler.py 或 handler.js
│   └── manifest.json
```

每次更新创建新版本目录，不物理覆盖旧版本。`manifest.json` 保存脚本 ID、版本、名称、描述、语言、入口文件、SHA-256、创建人和创建时间。

写入过程使用同级临时目录，文件与清单完整写入后再原子替换到目标版本目录。数据库事务失败时清理新建目录。

## 6. API

### 6.1 教师可用

- `GET /api/workflow-admin/audit-scripts`
  - 返回活动脚本的 ID、名称、描述、语言、当前版本、哈希和更新时间；
  - 不返回源代码或目录。

### 6.2 仅超级管理员

- `GET /api/workflow-admin/audit-scripts/templates/{language}`：下载 Python 或 JavaScript 骨架模板。
- `POST /api/workflow-admin/audit-scripts`：接收 `name`、`description` 和文件，创建版本 `1`。
- `PUT /api/workflow-admin/audit-scripts/{script_id}`：接收 `description` 和文件，创建新版本并更新当前版本指针。

本期界面不增加删除或归档操作，保留已有后端归档能力供后续管理需求使用。

## 7. 后续执行解析入口

新增内部服务接口，根据 `script_id + version + sha256` 解析固定版本：

1. 查询指定版本记录；
2. 校验节点哈希与数据库哈希一致；
3. 确认入口文件位于配置的 `backend/scripts` 根目录内；
4. 确认入口文件存在且实际 SHA-256 一致；
5. 返回语言、入口文件和版本元信息。

该接口只解析可信版本，不启动 Python 或 Node.js 进程，也不向脚本注入项目 `.env`。后续执行器必须在独立任务中设计超时、资源限制、输入输出 JSON 校验和密钥白名单。

## 8. 校验与错误处理

- 功能名称必填、唯一，最长 120 字符；
- 功能描述必填，最长 500 字符；
- 脚本必须是 UTF-8 编码的 `.py` 或 `.js` 文件；
- 单文件最大 1 MiB；
- 更新版本必须保持原语言；
- 上传中禁用重复提交；
- 名称冲突、格式错误、权限不足和上传失败在弹窗内显示明确提示；
- 更新成功后刷新列表并显示新的当前版本。

## 9. 验收标准

1. 超级管理员在教务流程页看到“审核脚本”入口，普通教师看不到。
2. 超级管理员可以下载 Python 和 JavaScript 模板。
3. 超级管理员可以填写名称、描述并上传新脚本。
4. 超级管理员可以为已有脚本上传同语言的新版本并修改描述。
5. 普通教师调用管理接口得到权限错误，但可读取脚本元信息。
6. 文件上传节点能选择管理员预设脚本，并保存脚本 ID、固定版本和哈希。
7. 已配置节点不随当前版本更新；新选择使用最新版。
8. 后端能依据 ID、版本和哈希解析到对应入口文件，但不执行脚本。

## 10. 非目标

- 执行 Python 或 JavaScript 审核逻辑；
- 向脚本共享项目 `.env`；
- 在线编辑脚本源代码；
- 普通教师上传或读取脚本源代码；
- 本期新增删除、回滚或历史版本选择界面。
