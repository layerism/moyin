# 审核脚本统一编辑器设计

## 目标

将审核脚本列表中的“编辑信息”和“配置”合并为一个入口，使管理员在同一页面完成脚本基本信息和可调参数的查看与修改，同时保留后端现有的数据职责边界。

## 现状与问题

- 脚本名称和功能说明属于脚本清单元信息，保存在 `manifest.json`。
- 节点参数默认值和运行配置属于具体脚本版本，保存在 `versions/1/config.json`。
- 当前前端把两类数据拆成两个按钮和两个页面，管理员需要先理解内部数据结构才能选择入口。
- 内部脚本不允许修改清单元信息，但可以修改版本运行配置。

## 交互设计

### 列表入口

- 每个脚本只显示一个操作按钮。
- 存在可编辑内容时显示“编辑”。
- 内部脚本且没有任何可调配置时显示“查看”。
- 点击按钮后统一读取版本配置详情并进入同一个编辑页面。

### 统一编辑页面

页面按以下顺序展示：

1. 脚本语言、版本和脚本 ID。
2. “基本信息”区域：名称和功能说明。
3. “节点参数默认值”区域：由 JSON 参数定义自动生成。
4. “运行配置”区域：由 JSON 运行配置定义自动生成。
5. 配置变更影响提示和统一操作栏。

公开脚本的名称、功能说明可以编辑；内部脚本的名称、功能说明只读展示。没有节点参数或运行配置时，不显示对应空区域。

### 保存行为

- 页面底部统一显示“保存修改”。
- 前端分别判断基本信息和版本配置是否发生变化，只请求发生变化的后端接口。
- 版本配置先保存，成功后再保存基本信息；这样配置并发冲突会在任何元信息写入之前被发现。
- 若第一项保存成功、后一项保存失败，页面保留已成功结果并明确提示尚未保存的区域，不宣称整体保存成功。
- 全部保存成功后刷新页面草稿、配置哈希、更新时间和列表摘要，并显示“修改已保存”。
- 没有修改时禁用“保存修改”。

## 数据与接口边界

- 继续使用 `GET /api/workflow-admin/audit-scripts/{id}/versions/1/config` 读取统一页面所需数据。
- 继续使用 `PUT /api/workflow-admin/audit-scripts/{id}/versions/1/config` 保存节点参数默认值和运行配置。
- 继续使用 `PATCH /api/workflow-admin/audit-scripts/{id}/metadata` 保存公开脚本的名称和功能说明。
- 不把名称和说明迁入版本配置，不改变 `manifest.json` 与 `config.json` 的职责。
- 不改变内部脚本元信息不可编辑的权限规则。
- 不改变配置哈希、发布快照和已发布流程的语义。

## 前端结构

- `AuditScriptMetadataDialog` 只保留“列表”和“统一编辑器”两种页面状态。
- 删除原有独立元信息编辑状态和独立保存表单。
- 复用 `AuditScriptConfigForm` 的 JSON 驱动字段渲染。
- 统一管理名称、说明、参数默认值、运行配置、字段错误、保存状态和局部保存结果。
- 沿用现有白色面板、灰色边框、蓝色主按钮、红色错误提示及既有间距。

## 错误处理

- 名称或功能说明为空时，在前端阻止提交并标记对应字段。
- 配置字段不合法时，沿用现有字段级红色错误提示。
- 配置哈希冲突时提示“配置已被其他管理员修改，请重新加载”。
- 分段保存发生局部失败时，明确指出已保存和未保存的区域，避免用户重复修改已成功内容。
- 读取失败时留在列表页并提供重新读取入口。

## 验收标准

- 列表中不再同时出现“编辑信息”和“配置”两个按钮。
- 公开脚本通过一个“编辑”入口同时看到基本信息和配置字段。
- 内部可配置脚本通过“编辑”入口看到只读基本信息和可编辑配置。
- 无可调配置的内部脚本显示“查看”。
- 保存按钮只在内容变化且字段有效时可用。
- 配置冲突、字段错误和局部保存失败均有明确提示。
- 现有 JSON 自动生成配置表单、配置哈希和流程快照行为保持不变。

## 验证边界

按照项目约定，实施过程中不运行自动化测试、不使用浏览器插件；完成后进行静态业务逻辑审计、差异检查、缓存清理和本地服务重启，并明确说明未执行的运行时验证。
