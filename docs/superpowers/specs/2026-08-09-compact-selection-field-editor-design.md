# 选择字段紧凑编辑器设计

## 1. 目标

优化信息填写节点中“单项选择”和“多项选择”字段的编辑界面，降低多字段、多选项场景的纵向占用和操作噪声，同时完整保留现有字段编辑、排序、删除、校验和数据行为。

本次采用已确认的“字段卡片默认折叠”方案，并使用手风琴规则管理展开状态。

## 2. 范围

### 2.1 本次修改

- 单项选择字段的编辑卡片；
- 多项选择字段的编辑卡片；
- 选择字段的折叠摘要、展开内容和字段操作菜单；
- 选择选项的紧凑行和选项操作菜单；
- 选择字段的错误摘要与只读查看状态。

### 2.2 不修改

- 单行文本字段的现有布局；
- 多行文本字段的现有布局；
- 表单字段数据结构；
- 字段和选项标识生成规则；
- 后端校验、数据库、流程版本和学生端渲染；
- 信息填写节点以外的编辑器。

## 3. 核心交互

### 3.1 折叠与展开

- 进入节点设置时，所有单项选择和多项选择字段默认收起；
- 同一时间最多展开一个选择字段；
- 点击另一个选择字段的摘要主体时，当前展开字段自动收起，新字段展开；
- 点击已展开字段的摘要主体时，该字段收起；
- 新增单项选择或多项选择字段后，仅自动展开新字段；
- 新增单行文本或多行文本字段时，不改变选择字段的展开状态；
- 删除当前展开字段后，没有其他字段自动展开；
- 字段上移或下移后，展开状态按字段 ID 保持，不按数组位置转移。

展开状态只属于当前 `FormFieldEditor` 的临时界面状态，不写入流程配置、草稿或后端。

### 3.2 折叠摘要

选择字段的摘要行显示：

1. 字段标题；
2. 字段类型：单项选择或多项选择；
3. 必填或选填状态；
4. 普通选项数量；
5. 展开或收起图标；
6. 字段操作“⋯”按钮。

字段标题为空时，摘要显示 `未命名字段`，但不替换实际字段值。

点击摘要主体切换展开状态。点击“⋯”按钮只打开字段操作菜单，不得触发展开或收起。

### 3.3 字段操作菜单

原有字段操作完整保留并收进“⋯”菜单：

- 上移；
- 下移；
- 删除字段。

边界字段对应的上移或下移项保持禁用。删除操作执行现有即时删除逻辑，不增加确认弹窗。

菜单规则：

- 同一时间只打开一个字段或选项菜单；
- 点击菜单外部关闭；
- 按 Esc 关闭；
- 执行操作后关闭；
- 菜单关闭后不改变字段展开状态；
- 菜单按钮和菜单项提供明确的 `aria-label` 或可见文本。

### 3.4 展开内容

展开区域继续提供现有全部设置：

- 字段标题；
- 字段类型；
- 必填；
- 选项编辑；
- 添加选项；
- 允许填写“其他”内容；
- 多项选择的最少选择数和最多选择数；
- 具体校验错误。

字段类型从单项选择或多项选择切换为单行文本或多行文本后，该字段立即恢复现有文本字段布局，并从选择字段展开状态中移除。

字段类型从文本类型切换为单项选择或多项选择时，该字段进入选择字段布局并保持展开。现有 `normalizeFieldSettings()` 继续负责补充默认选项和清除不适用于新类型的设置。

## 4. 选项列表

### 4.1 紧凑选项行

每个普通选项使用单行结构：

- 左侧显示从 1 开始的视觉序号；
- 中间是选项标题输入框；
- 右侧是“⋯”操作按钮。

视觉序号不写入数据，不替代选项 ID。选项标题继续即时调用现有 `updateOption()` 更新。

### 4.2 选项操作菜单

原有选项操作完整保留并收进“⋯”菜单：

- 上移；
- 下移；
- 删除选项。

第一项的上移和最后一项的下移保持禁用。删除后继续使用现有字段归一化与校验逻辑；不会绕过“至少两个普通选项”等既有规则。

“+ 添加选项”保留为列表底部的整行按钮，新增后不改变当前字段的展开状态。

## 5. 视觉规范

### 5.1 摘要行

- 高度约 48px；
- 白色背景；
- 使用现有灰蓝边框与蓝色交互强调色；
- 字段标题是主信息；
- 类型、必填状态和选项数量使用低权重辅助文字；
- 不使用大面积彩色标签、渐变、阴影或新增装饰图形。

### 5.2 展开区域

- 沿用现有输入框、选择框、复选框和错误色；
- 缩减卡片内边距、区块间距和选项行间距；
- 选项行高度约 34px；
- “⋯”按钮使用小型图标按钮样式；
- 菜单使用白底、细边框和轻量阴影，危险操作使用现有红色语义；
- 保留清晰的 hover、focus-visible 和 disabled 状态。

### 5.3 文本字段一致性

单行文本和多行文本字段不改为折叠卡片，但选择字段的字体、边框、圆角和控件高度继续使用当前节点设置面板的设计语言，避免形成第二套界面风格。

## 6. 状态模型

`FormFieldEditor` 增加最小本地状态：

```ts
const [expandedSelectionFieldId, setExpandedSelectionFieldId] = useState<string | null>(null);
const [openActionMenu, setOpenActionMenu] = useState<
  | { kind: "field"; fieldId: string }
  | { kind: "option"; fieldId: string; optionId: string }
  | null
>(null);
```

不新增全局状态、Context、持久化字段或第三方菜单组件。

当外部 `fields` 更新导致展开字段或打开菜单目标不存在时，组件应清除对应本地状态。该同步只清理失效 ID，不复制表单数据到本地状态。

## 7. 禁止编辑状态

当 `disabled` 为 `true` 时：

- 选择字段仍可展开和收起，便于查看完整配置；
- 字段与选项操作菜单按钮禁用；
- 输入框、选择框、复选框、添加按钮继续禁用；
- 不允许触发排序、删除或数据更新；
- 摘要信息和校验状态继续可见。

## 8. 校验与错误

继续使用现有 `validateFormFieldConfig()` 结果，不新增第二套校验。

选择字段存在错误时：

- 折叠摘要使用红色边框或错误强调；
- 摘要显示 `需修正`；
- 展开后继续逐条显示现有具体错误文案；
- 错误状态不强制自动展开，避免多个错误字段破坏手风琴规则；
- 用户点击错误摘要即可查看并修改。

空标题、重复选项、空选项、选项不足、无效选择数量等错误规则全部保持不变。

## 9. 数据与业务边界

本次只改变编辑器的界面组织，不改变 `onChange()` 的数据流：

```text
用户操作
  → 现有 updateField / updateOption / moveField / moveOption
  → normalizeFieldSettings
  → onChange(nextFields)
  → 节点配置草稿
```

不得改变：

- `FormField` 和 `FormFieldConfig` 类型；
- 字段及选项 ID；
- 字段数组和选项数组的顺序语义；
- 单选、多选、“其他”选项和数量限制规则；
- 发布与学生填写时的配置格式。

## 11. 验收标准

1. 单项选择和多项选择字段初始均为折叠摘要；
2. 同时最多展开一个选择字段；
3. 新增选择字段后只展开新字段；
4. 单行文本和多行文本字段布局保持不变；
5. 摘要正确显示标题、类型、必填状态和选项数量；
6. 字段上移、下移和删除可通过字段菜单完成；
7. 选项上移、下移和删除可通过选项菜单完成；
8. 字段和选项的边界排序项正确禁用；
9. 点击菜单不触发字段折叠，点击外部或按 Esc 可关闭菜单；
10. 展开后所有原有选择字段设置均可编辑；
11. 禁止编辑状态下可展开查看，但不能修改数据；
12. 错误字段在折叠状态可识别，展开后显示具体错误；
13. 类型切换、排序、删除和新增后的数据结构与现有逻辑一致；
14. 不新增依赖、数据库字段或后端接口。

## 12. 验证边界

按项目约定，不运行自动化测试、构建或业务页面浏览器测试。实施完成后执行静态业务审计：

- 折叠和菜单状态是否只保存 ID，不复制字段数据；
- 菜单事件是否阻止冒泡到摘要切换；
- 排序、删除、添加和类型切换是否继续调用现有函数；
- 失效字段或选项 ID 是否被安全清理；
- disabled 状态是否阻止全部数据修改；
- 错误摘要是否与现有校验结果一致；
- 数据类型、后端和学生端文件是否无改动。

完成静态审计后清理项目源码缓存、重启本地 FastAPI 与 Vite 服务，并交由用户手动验收。
