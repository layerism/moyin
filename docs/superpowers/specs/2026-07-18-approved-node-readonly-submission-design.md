# 已通过学生节点只读查看设计

## 目标

学生端的已通过节点仍可从流程拓扑打开，以只读方式查看该节点当前通过尝试的提交内容；学生不得修改字段、暂存、上传文件或再次提交。

## 范围与非目标

- 仅展示节点当前 `attempt_no` 对应的提交快照，不提供提交历史列表。
- 表单节点展示字段值；确认和公告节点展示确认状态。
- 文件节点仅展示文件名、文件大小和提交时间；不提供下载或预览。
- 不改变审核逻辑、节点状态机、流程推进规则或已有表结构。

## 数据流

1. `get_instance` 在读取节点实例时，继续关联当前尝试的 `submissions`，并读取其 `payload_snapshot`。
2. 后端将解析后的快照以 `submission` 字段附在对应 `nodeInstances` 项中；无当前提交时返回空对象。
3. 学生拓扑将 `approved` 加入可打开状态。
4. 节点弹窗在 `approved` 状态使用 `submission` 填充内容，并渲染只读展示；其他状态保持现有可编辑、审核中或退回行为。

## 只读交互规则

- 表单字段使用不可编辑文本或只读输入展示，避免触发草稿状态更新。
- 确认节点展示“已确认”或“未确认”，不提供可切换复选框。
- 文件节点展示快照中的 `name`、`size`、`type`（如有）和节点的 `submittedAt`；不展示文件选择控件。
- 已通过弹窗不显示“暂存”“提交节点”“重新审核”按钮。
- 后端现有 `save_node_draft`、上传和 `submit_node` 状态校验继续拒绝 `approved`，作为前端只读限制之外的服务端保护。

## 兼容性与异常处理

- 旧流程的已通过节点若提交快照为空或格式损坏，仍可打开，但对应内容显示为空值；不回退到可编辑模式。
- 文件快照缺少名称或大小时，使用“未记录”占位，不发起额外文件存储查询。
- 响应字段为附加字段，教师端和现有学生端数据消费方不受影响。

## 验收标准

1. 已通过节点在学生拓扑中可点击打开。
2. 弹窗显示当前提交快照，且没有任何修改、上传、暂存或提交入口。
3. 文件节点显示文件名、大小和提交时间，不显示下载或预览入口。
4. 直接调用暂存、上传或提交接口处理已通过节点时，仍返回当前节点不可操作的冲突结果。
