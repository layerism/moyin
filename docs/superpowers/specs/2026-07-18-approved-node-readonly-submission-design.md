# 学生节点只读查看与现代化交互设计

## 目标

学生端的已通过节点仍可从流程拓扑打开，以只读方式查看该节点当前通过尝试的提交内容；学生不得修改字段、暂存、上传文件或再次提交。同时统一升级学生端拓扑、进度概览和节点弹窗的视觉层级及状态反馈。

## 范围与非目标

- 仅展示节点当前 `attempt_no` 对应的提交快照，不提供提交历史列表。
- 表单节点展示字段值；确认和公告节点展示确认状态。
- 文件节点仅展示文件名、文件大小和提交时间；不提供下载或预览。
- 不改变审核逻辑、节点状态机、流程推进规则或已有表结构。
- 不改为线性步骤条，不新增独立的“我的提交”入口；DAG 拓扑仍是学生端唯一的流程入口。

## 数据流

1. `get_instance` 在读取节点实例时，继续关联当前尝试的 `submissions`，并读取其 `payload_snapshot`。
2. 后端将解析后的快照以 `submission` 字段附在对应 `nodeInstances` 项中；无当前提交时返回空对象。
3. 学生拓扑将 `approved` 加入可打开状态。
4. 节点弹窗在 `approved` 状态使用 `submission` 填充内容，并渲染只读展示；其他状态保持现有可编辑、审核中或退回行为。

## 学生端现代化交互

### 进度概览

- 在学生流程页顶部保留流程名称和学生身份，并以进度卡片展示“已完成 / 总节点数”“当前可填写节点数”“自动审核中节点数”。
- 进度统计只反映节点当前状态；被退回或审核异常的节点不计入完成数。
- 进度卡片使用图标、文字和语义色共同表达状态，避免仅凭颜色理解流程进度。

### 拓扑节点卡片

- 所有节点使用统一的圆角卡片、状态图标、节点类型标签和状态标签，保留现有 DAG 布局、拖拽画布与缩放行为。
- 可操作、审核中、已通过、退回、待开放和已截止分别使用稳定语义色；可点击节点提供悬浮、焦点和按下反馈。
- 已通过节点显示“已完成 · 可查看”，并保持可点击；审核中节点仍可打开查看审核状态，但不可编辑；待开放和已截止节点不可点击。
- 连线延续“目标节点通过则高亮”的规则，不以动画或颜色替代文字状态。

### 节点弹窗

- 弹窗统一为“状态头部、内容卡片、操作区”三级结构，状态头部展示图标、节点名称、要求和状态说明。
- 可填写节点继续使用现有输入、暂存、上传和提交动作；布局与只读内容卡片保持一致。
- 已通过节点使用完成横幅，展示提交时间和不可修改的提交摘要；不显示任何写入按钮。
- 文件摘要以独立信息卡片展示文件名、文件大小和提交时间；不提供下载、预览或重新选择文件。
- 审核中、退回、审核异常和已截止节点分别展示对应的解释或审核结果，避免将不可写状态误解为界面故障。

### 响应式与可访问性

- 桌面端保留拓扑画布；窄屏时节点卡片和进度卡片采用单列可读布局，弹窗宽度适配视口。
- 关键交互保留键盘焦点样式和清晰的可访问名称；所有状态均提供文本标签。

## 只读交互规则

- 表单字段使用不可编辑文本或只读输入展示，避免触发草稿状态更新。
- 确认节点展示“已确认”或“未确认”，不提供可切换复选框。
- 文件节点展示快照中的 `name`、`size`、`type`（如有）和节点的 `submittedAt`；不展示文件选择控件。
- 已通过弹窗不显示“暂存”“提交节点”“重新审核”按钮。
- 后端现有 `save_node_draft`、上传和 `submit_node` 状态校验继续拒绝 `approved`，作为前端只读限制之外的服务端保护。

## 兼容性与异常处理

- 旧流程的已通过节点若提交快照为空或格式损坏，仍可打开，但对应内容显示为空值；不回退到可编辑模式。
- 文件快照缺少名称或大小时，使用“未记录”占位，不发起额外文件存储查询。
- 响应字段为附加字段，教师端和现有学生端数据消费方不受影响。

## 验收标准

1. 已通过节点在学生拓扑中可点击打开。
2. 弹窗显示当前提交快照，且没有任何修改、上传、暂存或提交入口。
3. 文件节点显示文件名、大小和提交时间，不显示下载或预览入口。
4. 直接调用暂存、上传或提交接口处理已通过节点时，仍返回当前节点不可操作的冲突结果。
5. 学生端显示进度概览，拓扑中各状态卡片具有一致的图标、文本、语义色和交互反馈。
6. 已通过节点显示“已完成 · 可查看”；审核中节点可查看状态；待开放和已截止节点不可点击。
