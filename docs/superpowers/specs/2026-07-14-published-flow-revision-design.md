# 已发布流程修订与 DAG 进度迁移设计

## 1. 目标

教师可以在流程首次发布后继续修订流程：修改已发布节点的填报内容、添加新节点并调整 DAG 连线。重新发布后，原高熵分享链接继续有效，学生端切换到最新版本；仅受变更影响的节点及其全部 DAG 后继节点需要重新填写。

本设计继续保留不可变发布快照，不直接修改历史 `flow_versions`。

## 2. 编辑规则

### 2.1 节点生命周期

- 曾进入任一发布版本的节点为“已发布节点”，永久禁止删除。
- 当前修订中新增且尚未发布的节点为“新节点”，允许修改、移动和删除。
- 新节点重新发布后转为已发布节点，之后永久禁止删除。
- 已发布节点允许修改标题、说明、字段、文件要求、审核配置等填报内容。
- 截止时间仍作为运行参数单独修改，不触发流程版本迁移或进度失效。

### 2.2 连线规则

- 修订期间允许新增或删除连线，以支持将新节点插入既有 DAG。
- 发布前继续执行无环校验、节点存在性校验和端点校验。
- 任何节点的直接前驱集合发生变化时，该节点视为受影响节点。

### 2.3 布局规则

- 节点坐标 `x`、`y` 属于展示布局，允许调整。
- 仅修改布局不会使学生进度失效。

## 3. 版本模型

### 3.1 修订草稿

`flows.draft_config` 始终保存教师当前编辑内容。首次发布或重新发布时，将其生成新的不可变 `flow_versions.config_snapshot`。

教师打开已发布流程时，前端同时获得：

- 当前修订草稿；
- 当前发布版本编号和版本 ID；
- 当前发布版本包含的节点 ID 集合；
- 草稿是否存在未发布变更。

前端据此区分已发布节点与本轮新节点，并控制删除按钮。

### 3.2 重新发布

重新发布生成 `vN+1`，不覆盖 `vN`。事务内完成：

1. 校验草稿和当前发布版本；
2. 计算版本差异和失效节点集合；
3. 创建新版本及运行参数；
4. 迁移全部现有学生实例；
5. 将原有效分享令牌改为指向新版本；
6. 将旧版本状态改为 `disabled`；
7. 写入发布和失效审计记录。

任一步骤失败，整个事务回滚。

## 4. DAG 差异与失效传播

### 4.1 业务内容指纹

旧节点业务指纹包含：

- `kind`、`title`、`requirement`；
- `infoFields`；
- `fileTypes`、`maxFileSizeMb`；
- `auditScriptType`、`auditScriptFile`；
- `autoApprove`。

指纹不包含 `x`、`y`、`deadlineAt` 和设计器预览状态。仅这些排除字段变化时，不触发学生进度失效。

### 4.2 初始受影响集合

以下节点进入初始受影响集合：

- 业务内容指纹发生变化的旧节点；
- 当前版本新增的节点；
- 直接前驱集合发生变化的节点。

已发布节点缺失时直接拒绝发布，以落实禁止删除规则。

### 4.3 传播规则

从初始受影响集合出发，沿新版本 DAG 的出边计算全部可达后继节点。初始集合和全部后继节点共同构成最终失效集合。

因此：

- 修改旧节点，只重置该节点及其全部后继节点；
- 新增节点，只影响新节点及其全部后继节点；
- 不可达的并行分支、祖先节点和无关节点保留原状态；
- 将新节点插入旧边时，原下游节点因前驱集合变化而失效。

## 5. 学生实例迁移

现有 `flow_instances.id` 保持不变，并将 `flow_version_id` 更新为新版本，确保学生已有运行页面地址继续可用。

### 5.1 不受影响节点

- 保留 `node_instances` 状态、提交次数和时间；
- 保留有效 `submissions` 与 `node_drafts`；
- 保留个别学生截止时间覆盖。

### 5.2 受影响节点

迁移前将原节点状态、草稿和提交快照写入 `audit_logs.before_data`，随后：

- 删除当前运行态中的原 `submissions` 和 `node_drafts`；
- 将节点实例重置为未提交状态，清空提交、审核时间和尝试次数；
- 根据新 DAG 中所有直接前驱的迁移后状态，重新计算为 `available`、`locked` 或 `expired`；
- 写入 `node_submission_invalidated` 审计事件，记录旧版本、新版本、学生实例、节点 ID 和失效原因。

### 5.3 新节点

- 为每个既有学生实例创建新的 `node_instances`；
- 若所有直接前驱已通过，则节点为 `available`；否则为 `locked`；
- 无前驱节点直接开放，并继续应用有效截止时间。

迁移完成后重新计算 `flow_instances.status` 和 `completed_at`。存在任一未通过节点时，流程状态恢复为 `in_progress`。

## 6. 分享链接

- 首次发布创建高熵分享令牌。
- 重新发布不改变 `token_value` 和 `token_hash`，仅在同一事务中将有效令牌的 `flow_version_id` 更新为新版本。
- 学生再次打开原 `/s/{token}` 时，读取最新版本并获得迁移后的同一流程实例。
- 旧版本不再接受新学生进入。

## 7. 审计

新增审计动作：

- `workflow_republish`：记录版本号、版本 ID、变更节点、失效节点和迁移学生数量；
- `node_submission_invalidated`：记录单个学生节点被重置前的状态、草稿和提交快照；
- `share_token_retargeted`：记录分享令牌从旧版本迁移到新版本。

失效的填写内容和审核结果不再保留在当前运行表中，仅保留在审计记录。审计记录不得包含密码、会话令牌或令牌明文。

## 8. 教师端交互

- 已发布流程显示“修订中”状态，保存按钮改为“保存修订”。
- 发布按钮改为“重新发布”。
- 节点配置、组件拖入、节点移动和连线恢复可用。
- 已发布节点不显示可执行的删除操作，并通过提示说明“已发布节点不可删除”。
- 新节点保留删除操作；发布后自动转为不可删除。
- 重新发布前展示影响确认弹窗：版本号、变更节点、失效节点和受影响学生人数。
- 教师确认后才执行迁移；成功后刷新当前版本和学生进度。

## 9. API

- `GET /api/workflows/{flowId}`：返回当前发布版本元数据、已发布节点 ID 和未发布变更状态。
- `PUT /api/workflows/{flowId}/draft`：发布后继续允许保存修订草稿，但拒绝缺失任何已发布节点的配置。
- `POST /api/workflows/{flowId}/revision-impact`：校验草稿并返回差异、失效节点和受影响学生数，不修改数据。
- `POST /api/workflows/{flowId}/publish`：首次发布沿用原行为；重新发布执行版本创建和实例迁移事务。

## 10. 测试

### 后端

- 已发布节点删除时保存和重新发布均失败；新节点发布前可以删除。
- 修改旧节点内容，只重置该节点及其 DAG 后继节点。
- 新增节点后，为既有学生补充节点实例，并重置受影响后继节点。
- 修改坐标或截止时间不使学生提交失效。
- 不受影响分支保留提交、草稿和审核状态。
- 失效数据从运行表移除，并完整写入审计记录。
- 原分享链接在重新发布后解析到新版本。
- 迁移中发生异常时，新版本、实例、令牌和审计均回滚。

### 前端

- 已发布流程可保存修订并重新发布。
- 已发布节点不可删除，新节点发布前可删除。
- 影响确认弹窗准确展示后端预检结果。
- 重新发布后学生拓扑显示新增节点，受影响节点恢复可填写或待开放状态。
