# 本地材料审核脚本库设计

## 目标

为文件上传节点提供教师或管理员自有的审核脚本管理能力：下载 Python 或 JavaScript 骨架模板、上传完成后的脚本、在节点中选择自己的脚本。脚本文件保存在后端本地目录，按统一目录和清单格式组织，为后续安全执行器提供稳定调用约定。

本期只管理脚本，不执行脚本，也不将脚本上传至对象存储。

## 角色与权限

- 当前登录教师或管理员可下载模板、上传脚本和选择自己的脚本。
- 脚本列表仅返回当前账号创建的脚本；其他账号不可读取、选择或覆盖。
- 既有内置脚本选项继续保留，以确保已保存流程的配置可被正常读取。

## 脚本协议

### Python

下载的 `.py` 模板提供 `run(payload: dict) -> dict` 骨架。入口从标准输入读取一个 JSON 对象，调用 `run`，并且只向标准输出写出一个 JSON 对象。

### JavaScript

下载的 `.js` 模板提供 `async function run(payload)` 骨架。入口从标准输入读取一个 JSON 对象，调用 `run`，并且只向标准输出写出一个 JSON 对象。

两个模板均把异常写入标准错误；后续执行器可据此以子进程方式调用，保持“JSON 输入、JSON 输出”的最小契约。

## 持久化模型

每个成功上传的脚本保存为：

```text
backend/scripts/<owner_id>/<script_id>/
  manifest.json
  handler.py | handler.js
```

`manifest.json` 记录脚本 ID、所有者 ID、显示名称、语言、入口文件名、源文件哈希、大小和创建时间。SQLite 中新增审核脚本索引表，保存相同的可查询元数据与目录路径；目录是源文件的唯一存放位置，数据库不存放脚本正文。

流程节点新增可选 `auditScriptId`。选择上传脚本时同时保存脚本 ID、显示名和语言；后续执行器通过脚本 ID 读取清单与入口文件。选择内置脚本时，维持现有名称和语言字段，`auditScriptId` 为空。

## 接口与界面

后端提供教师认证接口：

- `GET /api/workflow-admin/audit-scripts/templates/python`：下载 Python 模板。
- `GET /api/workflow-admin/audit-scripts/templates/javascript`：下载 JavaScript 模板。
- `GET /api/workflow-admin/audit-scripts`：列出当前账号的上传脚本。
- `POST /api/workflow-admin/audit-scripts`：以 multipart 上传 `.py` 或 `.js` 文件并创建目录、清单及索引。

文件节点的“标准审核脚本”区域包含：

- Python 模板下载按钮；
- JavaScript 模板下载按钮；
- 脚本上传按钮；
- 下拉选择框：不启用、既有内置脚本、当前账号上传的脚本。

上传成功后立即刷新列表并自动选中新脚本。失败时保留当前节点配置并显示可读错误。

## 约束与错误处理

- 仅接受 `.py` 与 `.js`，拒绝空文件、路径分隔符文件名和超出脚本大小上限的文件。
- 服务端自行生成 `script_id` 和目录名，不信任客户端路径或脚本 ID。
- 在完成文件写入、清单写入和数据库插入前，上传视为未成功；任一步失败时清理本次创建的临时目录。
- 本期不导入、不解释、不运行用户脚本，避免上传阶段产生任意代码执行风险。
- `backend/scripts/` 作为运行时数据目录，不纳入版本控制；模板源文件由后端代码生成或受版本控制的模板文件提供。

## 验证

- 后端测试覆盖模板下载、`.py`/`.js` 上传、目录及清单生成、账号隔离、非法扩展名和写入失败回滚。
- 前端测试覆盖上传请求体、上传结果到节点配置的映射以及内置/自有脚本选项的组合。
- 前端生产构建成功。
- 浏览器验证模板下载控件、上传后的列表刷新及节点选择状态。

## 范围外

- 脚本沙箱、资源配额、超时、依赖安装和实际审核执行。
- 脚本共享、管理员代管或跨账号授权。
- OSS 脚本存储与版本回收策略。
