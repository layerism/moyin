# 确认承诺审查仅支持图片设计

## 背景与目标

“确认承诺”节点当前允许学生上传 JPG、JPEG、PNG 和 PDF，并由视觉审核脚本将材料转换为图片后调用多模态模型。PDF 请求可能经过页面渲染并触发较长的模型调用与重试。现调整为：新上传和替换仅允许 JPG、JPEG、PNG，不再接受 PDF。

本次调整只作用于“扫描件提交与审核”能力，不改变普通文件上传节点对 PDF、DOCX 等文件的支持。

## 行为边界

- 学生新上传或替换扫描件时，文件选择器仅展示 `.jpg`、`.jpeg`、`.png`。
- 拖拽上传不能绕过限制；后端以扩展名和实际图片内容进行最终校验，PDF 返回明确的格式错误。
- 教师端配置说明和学生端上传提示统一改为仅支持 JPG、JPEG、PNG。
- 确认承诺视觉审核脚本的目录契约仅声明 `.jpg`、`.jpeg`、`.png`，脚本移除 PDF 解析逻辑和 PDF 相关提示。
- 历史 PDF 文件及其已有审核结果不删除，仍可按现有权限下载。
- 历史 PDF 若因审核错误被重新执行，脚本必须明确拒绝其格式；学生需删除该 PDF 并改传图片后重新提交。

## 实现范围

### 前端

修改扫描件上传区和替换入口的 `accept` 属性，并同步学生端、教师端文案。前端限制仅用于引导，不能作为安全边界。

### 后端上传校验

`inspect_scan_material()` 仅接受 JPG、JPEG、PNG。保留现有文件大小、像素数量、扩展名与真实图片格式一致性校验；移除 PDF 打开、页数读取及 PDF 专属异常处理。每张图片仍计为一页，整组数量和容量限制保持不变。

### 审核脚本

脚本配置中的 `acceptedExtensions` 移除 `.pdf`。页面规范化逻辑只读取图片；如遇历史 PDF 或其他非图片扩展名，返回明确的“不再支持 PDF，请改传 JPG、JPEG 或 PNG 图片”执行错误，不将其发送给模型。

## 数据兼容与错误处理

不迁移或删除 `uploaded_files`、提交记录、审核任务和 OSS 对象。新上传 PDF 在写入 OSS 前被拒绝。历史 PDF 下载路径不变；仅当它再次进入审核执行链路时失败，并沿用现有 `audit_error` 状态和重试入口。重复重试同一历史 PDF 不会成功，学生需要重新上传图片形成新提交。

## 验证边界

依据项目规范，修改过程中不运行测试、不使用浏览器。完成后进行源代码调用链审计和 `git diff --check`，确认前端提示、后端校验和脚本契约一致；随后清理限定缓存并以本地方式重启前后端服务，核对 5173 与 8000 端口。
