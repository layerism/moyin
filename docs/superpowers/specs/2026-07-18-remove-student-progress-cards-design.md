# 移除学生流程进度卡片设计

## 目标

移除学生流程详情页顶部的三张进度统计卡片：“已完成”、“当前可填写”和“自动审核中”，减少与办理拓扑重复的状态展示。

## 现状与范围

三张卡片仅由 `StudentRuntimePage` 内部的 `progress` 统计对象渲染，统计值没有其他业务消费者。节点状态、审核轮询、提交逻辑、只读查看和下方拓扑均直接依赖 `instance.nodeInstances`，不依赖该展示区块。

保留：

- 页头的流程总状态“全部完成/填写中”；
- 办理拓扑中的节点状态、状态图例与通过数量；
- 节点弹窗中的审核及提交反馈。

移除：

- `runtime-progress-grid` 区块及其三张 `runtime-progress-card`；
- 仅为该区块计算的 `progress` 对象；
- 不再被使用的进度卡片专用 CSS 与窄屏覆盖规则。

## 方案选择

推荐直接删除渲染区块、无用计算和专用样式。相比仅用 CSS 隐藏，直接删除不会保留无意义的可访问性节点、运行时计算或死样式；相比把统计转移到页头，会重新引入用户已要求移除的汇总功能。

## 验收标准

- 学生流程详情页的页头下方直接进入办理拓扑；
- 页面不再出现三张进度统计卡片及其“已完成/当前可填写/自动审核中”汇总文案；
- 流程总状态、办理拓扑、节点操作和审核轮询保持原有行为；
- 不保留无引用的 `progress` 计算或 `runtime-progress-*` 专用样式。

## 验证边界

本次按项目约定仅执行静态源码、CSS 和 Git 范围审计，不运行自动化测试、构建或浏览器测试；由用户在学生流程页面手动确认。
