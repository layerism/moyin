# 已发布节点布局修订设计

## 1. 目标

教师解锁已发布流程后，可以拖动旧节点和本轮新增节点。重新发布时，新坐标写入新的流程版本并同步到学生端，但学生已有的填写、提交和审核状态不因纯布局变化而重置。

旧连线仍属于受保护结构，不提供选中、悬停删除、删除按钮或键盘删除交互。

## 2. 交互规则

| 对象 | 已发布锁定 | 本地修订中 |
| --- | --- | --- |
| 旧节点 | 不可拖动 | 可拖动，不可删除 |
| 新节点 | 不存在 | 可拖动、可删除 |
| 旧连线 | 不可修改 | 可作为新连线端点，但不可删除 |
| 新连线 | 不存在 | 可创建、可删除 |
| 画布 | 右键拖动平移 | 右键拖动平移 |

节点拖动只更新前端工作副本并设置本地脏标记。教师未重新发布便离开页面时，坐标修改与其他本地修订一并丢弃。

## 3. 前端设计

### 3.1 节点移动权限

节点移动权限与节点删除权限分离：

- `editorLocked = true` 时，所有节点不可移动；
- 进入本地修订状态后，旧节点与新节点均可移动；
- 旧节点仍通过已发布节点 ID 集合禁止删除；
- 新节点继续允许删除。

坐标更新不再因流程已发布而过滤旧节点的 `x`、`y`。截止时间及其他运行参数继续沿用现有独立规则。

### 3.2 连线保护

当前发布版本中的连线 ID 继续作为受保护集合：

- 旧连线不渲染交互命中层；
- 旧连线不出现删除按钮；
- 旧连线不能通过 `Delete` 或 `Backspace` 删除；
- 提交工作副本前继续恢复任何被异常移除或修改的旧连线。

新连线仍允许连接旧节点或新节点，并可在重新发布前删除。

## 4. 后端设计

### 4.1 发布校验

重新发布时取消“已发布节点坐标必须保持不变”的校验。继续保留：

- 历史已发布节点 ID 必须存在；
- 历史已发布连线必须存在；
- 流程配置必须通过节点引用和 DAG 无环校验。

因此，重新发布可以改变旧节点的 `x`、`y`，但不能删除旧节点或旧连线。

### 4.2 版本与学生同步

重新发布继续创建新的不可变 `flow_versions.config_snapshot`。新快照包含调整后的节点坐标，学生端读取新版本后显示新布局。

布局字段 `x`、`y` 不进入节点业务内容指纹，也不构成前驱集合变化。因此只有坐标变化时：

- 既有 `flow_instances` 切换到新版本；
- 原 `node_instances` 状态保持不变；
- 原 `submissions`、`node_drafts`、审核状态和尝试次数保持不变；
- 不生成节点失效或重填要求。

若同一次重新发布还包含节点内容、节点新增或前驱集合变化，则继续按既有迁移规则处理真正受影响的节点。

## 5. 数据流

1. 教师打开已发布流程，页面使用当前发布快照建立基线。
2. 教师点击“解锁编辑”，生成前端工作副本。
3. 教师拖动旧节点，工作副本更新坐标并标记未发布修改。
4. 影响预览接收完整工作副本，但将纯坐标变化判断为零状态影响。
5. 教师确认重新发布，后端创建包含新坐标的版本快照并迁移实例版本引用。
6. 学生继续使用原链接和原实例，页面显示新布局，原填写状态保持不变。

## 6. 异常处理

- 未解锁编辑时的拖动事件直接忽略。
- 旧节点或旧连线缺失时，影响预览和重新发布均拒绝请求。
- 发布版本发生并发变化时，拒绝覆盖并保留当前前端工作副本。
- 发布事务失败时，版本、学生实例和状态迁移全部回滚。

## 7. 测试与验收

### 前端

- 已发布锁定状态下旧节点不可拖动。
- 解锁修订后，旧节点和新节点均可拖动。
- 旧节点仍不可删除，新节点仍可删除。
- 旧连线不出现选择或删除交互，新连线可以删除。
- 拖动旧节点后形成未发布修改，并将新坐标提交到影响预览和重新发布。

### 后端

- 仅修改旧节点坐标时，影响预览返回零失效节点。
- 重新发布成功创建包含新坐标的版本快照。
- 既有学生节点状态、提交、草稿、审核结果和尝试次数保持不变。
- 删除旧节点或旧连线仍被拒绝。

## 8. 非目标

- 不允许删除旧节点或旧连线。
- 不直接修改历史版本快照。
- 不改变学生节点状态迁移算法中的业务内容和前驱变化规则。
- 不增加修订草稿的数据库保存或自动保存。
