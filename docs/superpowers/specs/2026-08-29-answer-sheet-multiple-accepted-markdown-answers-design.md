# 填空题多个可接受 Markdown 答案设计

> 状态：已完成交互与技术方案确认，待用户审核本文档后进入实施计划。

## 目标

将单 Markdown 填空题的标准答案从一个值扩展为多个相互独立的可接受答案。教师以紧凑列表维护答案；学生仍只提交一个 Markdown 答案；系统去除首尾空白后，只要命中任一可接受答案即获得整题分值。

本次同时降低标准答案编辑区的常态高度，避免短答案占用与题干相近的大块空间。

## 教师端 UI

单 Markdown 填空题的标准答案区域调整为“可接受答案”列表：

- 标题左侧显示“可接受答案”，辅助说明为“命中任意一个即正确”，右侧显示答案数量；
- 每个答案使用独立 Markdown 原位编辑行，依次显示序号、内容和删除按钮；
- 普通单行答案的渲染态与编辑态均以 38px 为最小高度，并使用相同字号、行高和内边距；
- 多行 Markdown 或独立公式可以按内容增高，但达到局部最大高度后在当前答案行内滚动，不扩大整个弹窗；
- 点击内容进入源码编辑，失焦后继续使用现有 `AnswerSheetMarkdown` 原位渲染；
- 列表下方提供“添加答案”按钮，新答案追加到末尾并自动进入编辑；
- 至少保留一个答案；仅剩一项时禁用删除；
- 空答案、去除首尾空白后重复的答案均显示现有红色校验语义，并禁止确认题目编辑；
- 不增加大小写开关、模糊匹配、答案权重、部分得分或格式工具栏。

该区域继续沿用现有白底、灰色边框、蓝色焦点、红色错误与紧凑圆角体系，不建立新的视觉语言。

## 学生端

学生侧保持一个 Markdown 答题区，不展示教师配置了多少种答案，也不改变提交载荷：

```json
{
  "answerMarkdown": "学生答案 Markdown"
}
```

教师真实学生预览与正式学生端继续复用 `RuntimeAnswerSheet`，不建立预览专用交互。只读提交内容仍按原始 Markdown 渲染。

## v3 数据契约

多个可接受答案会改变确定性判分语义，因此不静默扩展 `answer-sheet-v2`。新建或进入可编辑状态的答题卡使用：

```json
{
  "schemaVersion": "3.0",
  "graderVersion": "answer-sheet-v3"
}
```

公开题目结构保持单 Markdown 填空题语义：

```json
{
  "id": "question-id",
  "type": "fill_blank",
  "format": "single_markdown_exact",
  "content": "题干 Markdown",
  "points": 1,
  "required": true
}
```

私有标准答案改为：

```json
{
  "type": "fill_blank",
  "format": "single_markdown_exact",
  "acceptedAnswerMarkdowns": [
    "3/4",
    "\\frac{3}{4}",
    "0.75"
  ]
}
```

数组必须至少包含一个非空字符串。系统保留每个答案的原始 Markdown；`trim()` 仅用于发布校验、等价重复检测和判分比较，不改写存储值。

## 自动判分

v3 判分器执行：

```text
actual = studentAnswer.trim()
accepted = acceptedAnswerMarkdowns.map(answer => answer.trim())
correct = accepted.some(answer => actual === answer)
```

命中任意一个答案即获得整题分值，否则为 0 分。比较规则固定为：

- 仅去除每个字符串的首尾空白；
- 区分大小写；
- 不合并内部空格或换行；
- 不进行 Unicode 归一化；
- 不比较 Markdown 渲染后的 HTML；
- 不做数值、代数、语义或 LLM 等价判断。

去除首尾空白后相同的教师答案属于重复配置，发布前必须拒绝。

## 版本与历史兼容

- `schemaVersion = "1.0"`、`answer-sheet-v1` 的旧版多空题继续使用原有逐空判分；
- `schemaVersion = "2.0"`、`answer-sheet-v2` 的单 Markdown 题继续读取私有字段 `answerMarkdown` 并执行单答案精确匹配；
- `schemaVersion = "3.0"`、`answer-sheet-v3` 才读取 `acceptedAnswerMarkdowns` 并执行任一命中规则；
- 后端必须依据已发布快照的协议与判分器版本严格分发，不能用字段猜测覆盖快照版本；
- 已发布 v1/v2 配置、标准答案快照、学生提交和成绩记录均不迁移、不重写、不重新计算；
- 教师打开可编辑草稿时，v2 的 `answerMarkdown` 安全转换为只包含该值的 `acceptedAnswerMarkdowns`，判分集合不变；
- v1 旧版填空仍遵守既有安全升级条件，不能借本次变更静默改变大小写或 Unicode 语义。

数据库中的答题卡配置与私钥均为 JSON 快照，本次不增加数据库表或关系字段。

## 校验与错误边界

前后端均必须拒绝：

- v3 单 Markdown 题缺少 `acceptedAnswerMarkdowns`；
- 数组为空、包含非字符串或去除首尾空白后为空；
- 去除首尾空白后出现重复答案；
- v3 私有答案继续携带 v2 的 `answerMarkdown`，或同时携带两种字段；
- v1/v2/v3 的 `schemaVersion` 与 `graderVersion` 不匹配；
- 私有答案题号、题型或 `format` 与公开题目不一致；
- 学生提交未知题号、未知字段、非字符串答案或缺失必答答案。

判分结果不包含私有答案数组。标准答案只在现有反馈策略允许时下发。

## 反馈与导出

反馈策略允许展示标准答案时：

- 每个可接受答案按编号独立展示；
- 每一项继续通过共享 `AnswerSheetMarkdown` 渲染；
- 不使用斜杠、分号或换行直接拼接 Markdown，避免答案边界与内容混淆。

Excel 导出中：

- “学生答案”字段保持学生原始 Markdown；
- “标准答案”字段对 v3 使用 JSON 数组字符串，例如 `["3/4","\\frac{3}{4}","0.75"]`；
- v1/v2 历史导出保持原有语义；
- 得分、满分、是否正确和审核结论继续使用各自独立字段，不与标准答案混合。

## 影响范围

- 前端答题卡协议类型、默认版本、草稿升级与配置校验；
- 教师端多个紧凑 Markdown 答案编辑行；
- 反馈页标准答案的编号展示；
- 后端 v3 公私有协议校验与确定性判分；
- 教师节点 Excel 导出的 v3 标准答案格式；
- v1/v2/v3 版本分发与兼容。

不修改学生提交结构、DAG 推进、作答次数、及格线、成绩表结构、发布快照不可变规则、Markdown/KaTeX 解析链或 LLM 审核。

## 验收标准

1. 教师可以添加、编辑和删除多个独立 Markdown 标准答案，且至少保留一项；
2. 普通答案行的常态高度为 38px，点击编辑时不产生明显高度和字号跳变；
3. 学生答案去除首尾空白后命中任一教师答案即获得整题分值；
4. 内部空白、大小写或 Markdown 源码不同仍判为不同答案；
5. 空答案和去除首尾空白后的重复答案不能确认或发布；
6. v3 标准答案反馈按编号分别渲染，Excel 使用 JSON 数组保留边界；
7. 已发布 v1/v2 流程与历史成绩保持不变；
8. 教师预览与正式学生端继续共享同一运行时组件。

## 验证边界

实施阶段遵守项目约定：不运行测试、TypeScript 构建或浏览器自动检查；仅执行静态业务逻辑审计、差异检查、限定缓存清理、本地非 Docker 重启及端口/工作目录核对，并在交付时明确说明验证边界。
