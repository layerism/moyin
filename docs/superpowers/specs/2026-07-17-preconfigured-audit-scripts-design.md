# 后台预置审核脚本设计

## 1. 目标

取消面向超级管理员的审核脚本模板下载、上传、更新和归档功能。审核脚本改由开发人员随后台代码部署到 `backend/scripts/`，教师和管理员仅能在流程画布的“文件上传”节点中选择有效脚本。

## 2. 范围与约束

- 每个脚本使用独立目录和一份 `manifest.json`。
- 后端自动扫描、校验和列出预置脚本，不提供脚本写入 API。
- 前端删除教务流程页的“审核脚本”管理入口及相关弹窗。
- 文件上传节点继续保存脚本 ID、版本、名称和 SHA-256。
- 已发布流程固定原脚本版本与哈希；新配置或重新选择脚本时使用目录中声明的最新版。
- 保留现有 JSON 输入输出协议和后端执行入口，本次不改变审核脚本的执行时机或业务结果处理。

## 3. 目录协议

```text
backend/scripts/
└── document-structure-check/
    ├── manifest.json
    └── handler.py
```

`manifest.json` 示例：

```json
{
  "id": "document-structure-check",
  "name": "材料结构检查",
  "description": "检查上传材料的格式与必要内容",
  "language": "py",
  "version": 1,
  "entry": "handler.py"
}
```

字段规则：

- `id`：全局唯一、稳定，只允许小写字母、数字和连字符。
- `name`：流程设计器中展示的名称。
- `description`：脚本用途说明。
- `language`：仅允许 `py` 或 `js`。
- `version`：正整数；脚本逻辑变化时由开发人员递增。
- `entry`：当前目录内的 `.py` 或 `.js` 入口文件名，必须与 `language` 一致。

## 4. 后端设计

### 4.1 脚本发现

新增只读脚本目录服务。每次读取脚本列表时扫描 `backend/scripts/*/manifest.json`，避免维护数据库与文件目录的双重状态。扫描时：

1. 解析并校验清单字段；
2. 使用真实路径检查入口文件仍位于对应脚本目录和 `backend/scripts` 根目录内；
3. 校验入口扩展名与语言一致；
4. 计算入口文件 SHA-256；
5. 对非法目录记录错误日志并跳过，不阻断其他有效脚本；
6. 检测重复 ID，重复项均不对外提供，避免选择结果不确定。

列表按脚本名称稳定排序，返回现有流程节点需要的 `id`、`name`、`description`、`language`、`version`、`sha256` 和更新时间字段。

### 4.2 API

保留：

- `GET /api/workflow-admin/audit-scripts`：登录教师或管理员读取有效预置脚本元数据。

删除：

- 模板下载 API；
- 脚本上传 API；
- 脚本更新 API；
- 脚本归档 API。

### 4.3 运行时解析

运行时根据流程节点保存的脚本 ID、版本和 SHA-256 解析对应目录。解析时重新校验清单版本、真实路径和文件哈希。目录脚本被修改但版本未递增时，旧流程的哈希校验失败并返回明确的脚本解析错误，防止静默执行不同逻辑。

## 5. 前端设计

- 删除教务流程列表页仅超级管理员可见的“审核脚本”按钮。
- 删除脚本管理弹窗、模板保存选择器、上传和更新表单及其专用样式。
- API 客户端只保留 `listAuditScripts()`。
- 文件上传节点保留“材料审核脚本”下拉框及加载失败提示。
- 下拉框选择脚本时写入当前扫描结果的版本和哈希；旧流程当前值不在列表中时继续显示固定版本回显项。

## 6. 示例脚本与版本控制

提供至少一个受版本控制的示例预置脚本目录，用于证明扫描、选择和运行时解析链路。调整 `.gitignore`，允许 `backend/scripts` 下符合目录协议的开发脚本进入版本控制；运行时临时文件和缓存仍保持忽略。

## 7. 错误处理

- 单个清单或入口文件无效：写入服务日志并跳过该脚本。
- 无有效脚本：API 返回空列表，节点下拉框仅显示“不启用材料审核”。
- 列表读取失败：前端在节点设置中显示错误，不清除已保存的固定脚本配置。
- 运行时版本或哈希不匹配：拒绝执行并返回统一的审核脚本解析错误。

## 8. 验收标准

1. 超级管理员和普通教师均看不到模板下载、脚本上传或更新入口。
2. 后端不存在可写审核脚本的 HTTP API。
3. 合法的 `backend/scripts/<script>/manifest.json` 能出现在文件上传节点下拉框中。
4. 非法路径、重复 ID、语言不匹配或缺失入口文件不会出现在列表中。
5. 新节点选择脚本后保存当前版本和 SHA-256。
6. 已发布流程不会因同 ID 脚本升级而自动切换版本。
7. 运行时能够按固定 ID、版本和哈希解析受版本控制的脚本入口。
