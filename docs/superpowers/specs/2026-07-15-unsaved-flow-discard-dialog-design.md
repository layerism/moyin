# 未发布流程修改离开警告弹窗设计

## 目标

用项目内统一样式的警告弹窗替代浏览器 `window.confirm`，准确说明离开页面会丢弃本地修改，同时避免教师误以为已发布版本会被删除。

## 触发范围

仅当页面存在尚未发布的本地修改时，下列操作触发弹窗：

- 返回教务流程；
- 返回首页；
- 打开学生链接。

“提交发布”和“重新发布”不得触发该弹窗。浏览器刷新、关闭标签页和关闭浏览器继续使用浏览器原生离开提示，因为网页无法自定义这些系统级提示。

## 弹窗内容

- 标题：`放弃未发布的修改？`
- 正文：`当前修改仅保存在本页面。离开后将无法恢复，但已发布版本不会受到影响。`
- 目标说明：根据触发入口显示 `即将前往：教务流程列表`、`即将前往：首页` 或 `即将前往：学生填写页面`。
- 次要按钮：`继续编辑`
- 危险按钮：`放弃修改并离开`

## 交互规则

1. 默认焦点位于“继续编辑”，降低误操作概率。
2. 点击“继续编辑”、按 `Esc` 或关闭按钮均关闭弹窗并保留全部本地修改。
3. 点击遮罩不关闭弹窗。
4. 点击“放弃修改并离开”后，清除当前页面工作副本并执行原导航动作，不调用保存接口。
5. 弹窗打开期间锁定画布与其他页面操作，避免导航目标和工作副本继续变化。
6. 每次只保存一个待执行导航动作；关闭弹窗后必须清空该动作。

## 视觉规范

- 复用现有发布影响确认弹窗的遮罩、圆角、阴影、间距和响应式规则。
- 使用警告图标和红色危险按钮表达不可恢复操作，但正文保持中性，不使用“永久删除流程”等夸张表述。
- 弹窗使用 `role="dialog"`、`aria-modal="true"` 和可关联的标题，保证键盘与辅助技术可识别。

## 异常边界

- 无本地修改时直接导航，不显示弹窗。
- 发布成功并清除脏标记后直接导航，不显示弹窗。
- 发布失败时保留脏标记，后续离开仍显示弹窗。
- 若目标导航回调失效，关闭弹窗但不清除工作副本。

## 验收标准

1. 项目中不再使用 `window.confirm` 处理流程设计器内部导航。
2. 三个内部导航入口显示正确的目标说明。
3. 继续编辑不会丢失节点、连线或配置修改。
4. 确认放弃后执行正确导航，且不产生流程配置保存请求。
5. 发布操作不出现离开警告弹窗。
6. 刷新或关闭页面仍保留浏览器原生离开保护。
