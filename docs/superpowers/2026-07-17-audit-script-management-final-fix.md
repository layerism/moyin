# 审核脚本管理最终审查修复

## 目标

以最小改动修复审查中发现的上传内存边界、旧库元数据约束和脚本管理对话框失败态问题，并保留当前角色无关选择器结构。

## 逻辑与边界

1. API 上传路由读取至多 \(audit\_script\_max\_bytes + 1\) 字节；多出的一个字节只用于让既有仓储大小校验返回 422，不改变其错误文案。
2. 对尚未执行迁移的旧库，以 `NOT NULL DEFAULT ''` 添加 `updated_at`，随后回填 `created_at`；不重建已迁移 SQLite 表，以免在外键引用的父表上引入迁移中断和数据一致性风险。
3. 对话框将列表加载、列表错误和列表数据分开表示；加载失败不再渲染“正在读取”。纯状态判定函数接受 Node 内建测试覆盖。
4. 不新增 React 渲染依赖。`AuditScriptSelector` 不接收角色，也没有角色条件分支；现有纯函数测试已覆盖选择项形成与固定版本回显，报告记录该静态结构和测试边界。

## 验收

- 直接调用 POST/PUT 上传超过 1 MiB 时返回 422，且读取上限不会超过 1 MiB + 1 字节。
- 迁移后的新旧表 `updated_at` 在 `PRAGMA table_info` 中为 `NOT NULL`。
- 列表请求失败时，状态判定为错误而非加载，并可重试。
- 运行相关 pytest、前端 Node 测试与 `npm run build`。
