# 答题卡得分与完成状态紧凑合并

## 目标

重构学生答题卡提交后的结果摘要，将得分、是否及格、逐题得分、完成状态和提交时间收敛到同一张紧凑卡片，消除当前两块提示区域的重复语义与不一致边距。

## 当前问题

- 得分卡紧贴弹窗边缘，完成状态条向内缩进，视觉边界不一致。
- 少量逐题得分纵向占满整行，信息密度过低。
- “已达到及格要求”与“已完成”分别使用独立区域，形成重复且竞争的绿色视觉重点。

## 设计

```text
┌──────────────────────────────────────────────────────┐
│ 得分  1 / 2 分                    [已达到及格要求]   │
│ [第1题  1/1分]  [第2题  0/1分]                      │
│ ──────────────────────────────────────────────────── │
│ 已完成 · 提交内容已锁定       提交时间：20:37:10    │
└──────────────────────────────────────────────────────┘
```

- `AnswerSheetGradeResult` 接收可选的完成状态文字和提交时间，并在得分卡底部渲染紧凑元信息行。
- 总分保持主视觉；是否及格改为浅色状态标签。
- 逐题得分改为可自动换行的横向紧凑标签，正确项使用绿色语义，错误项使用红色语义。
- 答案卡已有评分数据且处于只读状态时，不再渲染独立 `.runtime-completion-banner`。
- 非答案卡节点以及答案卡缺少评分数据的兜底路径继续使用原完成状态条。
- 标准答案区域继续保留在同一得分卡内，不改变反馈策略。

## 共享入口与业务边界

- 教师真实学生预览与正式学生端均通过 `App -> StudentRuntimePage -> NodeRuntimeDialog -> AnswerSheetGradeResult`，本次只修改该共享路径。
- 不修改评分、及格判定、逐题得分、提交时间、只读状态、重试次数、标准答案、后端接口或数据结构。
- 不改变可填写、审核中、审核失败及表单/文件/确认节点的现有逻辑。
