# 超级管理员用户管理设计

状态：UI 方向与交互已确认，实施前设计稿。尚未实现。

## 页面与权限

采用 A「统一管理台」，沿用个人中心现有配色、面板和间距。在邀请管理与数据库管理之间新增用户管理入口。前端入口和所有后端接口均限定超级管理员。普通教师、学生不能通过直接请求访问。

页面分为「用户列表」「注册白名单」两个标签。用户列表中提供全部、教师、学生筛选，按姓名和学号／工号搜索，服务端分页。字段为姓名、账号、角色、注册时间、操作；账号标识由账号类型和 ID 共同组成，避免两个账号表的数字 ID 冲突。系统预览学生不进入普通用户列表。

普通账号行提供「初始化密码」「彻底删除」。超级管理员显示受保护标识，本期不通过此入口删除或重置超级管理员，保留现有账户安全入口。

## 注册白名单

学生注册必须匹配白名单中的学号与姓名。教师继续走现有邀请注册流程。白名单不等于流程授权名单，允许注册并不自动获得任何流程访问权。

界面提供单条添加、批量粘贴、CSV 导入和移除。导入两列：学号、姓名；学号按字符串处理以保留前导零。仅去除字段两端空白，不做姓名模糊匹配。同一学号仅允许一个姓名；同配对重复可跳过，姓名冲突与空字段按行提示。先预览结果，再提交，存在错误时不得静默部分导入。

表格展示学号、姓名、已注册／未注册状态和移除操作。名单为空时不允许学生新注册；对存量账号的登录不追溯限制。移出白名单只限制后续注册，不清空已注册账号，不撤销既有流程权限。

注册检查覆盖当前两个学生注册路由，并与账号创建处于同一事务中，避免名单移除与注册并发导致绕过限制。部署启用后需先维护名单，再开放新生注册。

## 密码初始化

点击后展示目标姓名、账号和影响：所有现有登录设备退出，下次登录必须修改密码。确认后服务端生成随机临时密码，只保存密码哈希；成功弹窗仅在该次响应中展示临时密码并支持复制，不记入日志、浏览器存储或 URL。

密码更新、强制改密标记与会话撤销在同一事务完成。学生已有 must_change_password 字段；教师需补齐同等能力。受限会话只允许修改密码与退出，所有业务 API 必须检查该状态。首次改密不能依赖已绑定手机号，否则未绑定用户会被锁在初始化流程中。

## 彻底删除

确认弹窗展示服务端计算的目标账号、关联记录分类数量、文件数量及影响的其他用户数量。管理员输入完整目标账号，并确认不可撤销说明后才能提交。第一版只支持单用户删除，不增加批量危险操作。

学生删除清理账号、会话、安全绑定与恢复数据、流程实例、草稿、提交、成绩、审核任务、反馈、下载记录及其专属上传文件；清理关联流程名单中的该学生记录，保留教师流程定义与其他学生记录。注册白名单默认保留，可勾选「同时移出注册白名单」。重新注册后不恢复旧成绩或旧会话；流程权限仍需教师重新授权。

教师删除清理其账号及安全数据、个人模型配置、材料、邀请关联、预览身份、拥有的流程和模板，以及这些流程下所有学生运行记录和专属文件。其他学生账号与其他教师独立资源保留。确认页必须明确列出流程数量和受影响学生数量。

实现前逐表审计所有外键、文本 owner_id 和 JSON 内资源引用，不能仅依赖 ON DELETE CASCADE。复制或共享资源只有在没有存活引用时才能删除；如果无法证明安全清理，应返回具体阻断原因。执行前重算影响范围，范围变化时要求重新查看确认。

数据库与 OSS 无法共享事务。使用持久化删除任务：先冻结目标账号并撤销会话，阻止新提交和审核回写；保存清理目标，清理数据库关联与专属 OSS 对象。界面展示「删除中」「删除失败，可重试」「已彻底删除」。仅在两侧都完成后显示成功，失败保留任务以重试，不让数据库删除成功掩盖文件残留。

历史日志中包含目标身份和被删除实体内容的关联记录也在清理范围；删除任务完成后清除其敏感目标载荷。历史备份、用户已下载的文件无法由此在线操作追溯抹除，确认说明应准确限定为在线系统数据。
